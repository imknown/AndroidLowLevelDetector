# 03 — 非功能需求、发布与开放问题

属于《[LowLevelDetector 规格文档](README.md)》(中文整理版)。

## 1. 非功能需求

| ID | 类别 | 需求 |
|---|---|---|
| NFR-1 | 兼容性 | 目标 **minSdk 23(Android 6.0)** —— 和当前 AndroidX 的下限一致;以后跟着 AndroidX 走。在老旧或厂商魔改的系统上,特性检测必须平稳退回(比如显示未知),不能崩溃。 |
| NFR-2 | 隐私 | 两个变体的检测都在手机本地完成;**检测结果绝不上传**。参考数据同步(FR-7)用不用网络由用户控制(FR-8,只管同步这件事)。缓存的参考数据只放在应用私有目录。**遥测看变体(FR-10)**:`firebase` 变体经 Firebase 收集崩溃报告和使用数据(默认开启,目前没有运行时关闭开关);`foss` 变体不收集任何数据。 |
| NFR-3 | 性能 | 检测异步运行;结果屏幕及时显示,检测工作绝不阻塞主线程。 |
| NFR-4 | 可靠性 | 状态按懒加载 / 缓存的规则,在界面重建和进程被杀之后还在(FR-13);刷新不死锁、不叠加(FR-5);失败被隔离在单条内(FR-6)。 |
| NFR-5 | 可维护性 | 代码库必须**人和 AI 助手都容易找到路**:状态只有一个数据来源(SSOT)、数据流单向(UDF)、**按特性放在一起** —— 一个特性的逻辑集中在一处,绝不散落到相距很远的模块。 |
| NFR-6 | 合法与安全 | 只用合法、只读的手段(FR-9);不做规避检测的花招(NG6)。 |
| NFR-7 | 可读性 | 三态模型必须让非专家(Explorer 画像)也能看懂:未知绝不能看起来像成功或失败。 |
| NFR-8 | 自适应 | 界面用**自适应布局**:手机、平板、折叠屏、窗口缩放 / 多窗口都能用。 |

## 3. 成功标准(产品层面)

1. Tinkerer 不用查任何外部资料,就能对目录里的每个条目回答「我的设备支持 X 吗?」。
2. 当前版本零「卡在加载」或「转屏后结果没了」的报告。
3. 成功同步一次后,开飞行模式应用照样完全可用。
4. 新贡献者(人或 AI)只看仓库目录树,几分钟内就能在一个地方找到某个检测特性的全部逻辑。
