# Build Conventions Reference

> **Status**: **living**, part of [AGENTS.md](../../AGENTS.md)'s Build conventions section.  
> Read this before changing a Gradle file, a version catalog, a toolchain version, or CI.  
> The prohibitions that bind every build edit stay in AGENTS.md.

## Flavors and variants

- The flavor dimension is `IssueTracker`, not the usual `mode` / `store`.
- `Foss` is the default: no tracking, and the version name carries the `-Foss` suffix.
- `Firebase` is the Play variant and requires `google-services.json`, which is gitignored.
- `AndroidApplicationFirebaseConventionPlugin` attaches Firebase dependencies as `firebaseImplementation` and  
  disables the GoogleServices / Crashlytics tasks for Foss, so a Foss build never needs that file.

## Application identity

- Debug builds work out of the box; debug adds `applicationIdSuffix = ".debug"`, so it installs side by side  
  with release.
- Release signing is configured outside the repository, in gitignored `local.properties` (see the root README).

## JDK on two independent tracks

- The code track reads the `javaToolchain` version from the build catalog (`gradle/toml/build.toml`, through  
  `Project.buildVersion()` in `build-logic/convention/src/main/kotlin/.../ext/ProjectExtensions.kt`) and applies  
  it in the `jvmToolchain` block of `KotlinAndroid.kt`, which pins the Adoptium vendor.
- The Gradle Daemon track reads `gradle/gradle-daemon-jvm.properties` (`toolchainVersion` and  
  `toolchainVendor`), generated by `updateDaemonJvm`.
- Don't conflate the two, and never restate either version in a doc or a comment: the file above is the source  
  of truth for each track.
- Inspect what the toolchain resolver sees with `./gradlew -q javaToolchains`.

## Native and pinned tool versions

- `:binderDetector` native code needs the NDK and CMake versions pinned in `gradle/toml/build.toml`.
- Those are the exact versions CI installs, so bump them and CI in lockstep.

## Version catalog layout

- The catalogs are split into five files under `gradle/toml/`: `build`, `android`, `kotlin`, `google`,  
  `thirdParty`, reached through the `libsAndroid`, `libsBuild`, `libsKotlin`, `libsGoogle`, `libsThirdParty`  
  accessors.
- Decide which category a dependency belongs to before referencing it.

## Repository filtering

- Repositories are content-filtered (`google()` narrowed by `includeGroupByRegex`) with  
  `FAIL_ON_PROJECT_REPOS`.
- `jitpack.io` exists only in the main build's dependency repositories.

## Kotlin flags

- The Kotlin version lives only in `gradle/toml/kotlin.toml`; the compiler runs with a set of experimental  
  flags declared in `build-logic`, grouped by the Kotlin version that introduced them.
- Re-review the groups on every Kotlin upgrade and drop the ones that have stabilized.

## Build cache and scans

- Configuration cache (with parallel and integrity checks) and parallel builds are enabled.
- Build scans use the Develocity plugin but never publish (`publishing.onlyIf { false }`), i.e. local scans only.
