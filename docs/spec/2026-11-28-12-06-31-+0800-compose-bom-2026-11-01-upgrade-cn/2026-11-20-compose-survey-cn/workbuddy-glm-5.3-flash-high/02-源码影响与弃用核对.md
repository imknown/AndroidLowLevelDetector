## 唯一的可清理点

`AppRoot.kt` 第 142 行的 `@OptIn(ExperimentalMaterial3Api::class)`, 行尾注释写着  
`// TopAppBar is still an experimental API in m3 1.4.0`.  
Material3 1.5.0 把 `TopAppBar` 全系变体和 `TopAppBarScrollBehavior` 转为稳定 API,  
所以升级后这个 OptIn 和注释都过时了. 不删也能编译, 属于顺手清理.  
(当场核过: 文件与行号; 转述未核: compose-material3 release notes 1.5.0 段的  
"previously experimental APIs now stable" 列表)

## 弃用清单零命中

这版的弃用项与本项目用法逐条对照:

| 弃用项 | 替代 | 本项目 |
|---|---|---|
| value 版 `BasicTextField` 与 `TextField(value, onValueChange)` | `TextFieldState` 重载 | 未用 |
| `VisualTransformation` | `OutputTransformation` | 未用 |
| Material2 库与 Material2 `TextField` | Material3 | 未引入该依赖 |
| `FlowRow` / `FlowColumn` | FlexBox (官方建议新代码用它) | 未用 |
| Compose 版 `ConstraintLayout` / `MotionLayout` | Compose 原生替代 | 未引入该依赖 |
| `EnterTransition.with` (已移除) | `togetherWith` | 已在用正确写法 (AppRoot.kt 第 131 行) |
| `MutableVector` / `mutableVectorOf` | `MutableObjectList` / `mutableObjectListOf` | 未用 |
| `LazyLayoutCacheWindow` / `LazyListPrefetchStrategy` 经 `LazyListState` 传入 | 直接传给 composable 函数 | 未用 |
| `derivedMediaQuery` | `computedMediaQuery` | 未用 |
| `LocalMotionScheme` | `MaterialTheme.motionScheme` | 未用 |

(弃用项栏转述未核: compose-ui release notes 的 alpha03 段, compose-animation release notes 的  
1.13.0 段, 官方博客的迁移方向表, anddev 汇总的迁移边界表; 本项目栏当场核过: grep 零命中)

## 不波及的行为变化与 flag

- `Modifier.border` 换了更快的新实现. 项目没有任何 `Modifier.border` 使用点,  
  该变化在 1.13 还是在 1.14 的第一个 alpha 生效都不波及.  
  (当场核过: grep 零命中; 上游条目转述未核: anddev 汇总与 compose-foundation release notes)
- 全仓库 grep `LinkComposer`, `ComposeUiFlags`, `ComposeFoundationFlags`, `ComposeMaterial3Flags`,  
  `MaterialTheme.LocalMaterialTheme`, `LazyLayoutCacheWindow`, `MediaQuery` 零命中.  
  所以实验版 SlotTable (LinkComposer 需手动 opt-in, 它的 proguard 语法在本版变了),  
  `isMinimalistLocalsEnabled` 默认开启, MaterialTheme 的主题 CompositionLocal 整合, 全部不波及.  
  (当场核过: grep 输出为空; 上游条目转述未核: compose-runtime 与 compose-ui release notes)
- 项目没有 `derivedStateOf` 使用点, 所以 runtime 1.13 新推荐的 `computedStateOf`  
  没有存量迁移要做. (当场核过: grep 零命中)
