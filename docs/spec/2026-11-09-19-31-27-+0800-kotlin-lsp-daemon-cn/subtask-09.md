## 验证

- 全部量测与核对项目的结论逐条记进本子任务的实现记录, 带命令与输出.
- 热查询在同一份文件上连续跑十次取最慢一次; 冷启动从前台启动命令发起到 `status` 就绪计时.
- 并发用两个客户端同时发同一批请求, 看响应顺序与 FIFO 队列记录; 响应交错或丢失算打断.
- 按 `plan.md:83` 先校验 daemon 的代码指纹, 确认不是旧代码的服务进程.
- 三个 CLI 在一批真实改动上跑通之后, 按 11 与 14 发 review.
- 按 02 的验证顺序跑自审与分析通道.

## 风险

- 中. 本机 Windows 的实测数字可能与另一台 macOS 机器的基线差很多.  
  数字只记事实, 不拿另一个平台的数字当本机结论.
- 常驻会话长期持有索引缓存, 量测要覆盖会话起落前后的状态.
- 沙箱会在命令结束时清后台进程. daemon 只由负责人在不随命令结束的终端里前台启动,  
  量测要在那个会话里做.
