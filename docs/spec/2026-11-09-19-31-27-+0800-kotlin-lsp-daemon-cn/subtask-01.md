> **状态**: living. 事实核对时间 2026-11-11, 代码在 `5656b51f`.  
> 任务级计划见 [plan.md](plan.md); 流程见 [13-任务工作流](../../agents-cn/13-任务工作流.md).

## 目标

给 daemon 加一份版本检查逻辑. 检查发行版自带 `build.txt` 的 build 号与 GitHub 上的最新 tag,  
提醒新版本; 发行版过期时给出明确提示. 检查逻辑单独成模块, 可以先单独验, 接进启动流程归子任务 2.

## concept primer

- 三个客户端现在各自解析 server 二进制. 顺序是 `KOTLIN_LSP_SERVER`, `KOTLIN_LSP_HOME`,  
  再到 `PATH`, 见 `scripts/kotlin-lsp-plan.js:52-57` 与 `:112-117`.
- 发行版根目录带一份 `build.txt`. 里面的 `ILS-263.7084.0` 是发行版自报的 build 号,  
  依据在 `plan.md:65-66`; `10-分析细则:221` 与 `scripts/kotlin-lsp-edit.js:14` 也提到这个 build 号.
- 发行版会到期. 原始记录里 server 以 `This build of kotlin-server has expired` 加退出码 7 退出,  
  这条由 daemon 启动失败判定, 不走版本检查的网络请求.
- 检查只提示, 不下载, 不安装. 下载与升级要负责人单独同意, 见 `plan.md:36`.
- 本机是 Windows, 另一台 macOS 机器的实测数字只当参考, 见 `plan.md:28`.

## 计划改动

1. **新增检查模块**  
   - 在 `scripts/kotlin-lsp-shared.js` 里单独导出一个检查模块. 本子任务先建该文件,  
     子任务 2 再往里补 server 解析等共用逻辑. 不引入 `plan.md:32` 范围之外的文件名.
   - 从已解析的发行版根目录读 `build.txt`, 拿本地 build 号.
   - 模块收一个发行版根目录参数. 独立验证时传一份临时目录, 里面放一份 `build.txt`;  
     server 二进制的解析留给子任务 2, 本模块不依赖它.
   - 请求 GitHub releases API 拿最新 tag, 结果按天缓存, 缓存写在索引缓存目录下.
   - tag 来源做成可注入的参数. 验"有新版本"时传一个比本地新的假 tag, 不发真实网络请求.
   - 有新版本打一行提示, 附对应平台的下载链接与校验文件位置. 已装版本比最新版旧两代以上时,  
     额外提示可能要换索引缓存.
   - 离线或请求失败时静默, 不拦住任何查询. 超时预算单独定, 不复用 `KOTLIN_LSP_CALL_TIMEOUT_MS`.
2. **过期分支可注入**  
   - 模块收一个可注入的假 build 号或退出码. daemon 启动失败时判定 `This build of kotlin-server has expired`  
     加退出码 7, 打印明确原因. 不要求真装一份过期发行版.
   - 过期提示单列, 不混进新版本提示.
3. **异步接入点留给子任务 2**  
   - 本模块只导出检查函数, 不自己起定时器, 不碰 socket. daemon 就绪后再异步调用,  
     不占冷启动关键路径, 不拦住 initialize 与第一批查询.

## 有意不改

- 三个 CLI 的命令行, 查询串, 输出行, 退出码.
- server 二进制的解析顺序. `shared.js` 收拢它归子任务 2.
- 不下载, 不安装, 不自动升级, 不改索引缓存的内容.
- `ILS-263.7084.0` 这类版本字面保持原样, 注明归子任务 8.

## 验证

- 断网, 有新版本, 已是最新, 三种情况各跑一次, 只核模块行为 (提示, 缓存, 不阻塞调用方).  
  查询结果不受影响随子任务 2 接入后复核.
- 注入过期信号单列核对启动失败与提示, 过期提示不混进新版本提示.
- 检查异步跑, 冷启动仍在 25 秒内. 这一条要等子任务 2 接进启动流程才跑得起来,  
  在本子任务里只验模块本身不阻塞调用方.
- 断网用可注入的请求失败造, 有新版本用可注入的假 tag 造, 已是最新用与本地 build 号一致的假 tag 造.
- 注入过期信号时核启动失败与退出码 7 的提示, 这一项没有查询可跑.

## 风险

- 低. 一个新增模块, 不碰现有三个 CLI.
- 网络请求超时会拖住调用方. 模块内部设独立且较短的超时, 失败静默.
- 缓存文件写不进索引目录时按离线处理, 不抛错.
