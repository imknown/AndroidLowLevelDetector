## 目标

把规划查询通道从每命令新起 server 改成连常驻 daemon. 命令, 查询串, 输出行, 退出码全部保持不变,  
一次会话批量查完.

## concept primer

- 用法是 `node scripts/kotlin-lsp-plan.js <query> [<query> ...]`, 见 `kotlin-lsp-plan.js:7` 与 `:80`.
- 查询串是冒号后缀, 从右往左切, 这样 Windows 盘符不会被切开. 位置查询形如  
  `<file>:<line>:<col>:<method>`, 另有 `:symbols`, `:diagnostics`, `:inlay-hints`, `wsymbol:`,
  见 `kotlin-lsp-plan.js:10-30` 与 `:132-166`.
- 输出一行一条发现, 带 `path:line:col`, 不是 JSON. 严重级别按 LSP 分四档打印, 协议外的值打  
  `UNKNOWN(n)`, 见 `kotlin-lsp-plan.js:33-45`.
- 退出码: 运行失败或任一带 ERROR 的诊断查询返回 1, 否则 0, 被中断返回 130 或 143,  
  见 `kotlin-lsp-plan.js:46-50`.
- 02 把 `references`, `calls-in`, `completion` 写成不许猜的核对义务.
- 11 的那份修订在回退时丢了, 由子任务 8 补回. 输出形状一变,  
  这些环节跟着错. 这是 `plan.md` 把命令行与输出形状不变排成第一判据的原因.

## 计划改动
这一节列的是接入步骤与保持项, 不是流程或判定逻辑, 不画图.

1. **接入前存基线**  
   - 挑一批覆盖常用方法的查询, 在旧版上跑一遍, 把完整输出存成基线文件放进这个 spec 目录.
   - 基线文件记下所用查询串, 便于接入后逐行对比.
2. **换掉启动与锁那段**  
   - 删掉自己的 `acquireLock`, `spawn`, `initialize`, 改成连 `shared.js` 给的本机端点.
   - 一批查询在一个请求批次里发给 daemon, 由 daemon 复用同一个 server 会话.
3. **保持输出形状**  
   - 查询串解析, 输出行, 退出码的逻辑原样保留. server 版本行允许与基线不同,
   - 除 server 版本行外, 改完的输出与基线逐行一致.
4. **连不上就报错**  
   - 连不上 daemon 时非 0 退出, 打印原因和可复制的启动命令, 不上报 `CLEAN`.
   - 不回落, 不自己起 server, 不自动拉起 daemon.
