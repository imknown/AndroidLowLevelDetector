## 任务清单

- [ ] **task 1 版本检查模块** (低风险).  
  凭什么是独立 task: 检查逻辑是独立模块, 可以先单独写好单独验; 接进启动流程归 task 2.  
  目标: 检查发行版 `build.txt` 的 build 号与 GitHub 最新 tag, 按天缓存, 提醒新版本; 过期由启动失败判定.  
  动哪些文件: `scripts/kotlin-lsp-shared.js` (新建, 先只放检查模块, server 解析归 task 2).  
  怎么验证: 断网 (注入请求失败), 有新版本 (注入较新假 tag), 已是最新 (注入同号假 tag) 三种各跑一次, 只核模块行为  
  (提示, 缓存, 不阻塞调用方); 注入过期信号单列核对启动失败提示与退出码 7, 过期提示不混进新版本提示;  
  "查询结果不受影响" 与 "冷启动仍在 25 秒内" 随 task 2 接进启动后复核.  
  对应 design: 版本检查; 落实 R-7.
- [ ] **task 2 共用库与 daemon 骨架** (高风险, 生疏).  
  凭什么是独立 task: 三个 CLI 的接入都以它为准, 它本身先用 `status` 与一个小探针验完, 不掺 CLI 改动.  
  目标: `shared.js` 收共用逻辑, `daemon.js` 持有唯一的 `intellij-server` 会话, 后续接入都连它.  
  动哪些文件: `scripts/kotlin-lsp-shared.js`: server 解析, 帧处理, 文档集与指纹, 客户端连接与端点路径,  
  ready 超时变量收拢, 协议版本与代码指纹; `scripts/kotlin-lsp-daemon.js`: initialize, FIFO 队列,  
  `status`, `stop`, 空闲 20 分钟退出, server 崩溃处理, 锁归 daemon 与原子拿锁, applyEdit 按客户端路由,  
  继承 `JAVA_HOME` 并打进日志, socket 0600, 日志按启动截断; 不碰三个 CLI.  
  怎么验证: 冷启动能起, `status` 能看到, `stop` 后端点与锁干净无残留 JVM; 空闲超时自退; 陈旧端点与锁自动接管  
  (手动留旧文件再起); workspace 单根; Windows 具名管道四步真跑; 用 `status` 探针验连不上时报错退出 (非 0),  
  打印启动命令, 不上报 `CLEAN`; 指纹不匹配报错提示重启; 客户端不自动拉起; 版本检查接进启动 (就绪后异步);  
  每项跑之前先校验代码指纹.  
  对应 design: 架构要点加生命周期; 落实 R-3, R-4, R-5, R-8, R-7 的接入点.
