## 计划改动

1. **建矩阵文件**  
   - 在 `plan.md:195` 指定的这个 spec 目录下, 文件名在实现时定并记进本子任务的实现记录.
   - 每样一条记录, 五列: 能力, 命令, 期望, 实际, 结论. 每行写明能不能接成可写操作与所需条件.
2. **覆盖全部脚本化能力**  
   - references, definition 系, typedef, implementation, call hierarchy 双向, type hierarchy,  
     workspace 与 document symbols, hover, completion, signature help, inlay hints, diagnostics,
     format, organize imports, 以及 rename 与 quickfix 的现状复查.
   - `10-分析细则:277` 那行维持不做, 不进矩阵. "一项都不跳过" 管的是脚本化能力.
3. **五项重探真发请求**  
   - format 发 `textDocument/formatting`.
   - organize imports 发 `codeAction` 接 `executeCommand` 再收 `workspace/applyEdit`.
   - rename 发 `prepareRename` 与 `rename`, `will-rename` 单独发一次或在矩阵里写明不探及理由.
   - quickfix 发 `codeAction` 接 `executeCommand` 收 `WorkspaceEdit`.
   - type hierarchy 发 `prepareTypeHierarchy`, 有结果再发 supertypes 与 subtypes;  
     回空就把后续两种请求未发和原因记进矩阵, 不留空行.
4. **结论回写 10**  
   - 停用与未接的条目按结果改判, 写回 `10-分析细则` 的能力盘点.
   - 判定某个未接能力可接时, 只写清所需条件, 接入实现归后续任务.
5. **判据**  
   - 能力盘点的每个脚本化行各有一条记录, 五项重探各有真实请求与应答.
   - 结论回写 10 之后, 盘点里没有过期或互相矛盾的行.
