# AR-05 组合根分散: 每个 ViewModel 自己 new 一套对象图

> 返回 [README 索引](../README.md) · [组2 · 主线重构 — 架构优先](../README.md#组2--主线重构--架构优先).


**严重程度: P1 | 修复难度: 低**
**影响文件: `HomeViewModel.kt`, `OthersViewModel.kt`, `PropViewModel.kt`, `SettingsViewModel.kt`**

## 问题核心代码

接线写在四个 ViewModel 各自的伴生 `Factory` 里 (`HomeViewModel.Factory`):

```kotlin
companion object {
    val Factory: ViewModelProvider.Factory = viewModelFactory {
        initializer {
            HomeViewModel(                                  // ← 界面层在组装数据层
                HomeRepository(LldDataSource(), MountDataSource(), AppInfoDataSource())
            )
        }
    }
}
```

`OthersViewModel.Factory` 一口气 new 7 个对象 (6 个 DataSource + 1 个 Repository), `PropViewModel.Factory`, `SettingsViewModel.Factory` 各自再来一套.

## 直接原因

对象图的组装代码 ("谁依赖谁" 的知识) 没有固定归属, 被复制到了每个界面入口. 改 `HomeRepository` 的构造签名, 表面上要动 1 个类, 实际上要动组装它的 `HomeViewModel.Factory`(View 时代是 `HomeFragment` 的 extras 接线) — 而 `HomeRepository` 的调用方还有 `HomeViewModel`, 测试和未来第二个使用方 (比如小部件, 快捷方式入口) 都得再抄一遍.

## 根本原因

缺少组合根 (composition root, 全项目唯一一处负责创建和装配对象的地方). DI 的价值不在框架, 而在 "接线知识只写一次": 现在接线知识写了四遍, 且写在最不稳定的 UI 层.

## 修复方案

在 [AR-04](06-AR-04-服务定位器上帝对象.md) 的 `AppContainer` 之上, 四个 Factory 退化成 "取现成的":

```kotlin
// MyApplication 暴露唯一容器
val appContainer: AppContainer by lazy { AppContainer(this) }

// HomeViewModel.Factory — 组装知识消失, 只剩一行声明
companion object {
    val Factory: ViewModelProvider.Factory = viewModelFactory {
        initializer { HomeViewModel(MyApplication.appContainer.homeRepository) }
    }
}
```

View 时代的 `MY_REPOSITORY_KEY` + `extrasProducer` 样板已随 Navigation 3 迁移删除 (入口改为 `viewModel(factory = ...)`, `AppRoot() 的 entryProvider 四条 entry`), 所以当年 "四个 Fragment 各写一份接线" 剩下的问题只有一个更小的版本: **同一份接线在四个 ViewModel 伴生对象里各写一遍**. 注意: 这一步必须在 AR-04 完成容器之后再做, 否则只是把 `new` 换了个地方.
