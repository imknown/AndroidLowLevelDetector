# R5 无三态模型, 无检测器注册表 — 目录硬编码 (FR-1 AC2 / FR-3 / ADR-008)

> 返回 [README 索引](../README.md) · [组2 · 主线重构 — 架构优先](../README.md#组2--主线重构--架构优先).


**严重程度: P1(🔴,Compose 迁移前必须关闭的主要结构缺口) | 修复: 注册表引擎**

- 唯一的行模型是 `MyModel(title, detail, color: StatusColor, type)` — "级别" 就是展示用状态色; **不存在 支持/不支持/未知 类型**("支持/不支持" 只是本地化的详情字符串, `HomeRepository.toSupportOrNotString()`). FR-3 的模型与 ADR-005 的 "Unknown 是一等结果" 在代码中没有表示.
- 目录是字面的 `tempModels += repository.detectXxx()` 序列 (`HomeViewModel.collectModels()`;`OthersViewModel.collectModels()`;`PropViewModel.collectModels()`) — 增删条目 = 改函数体, 正是 FR-1 AC2 / ADR-008 禁止的.
- 目录计数与渲染行数不符: Home = 23 个检测器调用但 **25 行**(`detectSecurityPatches` 产 2 行, `detectTrebleAndGsiCompatibility` 产 2 行, 复验);Others = 31 固定 + 6 个 API 条件项 + N 个分区指纹动态行; Prop = 5 个检测器各产动态行. 目录 (见 [docs/spec-cn/05](../../../spec-cn/05-检测条目目录.md)) 预填的值是 23/37/5.
- 连锁后果: 没有三态类型 → 没有统一的圆点映射 (C6)→ 每行各自随便配色; 没有注册表 → 目录附录没法按设计一一对应. Others/Prop 纯展示 (2026-09-06), 三态 + 注册表工作只需覆盖 Home 条目.

**裁定 2026-09-06(Q5/Q6/Q7)**: 三态语义, 注册表引擎, 有界并发维持书面目标 (四值颜色属性被接受为过渡表示) — 作为代码 TODO 开放, 不是文档抄写的问题.
