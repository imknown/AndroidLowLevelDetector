# 32 启动路径与性能杂项

> 返回 [README 索引](../README.md) · [6 · 性能](../README.md#6--性能).

**严重程度: P3 | 修复难度: 低 (各项独立)**

一组各自都不大, 但都落在启动路径或每次加载路径上的开销, 逐条记在这里, 攒批处理.

- **`MyApplication.onCreate()` 主线程同步读 SharedPreferences**: `initTheme()` 与 `initScrollBar()` 在 `onCreate()` 里各做一次 `sharedPreferences.getString(...)`, 并把结果写进 `themeMode` / `scrollBarMode` 这两个 StateFlow 的种子. 修法: 把这两处读挪到启动后的后台任务里, 首帧用枚举默认值 (FollowSystem / None); 或在 [#08](../2-SSOT-唯一数据来源/08-设置无唯一数据来源.md) 把设置改成可观察的唯一来源时一并处理 — 那条本来就要换掉这种直读.
- **`initMyAndroid()` 主线程反射**: 它经 `getApiAndDesserts()` 反射遍历 `Build.VERSION_CODES` / `Build.VERSION_CODES_FULL` 的字段 (`kClass.java.fields` + `getInt(null)`), 只为算出 "最后一个版本码" 和 `apiFull` / `version` 的推导. [#09](../2-SSOT-唯一数据来源/09-myAndroid可变单例.md) 的方案把它改成 `AndroidInfo.current by lazy { build()}`, 顺带就把这份启动期开销推到了第一次真正需要的时候.
- **`MyDebugApplication` 的 StrictMode 开晚了**: `app/src/debug/.../MyDebugApplication.onCreate()` 先 `super.onCreate()` 再 `StrictMode.enableDefaults()`, 于是 `initMyAndroid()` / `initTheme()` / `initScrollBar()` / `initShellAndProperty()` 这段启动路径的违规全部漏检. `StrictMode.enableDefaults()` 不依赖 `MyApplication.instance`, 移到 `super.onCreate()` 之前即可.
- **`PropertyDefault` 每次调用重新反射**: `getStringOrThrow()` / `getBooleanOrThrow()` 每次调用都 `getDeclaredMethod(...)`, 而 `PropertyManager(PropertyDefault)` 正是 `MyApplication.initShellAndProperty()` 接线的当前实现, `getStringProperty()` 每读一个属性走一次. 修法: 把 `Method` 缓存成对象成员, 反射一次复用.
- **`SettingsDataSource` 每 key 一次反射**: `getStringOrNullOrThrow()` 在每个 key 的循环里重新 `getDeclaredMethod("getString", ...)`, 叠加在 [#30](30-Prop页逐key查询.md) 的逐 key 查询上. 同上一条一样, `Method` 提取一次即可.
- **`LldDataSource` 每次刷新新建整套 OkHttp 引擎**: 见 [#16](../4-并发与调度/16-阻塞调用与HttpClient.md) — 客户端改成类级复用, 顺带补上 HTTP 状态码闸门.
