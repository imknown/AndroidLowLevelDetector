# 07 "常量仓库"名不副实, 常量跨功能引用, 两个同名 DataSource 异义

> 返回 [README 索引](../README.md) · [1 · 架构与分层](../README.md#1--架构与分层).


**严重程度: P2 | 修复难度: 低 (重命名 + 搬移, 随 #04 顺手)**  
**影响文件: `AndroidDataSource.kt`, `BasicDataSource.kt`, others 与 settings 的 `FingerprintDataSource.kt`**

## 问题核心代码

`AndroidDataSource` 没有任何数据源行为, 是纯常量表,  
却顶着 DataSource 之名 (`ui/home/datasource/AndroidDataSource.kt`, 全文件 144 行只有 companion object 常量):

```kotlin
class AndroidDataSource {
    companion object {
        const val PROP_AB_UPDATE = "ro.build.ab_update"
        const val PROP_VENDOR_SKU = "ro.boot.product.vendor.sku"
        // ...52 个常量, 无一个方法
    }
}
```

系统属性名是全设备共享的知识, 却作为 home 功能的私有物, 被 others 功能跨包引用 (`ui/others/datasource/BasicDataSource.kt`):

```kotlin
import net.imknown.android.forefrontinfo.ui.home.datasource.AndroidDataSource

fun getVendorSku() = propertyReader.getString(AndroidDataSource.PROP_VENDOR_SKU)
```

跨功能引用不止这一处, 且 home 与 settings 已成双向依赖:

- `HomeRepository` 注入 settings 功能的 `AppInfoDataSource`  
  (`ui/home/repository/HomeRepository.kt` 的 import 与构造参数, `detectWebView` 区使用);
- `SettingsRepository` 反向注入 home 功能的 `LldFileStore`  
  (`ui/settings/repository/SettingsRepository.kt` 的 import 与构造参数, 读内置资产版本用);
- `ui/others/datasource/BasicDataSource.kt` 引 home 的 `AndroidDataSource` 常量 (上面那处).

从包名判断不出依赖方向; `HomeViewModel` 还残留两个未使用的跨包 import (`MountDataSource`, `AppInfoDataSource`, 见  
[#45 第 12 项](../08-反模式与卫生/45-零散小问题.md)). 这两条注入边的归置 (共享 DataSource  
进中立层) 与模块化方向一致, 记录在 `docs/dev/module-structure-cn.md` 的待决问题里.

另外 others 与 settings 各有一个职责不同的 `FingerprintDataSource` (前者读分区指纹, 后者算签名证书 SHA-256), 同名异义, IDE 自动导入易错.

## 直接原因

常量跟着 "第一个使用者" 所在的 feature 放置; 命名沿用 DataSource 后缀, 但内容早已不是数据源.

## 根本原因

与 [#04](04-base一词三义.md) 同根: 缺一个中立的共享层 (core), 跨功能知识只能寄生在某个功能包里, 名字再错也只能将就.

## 修复方案

```kotlin
// core/android/AndroidProps.kt: 名副其实, 位置中立, 跨功能引用消失
object AndroidProps {
    const val AB_UPDATE = "ro.build.ab_update"
    const val VENDOR_SKU = "ro.boot.product.vendor.sku"
    // ...
}
```

两个 `FingerprintDataSource` 分别更名为 `PartitionFingerprintDataSource` 与 `SigningCertDataSource`  
(或随 [#04](04-base一词三义.md) 的包重排迁入各自功能后自然消歧). 随 #04 的机械搬移一并完成, 不单独开提交.
