# 06 技术栈缺口

> 返回 [README 索引](../README.md) · [1 · 架构与分层](../README.md#1--架构与分层).

**严重程度: P1(🟡, 工程配套) | 补齐节奏: 大重构开工前先补齐测试基础设施, 其余分批**

**已就位** (在 `gradle/toml/` 与 `build-logic/` 可核): coroutines (`kotlinx-coroutines-android`),  
Ktor + OkHttp 引擎  
(`ktor-client-okhttp`), kotlinx.serialization, libsu, Compose (BOM + Material 3),  
LeakCanary (`debugImplementation`),  
StrictMode (`app/src/debug/.../MyDebugApplication.kt` 的 `StrictMode.enableDefaults()`). 设置页是手写 M3,  
`androidx.preference` 已不在依赖目录里, View 时代的偏好界面没有留下兼容层.

**缺** (以下依赖或工具链在版本目录与 `build-logic` 里零出现): DataStore (+protobuf), Baseline Profiles,  
App Startup,  
Macrobenchmark, JUnit 5, MockK, Turbine, Espresso, Robolectric, Compose UI 测试. 测试基础设施的现状:  
`build-logic/.../KotlinAndroid.kt` 的 `configureTest()` 只挂了 `test = ["junit"]` (JUnit 4, 版本取 `android.toml`  
的 `junit`)  
与 `androidTest = ["test-core", "test-ext-junit"]`;  
`base/src/test/.../DateTimeExtTest.kt` 已有 4 个真实测试方法 (`isLldDatetime()` 的格式契约与 locale 无关性),  
`app/src/test` 里仍只有模板 `ExampleUnitTest`. 所以不是 "完全没有测试", 而是 "只有一处契约测试,  
且没有 CI 上必须通过的检查" (检查归 [#50](../09-构建与CI/50-CI只编译不测试.md)).

**版本 pin**: 唯一进入依赖解析的非稳定 pin 是 `kotlinx-serialization` (`gradle/toml/kotlin.toml`);  
[09-构建约定](../../../agents-cn/09-构建约定.md) 的版本分级允许 RC 直接进生产, 所以这不是违规,  
是应当如实记录的那一个 pin. `isPreview = "false"`, 因此走的是  
`compileSdk` / `targetSdk` / `buildTools` 的稳定条目; `compileSdkPreview`,  
`targetSdkPreview` 与 `androidGradlePlugin-canary` 这些条目当前没有消费者  
(空挂 toml 条目归 [#55](../09-构建与CI/55-构建配置杂项.md)).

**不算缺口**: Coil 缺席: 全项目唯一的图片用法是 `painterResource(tab.iconRes)` 加载本地导航图标 (`AppRoot()`),  
没有任何网络图片需要加载器.  
五个拆分版本目录 (`gradle/toml/` 下 build/android/kotlin/google/thirdParty) 是 [09-构建约定](../../../agents-cn/09-构建约定.md) 记的项目约定, 不是问题.

**补齐节奏**: JUnit 5 + MockK + Turbine 先行 (大重构开工前,  
与 #50 的 CI 检查同批); Espresso / Robolectric / Compose UI  
测试随迁移完成后的测试立项补齐 (迁移本身不带测试); Baseline Profiles / App Startup / Macrobenchmark 属更后期.
