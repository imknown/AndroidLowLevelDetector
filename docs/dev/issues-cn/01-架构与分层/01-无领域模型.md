# 01 数据层直接产出"展示内容", 全项目没有领域模型

> 返回 [README 索引](../README.md) · [1 · 架构与分层](../README.md#1--架构与分层).

**严重程度: P0 | 修复难度: 难**  
**影响文件: `ui/home/repository/HomeRepository.kt` (986 行, 按换行数), `OthersRepository.kt`, `PropRepository.kt`, `SettingsRepository.kt`,  
`MyModel.kt`, `MyModelExt.kt`, `MyModelCard.kt`, `MyModelListScreen.kt`**

## 问题核心代码

`HomeRepository.detectPerformanceClass()` 挂在数据层, 做的却是界面的事:

```kotlin
fun detectPerformanceClass(): MyModel = guardedMyModel(R.string.performance_class_title) {
    var performanceColorRes = StatusColor.CRITICAL          // ← 界面颜色

    val result = if (isAtLeastAndroid12()) {
        val performanceClass = Build.VERSION.MEDIA_PERFORMANCE_CLASS
        if (performanceClass == Build.VERSION.SDK_INT) {
            performanceColorRes = StatusColor.NO_PROBLEM        // ← 界面规则
        } else if (performanceClass == Build.VERSION.SDK_INT - 1) {
            performanceColorRes = StatusColor.WARNING
        }

        if (performanceClass != 0) {
            MyApplication.getMyString(R.string.performance_class_detail_api, performanceClass)  // ← 界面文案
        } else {
            MyApplication.getMyString(R.string.result_not_supported)
        }
    } else {
        MyApplication.getMyString(R.string.result_not_supported)
    }

    return toColoredMyModel(R.string.performance_class_title, result, performanceColorRes)
}
```

示例里的 `guardedMyModel` 只负责把抛出的异常降级成错误行, 对 "谁决定颜色" 没有影响; 这个函数已随 2a 删除.

颜色这一半在 Compose 迁移里已经改完 (`R.attr` 主题句柄换成了 `StatusColor` 枚举,  
见 [#44](../08-反模式与卫生/44-资源ID当逻辑值.md)), 2a 之后  
**颜色由 `HomeModelMapper` 决定**, 仓库只返回领域对象.

Home 的 23 个检测条目现在由仓库返回 `DetectResult<领域对象>` (其中两条再包 `List` / `Pair`),  
`MyModel` 由 `HomeModelMapper` 产出; 另外两页的仓库仍直接返回 `MyModel`.  
这个界面模型在另两页仍是跨层传递物:

```kotlin
// MyModel.kt → MyModel
@Immutable
data class MyModel(
    val title: MyModelTitle,          // 标题 (资源 ID 或字符串)
    val detail: String,               // 已拼好, 已本地化的展示字符串
    val color: StatusColor = StatusColor.NONE,   // 展示用状态色
    val type: MyModelType = General
)
```

Others 与 Prop 仍在仓库里就地翻译成人话: `toTranslatedDetailMyModel()` 把读到的值直接当 detail,  
没有任何可供下游判定的结果类型. Home 侧已经返回 `DetectResult<领域对象>`.

## 直接原因

仓库方法把三件事揉在一个函数里: **取数** (读 `Build.VERSION.MEDIA_PERFORMANCE_CLASS`),  
**判断** (和 `SDK_INT` 比较), **展示** (选文案, 选颜色).  
函数当场把判断结果翻译成了给用户看的字符串, 没有以数据形式把结果返回.  
`getMyString` 在 app 模块 main 源集有 **32 处限定调用** (全部为限定形式 `MyApplication.getMyString`,  
不含两个重载的定义, `MyApplication` 内部也没有自调用),  
其中 `HomeRepository` 3 处, `OthersRepository` 9 处, `SettingsStore` 11 处.

## 根本原因

项目从第一行代码起就没定义过  
"领域模型" (domain model, 只描述事实, 不关心怎么显示的数据结构, 例如 "媒体性能等级 = 33, 落后正式版 1 级").  
列表条目界面模型 `MyModel` 被直接下推到了最底层. 这份界面模型一旦成为各层之间通用的传递物:

- **不可测试**: Others 与 Prop 的检测逻辑离不开 `MyApplication.instance` (Context), `R.string`, `StatusColor`, 只能跑在真机上,  
  Home 侧已把判断与格式化拆开, `app/src/test` 与 `base/src/test` 现有 21 个测试类, 82 个测试方法;  
  另两页的检测逻辑仍没有单测.
- **不可复用**: 同一份检测数据想换个展示方式 (比如排序, 导出, 深色下换色), 必须重写取数逻辑.
- **反向依赖**: 数据层反过来依赖 UI 资源 (`R`), 违反了 "依赖只能从外层指向内层" 的分层规则,  
  也是 [#04](04-base一词三义.md) 包循环的一半成因.

## 修复方案

引入 "领域模型 + 映射器" 两步走: 仓库只返回纯数据; 把数据翻译成 `MyModel` 的映射函数放在 UI 包,  
且只放在那里. 这条约定的现状要交代清楚:  
[06-检测条目](../../../agents-cn/06-检测条目.md) 的流程  
Home 侧已经写成 "`detect...()` 返回 `DetectResult<领域对象>`", Others 与 Prop 仍是 "`get...()` 返回 `MyModel`",  
所以本条目对 Home 已经完成, 剩的是 Others 与 Prop 两页,  
改那两页时 [06-检测条目](../../../agents-cn/06-检测条目.md) 的 Others 与 Prop 分支要同步改写. 以 `detectPerformanceClass` 为例:

```kotlin
// ── domain 层: 纯 Kotlin, 无任何 Android 依赖, 可直接单测 ──
// ui/home/model/PerformanceClass.kt
sealed interface PerformanceClassInfo {
    data class Met(val api: Int) : PerformanceClassInfo          // 达标
    data class Lagging(val api: Int) : PerformanceClassInfo      // 落后一代
    data object NotDeclared : PerformanceClassInfo               // 设备未声明
    data object NotSupported : PerformanceClassInfo              // 系统低于 12
}

// ui/home/repository/HomeRepository.kt: 只剩取数 + 判断
fun detectPerformanceClass(): PerformanceClassInfo = when {
    !isAtLeastAndroid12() -> PerformanceClassInfo.NotSupported
    Build.VERSION.MEDIA_PERFORMANCE_CLASS == 0 -> PerformanceClassInfo.NotDeclared
    Build.VERSION.MEDIA_PERFORMANCE_CLASS == Build.VERSION.SDK_INT ->
        PerformanceClassInfo.Met(Build.VERSION.MEDIA_PERFORMANCE_CLASS)
    else -> PerformanceClassInfo.Lagging(Build.VERSION.MEDIA_PERFORMANCE_CLASS)
}
```

```kotlin
// ── ui 层映射器: 全项目唯一知道 "这个数据长什么样" 的地方 ──
// ui/home/mapper/HomeModelMapper.kt
fun PerformanceClassInfo.toMyModel(context: Context): MyModel {
    val detail = when (this) {
        is Met, is Lagging ->
            context.getString(R.string.performance_class_detail_api, api)
        NotDeclared, NotSupported ->
            context.getString(R.string.result_not_supported)
    }
    val color = when (this) {
        is Met -> StatusColor.NO_PROBLEM
        is Lagging -> StatusColor.WARNING
        else -> StatusColor.CRITICAL
    }
    return MyModel(
        title = MyModelTitle.Res(R.string.performance_class_title),
        detail = detail,
        color = color
    )
}
```

```kotlin
// ── HomeViewModel.detect() 内的调用点改为 ──
tempModels += homeRepository.detectPerformanceClass().toMyModel(context)
```

改造后可以写出这样的纯单元测试 (现在写不出来):

```kotlin
@Test
fun `落后一代时应返回 Lagging`() {
    // Shadows.shadowOf(Build.VERSION) 或抽象掉 Build 读取后
    assertEquals(PerformanceClassInfo.Lagging(35), repository.detectPerformanceClass())
}
```

**节奏 (已定)**: 一次性: 主线步骤 2a 集中迁移全部 detect* 方法,  
不走渐进. `MyModel`, `MyModelCard` / `MyModelListScreen` 不用动,  
它们本来就是 UI 层的东西, 动的只是 "谁生产 MyModel";  
`toColoredMyModel` / `toTranslatedDetailMyModel` (`MyModelExt.kt`) 里那套 `MyApplication` 取不到值时的默认处理,  
迁移时一并移入 mapper.

**边界说明**: 本项目是只读检测工具, 领域逻辑确实较薄, 不必追求完整的 domain 模块. 底线是把 "判断" 从 "格式化"  
里剥出来: 判断结果可测试, 可断言, 是防止以后越写越乱的最低要求.  
检测结果缺三态类型这条缺口记在 [#03](03-无三态模型与注册表.md).
