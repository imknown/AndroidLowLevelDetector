# 03 无三态模型, 无检测器注册表: 目录硬编码

> 返回 [README 索引](../README.md) · [1 · 架构与分层](../README.md#1--架构与分层).

**严重程度: P1(🔴) | 修复: 注册表引擎 + 三态结果类型**

- 唯一的行模型是 `MyModel(title, detail, color: StatusColor, type)`: "级别" 就是展示用状态色;  
  **不存在 支持/不支持/未知 的结果类型** ("支持/不支持" 只是本地化的详情字符串, `HomeRepository.toSupportOrNotString()`).  
  "Unknown 是一等结果" 在代码里没有表示.
- 缺的是三态结果**类型**, 不是颜色映射:  
  状态色 → 圆点色值 已有唯一一处 `ExtendedColors.of(status: StatusColor)`  
  (`MyModelCard` 经 `LocalExtendedColors.current.of(model.color)` 调用它). 圆点颜色不设中央定义,  
  各条目按自身语义决定,  
  现状为非缺陷 (见 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md), 有意接受); 缺的是让 "未知"  
  成为一等结果的三态类型.
- 目录是字面的 `tempModels += repository.detectXxx()` 序列:  
  Home 的序列在 `HomeViewModel.detect()` 里 (由 `collectModels()` 调用), `OthersViewModel.collectModels()`,  
  `PropViewModel.collectModels()` 各自一份: 增删条目 = 改函数体.
- 按调用点数量点目录, 得到的数和渲染行数对不上:  
  Home 23 个检测器调用产 **25 行** (`detectSecurityPatches` 产 2 行, `detectTrebleAndGsiCompatibility` 产 2 行);  
  Others 37 个 `tempModels +=` 里 31 个无条件, 6 个包在 `isAtLeastAndroid12()` / `isAtLeastAndroid10()` 里, 再加  
  `getPartitionFingerprints()` 的动态 N 行; Prop 5 个检测器, 每个产动态行数. 目录没有可核对的数据源,  
  只有调用顺序.
- 连锁后果: 没有三态类型, "未知" 没有一等表示; 没有注册表 → 目录无法按数据一一对应.
- 范围: Others/Prop 的检测器不碰状态色 (`StatusColor` 在 `OthersRepository` 与 `PropRepository` 零出现;  
  Prop 已随止血批转无色, Others  
  的失败行色归 [#69](../07-UI与无障碍/69-Others失败行渲染红色圆点.md)); 三态 + 注册表的工作只需覆盖 Home 条目.

**书面目标**: 三态语义, 注册表引擎, 有界并发维持书面目标,  
四值颜色属性 (`NoProblem` / `Warning` / `Critical` / `NONE`) 是被接受的过渡表示,  
这是代码里的待办, 不是文档抄写的问题. 圆点颜色不设跨条目的统一映射, 未知档由各检测项语义自行决定,  
现状为非缺陷 (见 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md), 有意接受), 本条目无待定前置.
