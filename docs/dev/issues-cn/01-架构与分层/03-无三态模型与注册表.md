# 03 无三态模型, 无检测器注册表: 目录硬编码

> **现状 (2026-11-22)**: 三页的清单都在各自的清单类里: Home 在 `ui/home/detect/HomeDetectorCatalog.kt`,  
> 23 条逐条对应目录的 HOME-01 到 HOME-23; Others 在 `ui/others/detect/OthersDetectorCatalog.kt`,  
> 37 条对应目录的 OTH-01 到 OTH-37; Prop 在 `ui/prop/detect/PropDetectorCatalog.kt`,  
> 5 条对应目录的 PROP-01 到 PROP-05. 下面记的是修之前的代码与判断.


> 返回 [README 索引](../README.md) · [1 · 架构与分层](../README.md#1--架构与分层).

**严重程度: P1(🔴) | 剩余修复: 三态结果类型 (注册表引擎已建第一版)**

- Others 与 Prop 的行模型仍是 `MyModel(title, detail, color: StatusColor, type)`: "级别" 就是展示用状态色;  
  Home 已有 `DetectResult` 三态 (Found / Missing / Failed) 与各条目的领域状态,  
  `toSupportOrNotString()` 已删除.  
  Home 的 `DetectResult` 定义了 `Missing` 这一档, main 源码还没有生产者, 另两页没有结果类型.
- Home 已有三态结果类型; 颜色映射并不缺:  
  状态色 → 圆点色值 已有唯一一处 `ExtendedColors.of(status: StatusColor)`  
  (`MyModelCard` 经 `LocalExtendedColors.current.of(model.color)` 调用它). 圆点颜色不设中央定义,  
  各条目按自身语义决定,  
  现状为非缺陷 (见 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md), 有意接受); `DetectResult` 定义了  
  `Missing` 这一档, main 源码还没有生产者 (归 subtask-05);  
  剩下的是把注册表与另两页接上.
- 目录是函数体里的字面序列: Home 是 `homeModelMapper.to...Model { homeRepository.detect...() }`,  
  Others 与 Prop 是 `tempModels +=`:  
  Home 的序列在 `HomeViewModel.detect()` 里 (由 `collectModels()` 调用), `OthersViewModel.collectModels()`,  
  `PropViewModel.collectModels()` 各自一份: 增删条目 = 改函数体.
- 把目录按调用点数一遍, 数出来的和渲染行数对不上:  
  Home 23 个条目产 **25 行** (`toSecurityPatchModels()` 与 `toTrebleAndGsiModels()` 各产 2 行);  
  Others 37 个 `tempModels +=` 里 31 个无条件, 6 个包在 `Build.VERSION.SDK_INT >= Build.VERSION_CODES.S` / `>= Build.VERSION_CODES.Q` 里, 再加  
  `getPartitionFingerprints()` 的动态 N 行; Prop 5 个检测器, 每个产动态行数. 目录没有可核对的数据源,  
  只有调用顺序.
- 连锁后果: 另两页没有三态类型, "未知" 没有一等表示; 没有注册表 → 目录无法按数据一一对应.
- 范围: Others/Prop 的检测器不碰状态色 (`StatusColor` 在 `OthersRepository` 与 `PropRepository` 零出现;  
  Prop 已随先行的低难度修复批转无色, Others  
  的失败行色归 [#69](../archived/07-UI与无障碍/69-Others失败行渲染红色圆点.md)); 三态 + 注册表的工作只需覆盖 Home 条目.

**书面目标**: 注册表引擎已建第一版 (三页的清单入各自的清单类, 引擎统一执行, 第一版串行);  
剩三态结果类型; 有界并发归 [#15](../04-并发与调度/15-检测串行不感知取消.md).  
四值颜色属性 (`NoProblem` / `Warning` / `Critical` / `NONE`) 是被接受的过渡表示,  
这是代码里的待办, 不是文档抄写的问题. 圆点颜色不设跨条目的统一映射, 未知档由各检测项语义自行决定,  
现状为非缺陷 (见 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md), 有意接受), 本条目无待定前置.
