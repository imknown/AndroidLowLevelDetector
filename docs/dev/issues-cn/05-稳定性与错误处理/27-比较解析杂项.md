# 27 比较与解析健壮性杂项

> 返回 [README 索引](../README.md) · [5 · 稳定性与错误处理](../README.md#5--稳定性与错误处理).

**严重程度: P3 | 修复难度: 低~中**


- **字符串当版本号比较** (三处): `HomeRepository.detectVndk()` 的 `vndkVersionResult >= lld.android.stable.api` (左边是 `PropertyReader.getString()` 拿到的字符串, 位数不同就比错 — `"9" > "34"`; AOSP 还允许 `ro.vndk.version` 取 `current`, 字典序里 `'c' > '3'`, 于是 `"current" >= "37"` 恒真, 直接假绿); `AndroidVersionExt.isLatestPreviewAndroid()` 的 `myAndroid.apiFull >= lld.android.preview.apiFull` (minor 到两位数即翻车: `"37.2" >= "37.10"` 为真); `LldFileStore.copyJsonIfNeededOrThrow()` 的 `savedLldVersion < assetLldVersion`. 这类的主体与收敛方向 (统一走版本对象, 日期解析后再比) 见 [#45 第 8 项](../08-反模式与卫生/45-零散小问题.md); lld 版本那一路的测试覆盖到哪一步, 见 [#19](19-版本合并残留弱点.md).
- **魔法偏移**: `HomeRepository.detectBuildId()` 内嵌的 `isDateHigherThanConfig()` 用 `250205 - 250101` 作 offset, 在非最新 stable 分支上加到 build 日期上. 两边都是 `yymmdd` 整数 (`getDate()` 取 build id 拆出的 `"250705"` 这一段再 `toIntOrNull()`), 相减得到的 104 不是真实天数 (这两个日期实际相差 35 天), 而这两个数本身属于当前那一季预览周期, 换一季就失真, 且失真不报错 (比较结果照样返回).
- **`": "` 分隔只取两段**: `MyModelExt.toPropMyModel()` 做 `rawProp.split(": ")`, 然后只用 `result[0]` 当标题, `result.getOrNull(1)` 当详情. 属性值里再出现 `": "` 时, 从第二个 `": "` 起的那几段整体丢弃 — 值 `[a]: [b: c]` 解析出的详情停在 `b`.
- **多行 prop 续块不回读**: `PropRepository.getBuildProp()` 用 `var temp = ""` 累积跨行值, 只在续行 `endsWith("]")` 时 `toPropMyModel(rawProp = temp)` 落一行; 循环结束后 `temp` 再没有被读过, 所以一份以非 `"]"` 行收尾的输出 (getprop 被截断, 或值本身没闭合) 会把攒下的整块静默丢掉, 既没有 `else` 也没有日志.
- **非 6 列行静默跳过**: `MountDataSource.getMounts()` 只处理 `columns.size == 6` 的行, 其余直接不进列表, 无 `else` 无日志. 尾部两列在 `Mount` 里保留为 `String` (`dummy0` / `dummy1`, 带注释说明 "没人消费它们, 当成数字解析曾是坏行的抛出路径") — 原先这条里的 `columns[4].toInt()` 无防护已随 `f089854a` 消失, 不再成立.
