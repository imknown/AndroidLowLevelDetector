# 67 两条检测规则的方向存疑 (VNDK, APEX)

> 返回 [README 索引](../README.md) · [5 · 稳定性与错误处理](../README.md#5--稳定性与错误处理).

**严重程度: P2 | 修复难度: 中 | 状态: 待负责人定 (规则方向需按 AOSP 文档/真机裁定)**

两行的判定规则与 AOSP 的兼容性语义方向对不上; 代码行为是确定的, **规则本身**要先裁定再改:

1. **VNDK**: `detectVndk()` 拿设备侧 `ro.vndk.version` 与库里最新 stable 的 API 比 "新不新" (`vndkVersionResult >= lld.android.stable.api`), 而 AOSP 的兼容性方向是 "系统镜像 (如 GSI) 提供的 VNDK 快照必须 ≥ 设备的 `ro.vndk.version`" — 比的对象与方向都可疑. 叠加两点: 框架/厂商两侧的 vndk 属性行被注释停用 (`HomeRepository` 里 `PROP_VENDOR_VNDK_VERSION` / `PROP_PRODUCT_VNDK_VERSION` 那两行), 现在只剩设备侧一个值; `ro.vndk.lite` 为真 (VNDK-Lite, 最小共享快照, **更**兼容的形态) 反被判 WARNING (`&& !hasVndkLite` 才给绿).
2. **APEX**: `detectApex()` 用挂载点含 `@` 认定 "遗留扁平 APEX" (`isLegacyFlattenedApex = !apexUpdatable && mounts.any { startsWith("/apex/") && contains("@") }`), 而 `/apex/<module>@<version>` 是已激活/可更新形态的挂载名, 遗留扁平 APEX 挂 `/apex/<module>` 无 `@` — 判据方向疑似写反, 且不同 Android 版本的挂载形态有差异.

## 处理

动手前先定规则: 按 AOSP 的 Treble/VNDK 与 APEX 文档把 "这两行该比什么、往哪个方向比" 写下来 (顺带核对挂载形态要用真机), 再改判定. 比较手法层面的字典序问题另记 [#27](27-比较解析杂项.md), 本条只管规则方向.
