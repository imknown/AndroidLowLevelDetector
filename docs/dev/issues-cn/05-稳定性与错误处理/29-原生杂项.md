# 29 原生杂项

> 返回 [README 索引](../README.md) · [5 · 稳定性与错误处理](../README.md#5--稳定性与错误处理).

**严重程度: P3 | 修复难度: 低**


- `BinderDetector.cpp` 的 `release()` 无条件 `close(fd)`,  
  而 `getBinderVersion()` 在 `fd < 0` 的失败分支也走它 (`getErrorNo(...)` → `release(...)`) → 对失败的 `open()` 收的是 `close(-1)`.  
  修复: `release()` 里判 `fd >= 0` 再关, 或让失败分支不进 `close`.
- `binderDetector/src/main/cpp/CMakeLists.txt`: `cmake_minimum_required(VERSION 3.10)`, 全文件没有任何编译选项:  
  无 `-Wall` / `-Wextra` / `-Werror`, 无 LTO. 现有加固只靠 AGP 默认 (stack-protector, `_FORTIFY_SOURCE`), 本模块没有另加 flag,  
  所以 "加固够" 这句的前提是默认值不动. 把 `cmake_minimum_required` 抬上去是 CMake 脚本自己的声明, 与 [AGENTS.md](../../../../AGENTS.md) 钉在  
  `gradle/toml/build.toml` 里的 NDK / CMake 版本  
  (`ndk = "30.0.16248370"`, `cmake = "4.1.2"`, 由 `build-logic` 传给模块) 是两件事, 不要一起改, 也不要指望改这一行会换掉构建用的 CMake.
- `:binderDetector` 没有 `consumer-rules.pro`  
  (全仓只有 `base/consumer-rules.pro`, 且只有 `base/build.gradle.kts` 注册了 `consumerProguardFiles`):  
  JNI 符号目前靠 AGP 默认 keep 规则保住, 参照 `:base` 补一份显式的.
- 命名不一致: `binderDetector/build.gradle.kts` 的 `namespace = "net.imknown.android.forefrontinfo.binderDetector"`  
  (大写 D), Kotlin 侧包名却是 `net.imknown.android.forefrontinfo.binderdetector` (小写, `BinderDetector.kt`), JNI 函数名  
  `Java_net_imknown_android_forefrontinfo_binderdetector_BinderDetector_getBinderVersion` 跟的是小写那个.
- `BinderDetector.h` 手写 `struct binder_version { __s32 protocol_version; };`,  
  而 `__s32` 不在本文件 include 的任何一个头里  
  (`jni.h`, `cerrno`, `android/log.h`, `cstdlib`, `cstring`, `unistd.h`, `sys/ioctl.h`, `fcntl.h`), 靠传递引入;  
  内核 uapi 的 `<linux/android/binder.h>` 里有这个结构体的正身 (`.cpp` 顶部的注释链就指着它), 直接 include 比手写稳.
