# 65 外链跳转依赖 resolveActivity 判浏览器存在, Android 11+ 包可见性下判空

> 返回 [README 索引](../README.md) · [5 · 稳定性与错误处理](../README.md#5--稳定性与错误处理).

**严重程度: P2 | 修复难度: 低**

## 问题核心

`SettingsScreen.kt` 的 `openInExternal()` 用

```kotlin
if (intent.resolveActivity(context.packageManager) != null) { ... }
```

判定 "有没有浏览器" 再决定跳不跳. 而:

- 全仓 manifest **没有任何 `<queries>` 声明**;
- targetSdk 37, Android 11+ 的包可见性过滤生效;
- 官方 "自动可见" 清单 (自家应用, 特定系统包, 安装来源等) **不含浏览器** — 无 `<queries>` 时, 对 http/https 的 `ACTION_VIEW` 做 `resolveActivity` 查询, 浏览器被可见性过滤挡住, 返回 null;
- `resolveActivity` 本身自 API 30 起废弃.

后果: 商店 / 源码 / 隐私政策 / 许可 / 译者信息五个外链行可能集体判 "无浏览器" 而不发起跳转 — 判空挡在了 `startActivity` 前面, 而系统对隐式 intent 的实际解析并不受这个过滤限制 (`startActivity` 本可以照常工作).

## 直接原因

把 "查询结果为空" 当 "没有浏览器": 在包可见性模型下, 查询结果为空只说明 "看不见", 不说明 "不存在".

## 根本原因

Android 11 引入可见性过滤后, "判存在再跳" 的旧模式整体失效; 迁移/targetSdk 升级时没有复查这段.

## 修复方向 (二选一)

- manifest 加 `<queries>` 的 http/https `VIEW` intent (官方 "Fulfill common use cases" 的开 URL 配方), 保留现有判空逻辑;
- 或者去掉 `resolveActivity` 判空, 直接 `startActivity` 并捕获 `ActivityNotFoundException`.

**真机核对一项**: 修前先在一台 Android 11+ 设备确认 `resolveActivity` 确实返回 null (机制是文档行为, 本条未做设备验证).
