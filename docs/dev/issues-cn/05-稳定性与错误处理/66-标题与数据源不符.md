# 66 Others 页标题与数据源不符, 字面读会得出错误因果

> 返回 [README 索引](../README.md) · [5 · 稳定性与错误处理](../README.md#5--稳定性与错误处理).

**严重程度: P2 | 修复难度: 低 (binder 行语义待负责人定)**

这几行不是算错, 是**标题说的和数据给的不是同一个东西** — 用户按字面理解会得出从数据里推不出来的结论:

1. **`os_arch` = "Current process architecture"**, 数据是 `System.getProperty("os.arch")` (`ArchitectureDataSource.getArchitectureOrNullOrThrow()`) — Android 上该值取内核架构, 32 位进程在 64 位内核上照样是 `aarch64`: 报的不是 "进程" 的架构.
2. **`build_cpu_abi` = "Current process ABI"**, 数据是 `Build.CPU_ABI` (已废弃) — 那是**设备**主 ABI, 与进程无关; 同一区还摆着 `current_system_abi` (`ro.product.cpu.abi`) 与 supported 32/64 位 ABI 列表, 三者混在 "进程" 叙事里.
3. **`build_stock_fingerprint` = "Stock ROM fingerprint"**, 数据是 `Build.FINGERPRINT` 原样返回 — 全程没有任何与官方镜像的比对, "Stock" (未刷机/原厂) 这个定语没有支撑. (同族里分区指纹那组是对的: 分区名与 `ro.<partition>.build.fingerprint` 的拼法跟 AOSP 一致, 也正确排除了 bootloader/radio.)
4. **`binder_status` = "Binder bit"** 的语义待定: `BINDER_VERSION` ioctl 返回的协议版本由内核按**调用方 ABI** 给 (compat/32 位 → 7, 64 位 → 8), 所以这一行的结果恒与 `current_process_bit` 一致 — 它测的是 "本进程看到的 binder 接口", 不是独立的设备属性. 这不是值域错误 (7/8 的映射是对的), 是 "这行到底想报什么" 没定义: 独立语义 (等 `hw/vnd_binder` 那类扩展, 资源已死, 见 [#49](../08-反模式与卫生/49-lint死资源.md)) 还是并入进程位宽行, 由负责人定.

## 修复方向

1-3 是标题与数据对齐的问题: 改标题 (去掉 "process" / "Stock") 或换数据源, 二选一, 改动只在 strings 与(必要时)`ArchitectureDataSource`. 第 4 条先定语义再动.
