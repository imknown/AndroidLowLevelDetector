# 31 · 主题文件里的死配色与首次组合的额外开销

> 返回 [README 索引](../../README.md) · [6 · 性能](../../README.md#6--性能).

**严重程度: P1 | 修复难度: 低 | 状态: 已修复 (死代码注释保留, 未删除)**

**现象**: `ui/theme/Theme.kt` 定义了 6 套 `ColorScheme`, 实际只用了 `lightScheme` / `darkScheme` 两套:  
medium/high contrast × light/dark 四套零引用; 同文件的 `ColorFamily` 与 `unspecified_scheme` 也是零引用.  
`AppTheme()` 的 `when` 分支只在 `dynamicDarkColorScheme` / `dynamicLightColorScheme` / `darkScheme` / `lightScheme` 之间选.

**问题代码**:

```kotlin
// Theme.kt 里四套对比度 colorScheme: 4 套, 全部零引用
private val mediumContrastLightColorScheme = lightColorScheme(...)
private val highContrastLightColorScheme   = lightColorScheme(...)
private val mediumContrastDarkColorScheme  = darkColorScheme(...)
private val highContrastDarkColorScheme    = darkColorScheme(...)

// Theme.kt 里的 ColorFamily / unspecified_scheme: 零引用 + public + snake_case
@Immutable data class ColorFamily(...)
val unspecified_scheme = ColorFamily(Color.Unspecified, ...)
```

**规模 (按行实测)**: `Theme.kt` 333 行, `Color.kt` 219 行, 合计 552 行. 死代码约 304 行 (164 + 140): `Theme.kt` 里从  
`mediumContrastLightColorScheme` 到 `unspecified_scheme` 是 164 行,  
`Color.kt` 里名字带 `MediumContrast` / `HighContrast` 的颜色常量正好 140 行 (219 行的绝大部分), 它们只被上面那 4 套死配色喂参数.  
每套配色是 35 个颜色条目 (`lightColorScheme` / `darkColorScheme` 各接 35 个具名实参).

**直接原因**: Material Theme Builder 一键生成后只接了主配色, 其余 4 套留在文件里没人删.

**根本原因**: 生成物未经 "用不用得着" 的裁剪就入库. 再加上 Kotlin 顶层属性的初始化语义: 这些 `private val` 与 `AppTheme` **在同一个文件**里,  
编译产物是 `ThemeKt`, 访问 `AppTheme()` 会触发 `ThemeKt.<clinit>`, **6 套配色在首次组合时被一次性全部构造**, 而其中 4 套永远用不上.  
`unspecified_scheme` / `ColorFamily` 同理, 还是 `public` 且是 snake_case (与项目的 `official` 代码风格冲突),  
等于对外暴露了一个没人用的 API.

**核实过的一个疑问**: 系统设置里有 "Color contrast" (Default / Medium / High) 档位, 这 4 套对比度配色看起来正是为它准备的,  
但那只是生成器的意图: 代码里没有任何读取档位并选择配色的接线, 档位调到 High 也不会有人选中它们.  
`MainActivity.kt` 里唯一的 "contrast" 是 `isNavigationBarContrastEnforced` (导航栏遮罩), 与配色无关;  
且 app 在 Android 12+ 默认走动态配色, 即使平台把对比度揉进壁纸派生色板, 响应路径也是 `dynamicXxxColorScheme()`, 轮不到静态配色.

**处置**: 死代码整体注释保留, 未删除:

- `Theme.kt`: 4 套对比度配色 + `ColorFamily` + `unspecified_scheme` 用块注释包起,  
  只被它们引用的 `import androidx.compose.runtime.Immutable` 与 `import androidx.compose.ui.graphics.Color` 一并注释,  
  各带一段说明恢复条件的 why 注释.
- `Color.kt`: 只喂那 4 套配色的 `MediumContrast` / `HighContrast` 颜色常量分 `Light` / `Dark` 两段块注释保留, 同样带 why 注释.
- 效果: `ThemeKt.<clinit>` 不再构造那 4 套配色, 首次组合的一次性额外开销消除, IDE 未用告警消失;  
  源码仍在文件里, 翻注释即可见.
- 将来做静态主题的对比度适配时: 优先另起文件并按需构造 (`lazy` 或函数), 不要挂回 `Theme.kt` 的静态初始化;  
  到时按现行 Material Theme Builder 重新生成或从注释恢复均可, 以与现行 `lightColorScheme` / `darkColorScheme` 同源为准.
- 验证: `assembleFossDebug` 构建通过; ILS 诊断无新增 (仅 `AppTheme` 命名与注解括号两条存量告警).
