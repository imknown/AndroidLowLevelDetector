# 05 组合根分散: 每个 ViewModel 自己 new 一套对象图

> 返回 [README 索引](../../README.md) · [1 · 架构与分层](../../README.md#1--架构与分层).

**严重程度: P1 | 修复难度: 低**
**影响文件: `HomeViewModel.kt`, `OthersViewModel.kt`, `PropViewModel.kt`, `SettingsViewModel.kt`**

## 问题核心代码

接线写在四个 ViewModel 各自的伴生 `Factory` 里 (`HomeViewModel.Factory`):

```kotlin
companion object {
    val Factory: ViewModelProvider.Factory = viewModelFactory {
        initializer {
            HomeViewModel(                                  // ← 界面层在组装数据层
                HomeRepository(LldDataSource(), MountDataSource(), AppInfoDataSource())
            )
        }
    }
}
```

`OthersViewModel.Factory` 一口气 new 7 个对象 (6 个 DataSource + 1 个 Repository: `BasicDataSource()`, `ArchitectureDataSource()`, `RomDataSource()`, `FingerprintDataSource()`, `KernelDataSource()`, `OthersDataSource()` 喂给 `OthersRepository`), `PropViewModel.Factory` new `PropRepository(PropertiesDataSource(), SettingsDataSource())`, `SettingsViewModel.Factory` new `SettingsRepository(AppInfoDataSource(), FingerprintDataSource())` — 四个入口四套接线.

## 直接原因

对象图的组装代码 ("谁依赖谁" 的知识) 没有固定归属, 被复制到了每个界面入口. 改 `HomeRepository` 的构造签名, 表面上要动 1 个类, 实际上要动组装它的 `HomeViewModel.Factory` — 而 `HomeRepository` 的调用方还有测试和未来第二个使用方 (比如小部件, 快捷方式入口) 都得再抄一遍.

## 根本原因

缺少组合根 (composition root, 全项目唯一一处负责创建和装配对象的地方). DI 的价值不在框架, 而在 "接线知识只写一次": 现在接线知识写了四遍, 且写在最不稳定的 UI 层.

## 约定与目标的分界

[AGENTS.md](../../../../../AGENTS.md) 把 "每个 ViewModel 用手写伴生 `Factory` 接线, Screen 用 `viewModel(factory = ...)` 取" 记为**当前约定**, 并明确要求新增 ViewModel 照 `HomeViewModel.Factory` 抄. 所以本条目针对的**不是 "要不要手写 Factory" 这个形式问题** (形式随组合根形态而定); 针对的只是 **同一份组装知识在四个伴生对象里各写一遍** 这件事. 目标形态引入 DI 框架后 (见 [#02](../../01-架构与分层/02-服务定位器上帝对象.md)), 伴生 `Factory` 随图整体消失.

## 修复方案

组合根落地为 Metro 图 (两段式划分见 [#02](../../01-架构与分层/02-服务定位器上帝对象.md)), 本条目随第一段关闭:

```kotlin
@Inject
@ViewModelKey
@ContributesIntoMap(AppScope::class, binding<ViewModel>())
class HomeViewModel(
    private val homeRepository: HomeRepository
) : BaseListViewModel()
```

四个伴生 `Factory` 整体删除: ViewModel 进入 MetroX 的 `Map<KClass<out ViewModel>, () -> ViewModel>` multibinding, 由图持有的 `MetroViewModelFactory` 按 `KClass` 创建 (工厂子类 `AppViewModelFactory` 挂 `@ContributesBinding`, 经 `AppGraph` 的 `metroViewModelFactory` 访问器暴露). `binding<ViewModel>()` 必须显式给出 — Metro 默认绑到直接父类型, 四个 ViewModel 的直接父类都是 `BaseViewModel`/`BaseListViewModel`, 不指定会把 map 的 key 绑错且运行期才暴露.

取用端同步换: `AppRoot()` 四条 entry 的 `viewModel<HomeViewModel>(factory = HomeViewModel.Factory)` 改 `metroViewModel<HomeViewModel>()`, 工厂经 `LocalMetroViewModelFactory` 在 `MainActivity.setContent` 根部下发; entry 作用域不变 (`metroViewModel()` 读的就是 Nav3 ViewModelStore 装饰器的 owner).

组装知识从 "容器里手写一遍" 收敛进各构造函数签名, 由编译器建图校验; 本条目不再以 "#02 完成容器" 为前置 — 图本身就是组合根, [#02](../../01-架构与分层/02-服务定位器上帝对象.md) 的静态单例归其第二段.

View 时代的 `MY_REPOSITORY_KEY` + `extrasProducer` 样板已随 `4093cd0c` (Navigation 3 单 Activity 骨架, 四个 Fragment 同批删除) 一起消失: 那次提交把接线从 Fragment 的 extras 搬进了 ViewModel 伴生 `Factory`, 入口改成 `viewModel(factory = ...)`. 于是当年 "四个 Fragment 各写一份接线" 剩下的问题只有一个更小的版本: **同一份接线在四个 ViewModel 伴生对象里各写一遍**.
