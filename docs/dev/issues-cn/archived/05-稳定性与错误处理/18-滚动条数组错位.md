# 18 · 滚动条选项数组的 keys / values 长度错位

> 返回 [README 索引](../../README.md) · [5 · 稳定性与错误处理](../../README.md#5--稳定性与错误处理).

**严重程度: P1 | 修复难度: 低 | 状态: 已修复 (values 侧改成一致的 2 项, 平行数组的重构未做)**

**现象**: `ui/settings/res/values/arrays.xml` 里 `scrollBarKeys` 只剩 2 个活 item ("fast" 一行注释),  
并行的 `scrollBarValues` 仍是 3 项. `SettingsChoiceDialog()` 用 `labels.zip(values)` 拼选项,  
`zip` 截断到较短一侧, 所以第 3 个 value 藏在界面之外, 当下既不崩也不显示错;  
但两种 "把它补齐" 的改法各自都会出错: 只放开 keys 侧的 item 行,  
`@string/interface_fast_scroll_bar_key` 在四个 locale 文件里都是注释状态, 资源引用解析不到, 资源链接失败;  
连 key 字符串一起放开, 已下线的 "可拖动" 选项回到设置界面,  
选中它等于什么都不画 (`drawsScrollBar` 为 false, 无实现, 见 [#37](../../07-UI与无障碍/37-滚动条可拖动是stub.md)).

**直接原因**: 下线 "fast scrollbar" 选项时只改了 keys 一侧.

**根本原因**: 平行数组的两侧没有一起维护; 用两个平行数组 + `zip` 表达 (label, value) 对的建模方式  
本身缺少长度一致性保障.

**怎么修的**: `scrollBarValues` 的第 3 个 item (`@string/interface_fast_scroll_bar_value`) 注释掉,  
与 keys 一样是 2 项, item 行上方留 why 注释说明字符串本体保留的原因.  
issue 原方案里更彻底的那条 (消灭整类问题: `SettingsChoiceDialog()` 改收  
`PersistentList<Choice(label, value)>` 单一数据来源) 未做: 影响面覆盖 theme 与 scrollbar 两组调用,  
超出原条目 "改动少, 影响面小" 的批次定位, 要做时单独议.

- 字符串 `interface_fast_scroll_bar_value` (值 `"2"`) 保持活资源: `SettingsStore.parseScrollBarMode()`  
  经 `fastScrollBarValue` 引用它, 把老用户存量的 `"2"` 认成 `ScrollBarMode.Draggable`, 删掉编译不过.
- 老用户行为不变: 存量 `"2"` 仍解析为 Draggable, 对话框里没有可匹配的行, 不选中任何项, 与修复前一致.
- 全仓确认 `scrollBarKeys` / `scrollBarValues` 只有 `SettingsScreen` 一处消费  
  (`stringArrayResource` 两个数组后 `zip`); 同文件的 `themeKeys` / `themeValues` (3/3) 不受影响.
- 验证: `assembleFossDebug` / `testFossDebugUnitTest` / `lintFossDebug` 全部通过 (资源链接真实跑过).
