# 61 · 数据加载惰性化 (WhileSubscribed)

> 返回 [README 索引](../../README.md) · [3 · UDF · 单向数据流](../../README.md#3--udf--单向数据流).

**严重程度: P3 | 修复难度: 中~难**

**结论**: 不是缺陷 — `BaseListViewModel` 的 UI 触发型加载 (`init()` 幂等 + `loadJob` 去重 + VM 级 `StateFlow` 缓存) 对现在的本地 prop 数据源是**对的形态**, README "已经做对的地方" 一节把它列为要保留的行为. 本条登记一个**数据源升级时的设计预案**, 触发条件未到前无待办.

**证据**:

- 现状形态: 组合内 `LaunchedEffect` 触发 `BaseListViewModel.init()`, 幂等 + `loadJob` 去重, `modelsStateFlow` 刷新不擦旧列表 — 属 UI 触发型, 即 Ian Lake 定调的两种反模式之一 (文章: [Loading Initial Data in LaunchedEffect vs. ViewModel](https://proandroiddev.com/loading-initial-data-in-launchedeffect-vs-viewmodel-f1747c20ce62)).
- 迁移期观察记录的原裁定 (2026-09-19): 本地 prop 毫秒级零成本, 幂等 + loadJob 去重 + VM 级缓存已挡住该反模式的两个实际危害 (重复触发 / 生命周期错位), 惰性化收益趋近于零, 现在不动.
- 触发条件: **列表数据源本身**从本地变为网络 / 数据库 — 现在的联网只在线刷新 `lld.json` 文件, 列表加载路径仍是本地, 所以未触发. 与 [#59](../../07-UI与无障碍/59-Expressive主题跟进.md) / [#60](../../07-UI与无障碍/60-StyleAPI跟进.md) 的版本触发不同类.
- 出处: Compose 迁移遗留优化 (2026-09-25 抢救版清单之外的独立一条, [归档 spec](../../../../spec/archived/2026-09-17-21-14-43-+0800-compose-migration-cn/plan.md) ST-02 遗留节). 曾随抢救件入册为附录; 现行 tracker (按性质重建版) 已无对应条目 (2026-10-04 全目录 grep 零命中), 本条补回并把出处锚定到归档 spec.

**处理**: 保持现状. 触发时按文章理想态重造 — 数据层暴露冷 Flow, `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), initial)` 惰性观察 (首订阅才加载, 失订阅 5 秒后停), UI 侧 `collectAsStateWithLifecycle` 消费; 现有 "刷新不闪空" 与 loadJob 去重语义如何在新形态下保留, 属届时方案的一部分.
