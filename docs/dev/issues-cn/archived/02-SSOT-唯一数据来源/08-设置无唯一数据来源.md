# 08 设置项绕开唯一数据源, 五个读取点各自偷读

> 返回 [README 索引](../../README.md) · [2 · SSOT · 唯一数据来源](../../README.md#2--ssot--唯一数据来源).

**严重程度: P0 | 修复难度: 中**
**影响文件: `SettingsScreen.kt`, `SettingsViewModel.kt`, `HomeViewModel.kt`, `HomeRepository.kt`, `MyApplication.kt`**

## 问题核心代码

"设置" 这份本该只有一处权威的数据, 现状是**写一处, 抄五路**:

写入只有一处 (`SettingsScreen() 的各 onXxxSelect 回调`, 每个选项的回调里直接 `edit { put... }`); 读取则有五路各自摸 `SharedPreferences`:

```kotlin
// ① 启动时读主题 — MyApplication.initTheme()
val themesValue = sharedPreferences.getString(themeKey, defaultTheme)

// ② 启动时读滚动条档 — MyApplication.initScrollBar()
val scrollBarValue = sharedPreferences.getString(
    getMyString(R.string.interface_scroll_bar_key),
    getMyString(R.string.interface_no_scroll_bar_value),
)

// ③ 设置页读自己那四档 — SettingsScreen() 里四组 remember 直读 prefs
var allowNetwork by remember {
    mutableStateOf(MyApplication.sharedPreferences.getBoolean(allowNetworkKey, false))
}

// ④ ViewModel 读联网开关 — HomeViewModel.collectModels()
val allowNetwork = MyApplication.sharedPreferences.getBoolean(
    MyApplication.getMyString(R.string.function_allow_network_data_key), false)

// ⑤ 仓库读排序开关 — HomeRepository.getOutdatedTargetSdkVersionApkModel()
val shouldOrderByPackageNameFirst = MyApplication.sharedPreferences.getBoolean(...)
```

没有 `SettingsStore` / `PrefsFlow` 之类的可观察仓库, 也没有任何一处集中定义这些键; 键名靠 `MyApplication.getMyString(R.string.*_key)` 在每个读取点就地翻译.

**"值变了" 的通知已经是数据流, 不是广播**: 原来挂在 `SettingsViewModel` 伴生对象上的那三条静态流如今全仓零出现 — `outdatedOrderChangedSharedFlow` 随 `55ecc34a` (排序开关改为消费者直接观察 prefs) 删除, `scrollBarModeChangedSharedFlow` 与 `emitScrollBarModeChangedSharedFlow` 随 `121dd849` 删除, 后者用 `MyApplication.scrollBarMode: StateFlow<ScrollBarMode>` 顶替了这套 emit/collect 机制, 由 `MyModelListScreen.kt` 与 `SettingsScreen.kt` 各自 `collectAsStateWithLifecycle()` 收集, 滚动条设置因此真的生效 (列表页的滚动指示条由 `ui/common/ScrollBarExt.kt` 的 `Modifier.nonInteractiveScrollbar()` 手绘). 排序开关则由消费者自己观察数据源 (`HomeViewModel.outdatedOrderChangeListener`):

```kotlin
// HomeViewModel — 观察自己的 key, replay 问题不复存在
private val outdatedOrderChangeListener =
    SharedPreferences.OnSharedPreferenceChangeListener { _, key ->
        if (key == MyApplication.getMyString(R.string.function_outdated_target_order_by_package_name_first_key)) {
            outdatedOrderChanges.update { it + 1 }
        }
    }
```

于是剩下的缺口全在读取侧: 上面五路各自摸 `MyApplication.sharedPreferences`, 没有一处可观察的来源; `SharedPreferences` 是这些状态流唯一的持久层, 启动之后别处改了存值, 没有任何机制把它送进流.

## 直接原因

- 五个读取点绕过一切抽象直接摸 `MyApplication.sharedPreferences` (这是 [#02](../../01-架构与分层/02-服务定位器上帝对象.md) 服务定位器的一个实例).
- 主题的副作用已经收拢了一半: `AppCompatDelegate.setDefaultNightMode` 随 `26b9094f` 移除, `MyApplication.themeMode` 是一条 `StateFlow<AppThemeMode>`, 由 `AppTheme` 收集 (`Theme.kt` 里 `MyApplication.themeMode.collectAsStateWithLifecycle()`); `scrollBarMode` 同形. 剩下一半没动: 写入仍由 `SettingsScreen() 的 onThemeSelect` / `onScrollBarSelect` 直接落 prefs 再调 `setMyTheme` / `setMyScrollBar`, 仍属 "写路径没有归属".
- 键的解析方式本身也是重复的: 五个读取点各自 `getMyString(R.string.*_key)`, 没有一处集中定义 (键资源是 `translatable="false"`, 所以存值稳定, 但代码路径分散).

## 根本原因

SSOT(Single Source of Truth, 唯一数据来源: 每份数据只保存在一个地方, 其他地方都观察它) 没有建立. 设置数据缺一个 "可观察的仓库", 导致每个用它的地方各自发明读取路径; 界面能跟着状态流走, 是因为有人把流补在了 `MyApplication` 上, 不是因为读取路径收敛了 — 再加一个设置项, 仍然要动存储键与文案, 选项数组, 设置页的行与回调, 每个消费方.

## 修复方案

先要回答一个问题: 现有路线是不是终态. 已经走过的一条路是把偏好接到 `MyApplication` 伴生对象的 `StateFlow` 上 (主题与滚动条两档都是这么修的) — 那是伴生对象上的流, 不是 ViewModel 伴生对象, 所以没有撞上 [AGENTS.md](../../../../../AGENTS.md) "No static event buses" 那条规则. 它的代价是把 "偏好状态" 叠在上帝对象上 ([#02](../../01-架构与分层/02-服务定位器上帝对象.md) 的八职之一), 而且每加一个设置项就再补一对 `xxxMode` + `setXxx()`. **动手前先与负责人确认: 这条 `MyApplication` 伴生流路线是否就是可接受的终态**; 若是, 下面的 `SettingsStore` 方案只在 "写路径归位" 这一层有意义; 若不是, 才整段实施.

第一步, 给 SharedPreferences 加 Flow(androidx 官方尚无现成扩展, 十几行即可; 日后想换 DataStore 时只改这一个文件):

```kotlin
// ui/settings/repository/PrefsFlow.kt
fun SharedPreferences.keyFlow(): Flow<String> = callbackFlow {
    val listener =
        SharedPreferences.OnSharedPreferenceChangeListener { _, key -> trySend(key) }
    registerOnSharedPreferenceChangeListener(listener)
    awaitClose { unregisterOnSharedPreferenceChangeListener(listener) }
}

fun SharedPreferences.stringFlow(key: String, default: String? = null): Flow<String?> =
    keyFlow()
        .onStart { emit(key) }              // 订阅时先推一次当前值, 取代各处手动初读
        .filter { it == key }
        .map { getString(key, default) }
        .distinctUntilChanged()

fun SharedPreferences.booleanFlow(key: String, default: Boolean = false): Flow<Boolean> =
    keyFlow()
        .onStart { emit(key) }
        .filter { it == key }
        .map { getBoolean(key, default) }
        .distinctUntilChanged()
```

第二步, 建唯一的设置数据仓 (与现有的 `SettingsRepository` — 关于页版本信息仓库 — 避免重名, 取名 `SettingsStore`), 所有键集中定义:

```kotlin
// ui/settings/repository/SettingsStore.kt
class SettingsStore(private val prefs: SharedPreferences) {   // 项目用的是具名 prefs 文件, 不是默认那个
    private fun key(@StringRes id: Int) = MyApplication.getMyString(id)

    val themeMode: Flow<String?> =
        prefs.stringFlow(key(R.string.interface_themes_key),
            key(R.string.interface_themes_follow_system_value))
    val scrollBarMode: Flow<String?> = prefs.stringFlow(key(R.string.interface_scroll_bar_key))
    val allowNetworkData: Flow<Boolean> =
        prefs.booleanFlow(key(R.string.function_allow_network_data_key))
    val outdatedOrderFirst: Flow<Boolean> =
        prefs.booleanFlow(key(R.string.function_outdated_target_order_by_package_name_first_key))
}
```

第三步, 消费方改为观察同一个来源 (UDF 恢复为: 数据向下流, 事件向上交). 排序开关已经是这个形状的现成实例 — `HomeViewModel.outdatedOrderChangeListener` 自己注册 `OnSharedPreferenceChangeListener`, 把 "键变了" 折进一条 `StateFlow`, 没有任何广播. 照同样的方向收:

```kotlin
// SettingsScreen — 只交意图给 ViewModel, 不再自己碰 prefs
onThemeSelect = { value -> viewModel.setTheme(value) },
onAllowNetworkChange = { value -> viewModel.setAllowNetworkData(value) },
onScrollBarSelect = { value -> viewModel.setScrollBarMode(value) },
```

```kotlin
// 列表页: 观察 store, 而不是各自读 prefs (现有的 MyApplication.scrollBarMode 收集点换成这条)
val scrollBarMode by settingsStore.scrollBarMode.collectAsStateWithLifecycle(initialValue = null)
```

```kotlin
// HomeViewModel — 联网开关从构造注入的设置仓读
private val settingsStore: SettingsStore,   // 构造参数 (经 Factory 注入)
override suspend fun collectModels(): List<MyModel> {
    val allowNetwork = settingsStore.allowNetworkData.first()
    ...
}
```

主题与滚动条的 "界面跟着变" 这一步**已经落地**: `AppThemeMode.isDark()` 是三态→明暗的唯一映射, `AppTheme` 收集 `themeMode`, `MainActivity.isAppDark()` 只读它来设窗口明暗; 滚动条侧由 `MyApplication.scrollBarMode` 承担同一角色. 剩下的只是把那对 "直接写 prefs + 直接调 `setMyTheme` / `setMyScrollBar`" 的写路径并进 `SettingsStore` 的写入口.

改造后: 设置项加一个, 只动 `ui/settings/res/values/strings.xml` (键与文案, 四语) + `SettingsStore` (加一行 Flow) + 消费方 (收集它); 五个直读 prefs 的点改成观察它. #10 是本条目的 UI 侧投影 (见 [#10](10-设置页直读SharedPreferences.md)), 合流实施最省.
