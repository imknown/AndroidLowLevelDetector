# 54 构建脚枪 (休眠)

> 返回 [README 索引](../../README.md) · [9 · 构建与 CI](../../README.md#9--构建与-ci).

**严重程度: P2(🟢) | 修复难度: — | 处置: 有意接受, 无待办**

留这一条是把三个 "看着像欠账, 实际不动才对" 的点位和它们各自的触发条件说清楚.

- **`isPreview` 一行翻整树**. `gradle/toml/build.toml` 现在 `isPreview = "false"`, 同文件挂着 `compileSdkPreview = "37.2-beta3"` 与 `targetSdkPreview = "DEV"`. 这个开关不是装饰: `build-logic/.../android/KotlinAndroid.kt → configureAndroidSdk()` 读它, true 时 `compileSdk` 走 `preview(compileSdkPreview)`, `buildToolsVersion` 换 `buildToolsPreview`, `targetSdk` 走 `preview(targetSdkPreview)` — 误改一次, 整棵树的 SDK 与 build-tools 一起翻到预览版. 不动的理由: [AGENTS.md](../../../../../AGENTS.md) 把 "SDK, build-tools, NDK 只写在 `build.toml`, 带一个 `isPreview` 开关" 记成项目约定, 开关本身是设计; 再加一层守护或注解, 只是把一条约定变成两套机制.
- **`versionCode` / `versionName`**. 两个值只在 `build.toml` (`73`, `1.18.8_unpublished`), 经 `AndroidApplicationConventionPlugin.configureName()` 里的 `buildVersion("versionCode")` / `buildVersion("versionName")` 进 `defaultConfig` — 构建路径上没有第二处取值, 所以 "解除版本硬编码" 这项没有对象. 代码里唯一重复了这两个数字的地方是 `SettingsScreen.kt → SettingsContentPreview()` 的 `@Preview` 样例数据 (`versionName = "1.18.8"`, `versionCode = 73`): 它不参与构建, 发版后它是过期的预览装饰, 不是错误的版本来源.
- **`settings.gradle.kts` 内联的插件版本**. `id("com.gradle.develocity") version "4.5.1"` 与 `id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"` 写在 catalog 之外. 收不进去是加载顺序问题: 五个版本目录文件正是由 `settings.gradle.kts` 的 `versionCatalogs { from(files("gradle/toml/...")) }` 注册的, 而 settings 的 `plugins {}` 必须在 catalog 可用之前解析完 — 先有鸡先有蛋.
