# 51 CI 缺硬化: 并发, 超时, 缓存, JDK 固定, 最小权限

> 返回 [README 索引](../README.md) · [9 · 构建与 CI](../README.md#9--构建与-ci).

**严重程度: P2 | 修复难度: 低**

**影响文件**: `.github/workflows/android-ci.yml`, `.github/workflows/dependency-submission.yml`, `.github/dependabot.yml`

**结论**: 两份 workflow 都缺同一批硬化项, Dependabot 只管依赖不管动作本身.

**证据** (逐条对着文件看):

- **无 `concurrency:` 组** — 两个文件全文没有这个键: 同一分支连续 push 时新旧构建并行排队, 互相抢 runner, 旧构建不会自动取消.
- **无 `timeout-minutes:`** — 两个文件同样没有; 卡死的作业只能由 GitHub 的默认上限兜底, 而不是由本仓库设定.
- **`android-ci.yml` 没有 `setup-java` 步骤, 也没有 Gradle 缓存** — 该步骤 (含 `cache: gradle`) 随 `c5e5ded5` ("Feat: Gradle Daemon JVM criteria") 整段删除. 现在 JDK 25 由 `gradle/gradle-daemon-jvm.properties` 的 `toolchainUrl.*` 现场获取, 那些值是 `api.foojay.io/disco/v3.0/ids/<id>/redirect` 形式的重定向链接: 该服务或其中某个 id 一变, CI 立刻受影响, 且没有任何东西钉住它.
- **`android-ci.yml` 没有顶层 `permissions:`** — `dependency-submission.yml` 有 (`contents: write`), 构建用的 workflow 反而没有, 因此它跑在仓库默认的 `GITHUB_TOKEN` 权限上.
- **`.github/dependabot.yml` 的 `updates` 只列 `package-ecosystem: "gradle"`** — 没有 `github-actions` 生态, 所以 `actions/checkout@v7`, `android-actions/setup-android@v4`, `gradle/actions/dependency-submission@v6` 这三个动作引用永远不会被 Dependabot 提版本.

**修复方向**: 与 [#50](50-CI只编译不测试.md) 合流实施最省 — 门禁一旦把测试与 lint 加进来, 单次作业时长和排队都会上去, `concurrency` 与 `timeout-minutes` 那时不再是可选项. 本条与 [AGENTS.md](../../../../AGENTS.md) 不冲突: 硬化改的是 workflow 的调度, 超时, 缓存与权限, 不动 "CI builds `assembleFossDebug` only" 的任务范围.
