# 55 构建配置杂项

> 返回 [README 索引](../README.md) · [9 · 构建与 CI](../README.md#9--构建与-ci).

**严重程度: P3 | 修复难度: 低 (各项独立)**

每一项都是卫生级, 逐条给位置与现状.

- **空挂的 `fileTree`**: `app/build.gradle.kts → dependencies` 有 `implementation(fileTree("libs") { include("*.jar", "*.aar") })`, `base/build.gradle.kts` 把同一条挂在 `api` 上; 两个模块都没有 `libs/` 目录, 所以两句今天恒为空. `api` 那条还把 "将来往 `libs/` 丢 jar" 变成对下游模块的编译期暴露.
- **无消费者的版本目录条目**: `android.toml` 的 `androidGradlePlugin-beta` (`9.4.1`, 与在用的 `androidGradlePlugin` 同号) 和 `androidGradlePlugin-canary` (`9.5.0-alpha07`) 在 `[versions]` 之外零引用; `compileSdkExtension` 只出现在 `KotlinAndroid.kt → configureAndroidSdk()` 的注释行 (`// sdkExtension = ...`); `kotlin.toml` 的库条目 `compose-gradlePlugin` 只被 `build-logic/convention/build.gradle.kts` 的注释行 (`// compileOnly(libsKotlin.compose.gradlePlugin)`) 提到; `google.toml` 的 `[bundles] firebase = [...]` 没有消费者 — 全仓 `findBundle` 只调过 `"compose"`, `"test"`, `"androidTest"` 三个, Firebase 三件套是逐个 `findLibrary` 挂的.
- **两份 settings 的重复块**: 版本目录注册 (`fun String.toToml()` 加五次 `"...".toToml()`) 与带内容过滤的 `google()` 仓库列表在根 `settings.gradle.kts` 和 `build-logic/settings.gradle.kts` 各写一份, 差别只有 toml 路径前缀 (`gradle/toml/` 与 `../gradle/toml/`). 加一个 catalog 或改过滤规则要记得改两处.
- **`gradle.properties` 的两个裸开关**: `org.gradle.configureondemand=true` 与 `android.debug.obsoleteApi=true` 都没有注释说明为何开启, 文件里看不出这是刻意的.
- **app 资源目录的取值方式**: `app/build.gradle.kts → android → sourceSets → named("main")` 用 `java.directories.toList()[0]` 取 `src/main/java`, 再按 namespace 拼出各 res 目录. 这个 `[0]` 依赖 "main 的 java 源集只有一个目录" 这个前提, 一旦加第二个 java 目录, 拼出来的路径就跟着错.
- **CI 的两处卫生**: `android-actions/setup-android` 步骤传的是空列表 `packages: ''` (cmake 与 NDK 由随后两步 `sdkmanager --install` 单独装); 三个动作引用只钉 major tag (`actions/checkout@v7`, `android-actions/setup-android@v4`, `gradle/actions/dependency-submission@v6`), 上游一次 major 变化就改变 CI 行为.
- **Firebase 插件的任务名匹配**: `AndroidApplicationFirebaseConventionPlugin` 靠 `task.name.startsWith("process$flavorFoss") + endsWith("GoogleServices")` 与 `contains("Crashlytics") + contains(flavorFoss)` 禁用 Foss 的对应任务, 匹配的是命名约定而不是任务类型, AGP 改任务名就静默失配; 每禁一个还 `println("Task $name disabled.")`, 每次配置都打印. 禁用方案本身是有意选择, 见 [#57](../10-权限与合规/57-foss纯度防护.md); 本条只登记 "按名字匹配" 与 "每次配置 println" 这两个实现细节.
- **重复 apply**: `AndroidApplicationNdkVersionConventionPlugin` 与 `AndroidLibraryNdkVersionConventionPlugin` 各自 `apply(plugin = androidPlugin("android-application" / "android-library"))`, 而宿主模块已通过 `lowleveldetector.android.application` / `lowleveldetector.android.library` 应用过同一个插件 (`app/build.gradle.kts` 与 `binderDetector/build.gradle.kts` 的 plugins 块里两条 alias 并存). 净效果取决于 Gradle 对重复 apply 的处理, 这一处至少是冗余调用.
- **release 签名的读取方式**: `app/build.gradle.kts → signingConfigs → register("release")` 读 `file("$rootDir/local.properties")`, 文件不存在就 `return@register` (整段配置为空), 没有环境变量回退; `storeFile = file(keystoreProperties["storeFile"].toString())` 是相对路径取值, 按 **app 模块目录** 解析而不是仓库根. 签名材料放在仓库外是 AGENTS.md 与 `.gitignore` 的约定, 本条只登记这个取值方式.
- **8 个实验性编译器开关**: `KotlinAndroid.kt → configureKotlin()` 给全模块注入 `-Xcontext-sensitive-resolution`, `-Xwhen-expressions=indy`, `-Xreturn-value-checker=full`, `-Xname-based-destructuring=only-syntax`, `-Xexplicit-context-arguments`, `-Xcollection-literals`, `-XIntrinsic-const-evaluation`, `-Xallow-returns-result-of`, 按引入版本分成五组注释. 这是 [AGENTS.md](../../../../AGENTS.md) 记的 **既成集合** — 升 Kotlin 时最容易集体翻车的一处, 但约定就是 "别删, 每次升级重新评审并去掉已稳定的". 知情记录, 不立项.

**不在本条** (AGENTS.md 已记为设计, 别当杂项清): NDK `30.0.16248370` 与 CMake `4.1.2` 在 `build.toml` 和 CI 各写一份, 是 "bump them and CI in lockstep" 的约定; Develocity 的 `publishing.onlyIf { false }` (本地 scan, 永不上传) 同理. 依赖与版本只住在五个 catalog 里, 所以 catalog 内多出没消费者的条目要在这里删, 而不是把坐标搬回模块脚本.
