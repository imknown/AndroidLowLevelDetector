# 44 把资源 ID 当"逻辑值"和"数据"用

> 返回 [README 索引](../README.md) · [8 · 反模式与卫生](../README.md#8--反模式与卫生).

**严重程度: P2 | 修复难度: 低~中 (两处独立, 各自可单独提交)**  
**影响文件: `HomeRepository.kt`, `HomeViewModel.kt`, `SettingsRepository.kt`, `SettingsScreen.kt`**

## 问题核心代码

### 1. 用文案的资源 ID 判断业务分支

字符串资源 ID 被当成枚举做逻辑判别 (`HomeRepository.detectMode()`):

```kotlin
if (lld != null) {
    datetimeFormatted = lld.version.formatToLocalZonedDatetimeString()
    color = if (modeResId == R.string.lld_json_online) {   // ← 用 "文案的编号" 判断业务分支
        StatusColor.NO_PROBLEM
    } else {
        StatusColor.CRITICAL
    }
}
```

`modeResId` 沿调用链传进来: `HomeViewModel.detect(..., @StringRes modeResId: Int)`,  
两个调用点 `HomeViewModel.tryDetectOnline()` 传 `R.string.lld_json_online`,  
`tryDetectOffline()` 传 `R.string.lld_json_offline`. 同一个值随后又被当文案用:  
`MyApplication.getMyString(modeResId, datetimeFormatted)`.

引入该比较与把它参数化的提交:

| 提交 | 日期 | 当时目的 |
|---|---|---|
| `5f8fc45f` Feat: Architecture refactor: Repositories and DataSources | 2021-03-21 | 仓库化重构时引入该比较 |
| `1266cb6f` Feat: Improve exception handling via UDF | 2025-12-03 | 异常处理改造把比较对象参数化成 `modeResId`, 沿调用链传进来 |

### 2. 数据类 `Version` 携带文案 ID

资源 ID 还作为数据跨层传递 (`SettingsRepository.Version`):

```kotlin
data class Version(
    @param:StringRes val id: Int,   // ← 数据类里携带 "用哪条文案" 的界面指令
    val versionName: String,
    ...
)
```

构造处 `SettingsRepository.getBuiltInDataVersion()` 传 `R.string.about_version_summary`; 界面按 `v.id` 取字符串  
(`SettingsScreen` 的 `SettingsContent()` 版本行: `stringResource(v.id, v.versionName, v.versionCode, ...)`),  
预览构造 `SettingsContentPreview()` 也传 `id = R.string.about_version_summary`.

## 直接原因

- `R.string.lld_json_online` 是**文案地址**不是业务语义. 资源重命名, 多模块合并资源 ID 重排,  
  或有人改了文案对应关系, 这段 `if` 会静默改变颜色逻辑, 编译器不会报任何错.
- `Version.id` 让界面层不得不反向持有格式化知识 (按 `v.id` 取字符串),  
  数据类里混入了界面指令: `SettingsScreen` 不看仓库源码就不知道这行套的是哪个模板.

## 根本原因

缺少显式的业务枚举, 资源 ID 因 "顺手可用" 被借作判别值, 也被当成数据跨层传递, "能跑" 和 "语义正确"  
之间隔着一次无声的重构事故.

## 修复方案

### 1. `detectMode` 改收业务枚举 (改动量 ~15 行, 文件 `HomeRepository.kt`, `HomeViewModel.kt`)

```kotlin
// HomeRepository.kt: 业务枚举承载语义, 资源只在拼文案时使用
enum class LldSource { ONLINE, OFFLINE }

fun detectMode(lld: Lld?, errors: List<String?>, source: LldSource): MyModel {
    ...
    color = if (source == LldSource.ONLINE) StatusColor.NO_PROBLEM else StatusColor.CRITICAL
    ...
    return toColoredMyModel(
        R.string.lld_json_mode_title,
        MyApplication.getMyString(
            when (source) {
                LldSource.ONLINE -> R.string.lld_json_online
                LldSource.OFFLINE -> R.string.lld_json_offline
            },
            datetimeFormatted
        ) + result,
        color
    )
}
```

`HomeViewModel.detect()` 的签名 `@StringRes modeResId: Int` 改为 `source: LldSource`; `tryDetectOnline()` 与  
`tryDetectOffline()` 分别传 `LldSource.ONLINE` / `LldSource.OFFLINE`.

### 2. `Version` 去掉 `id` 字段 (改动量 ~10 行, 文件 `SettingsRepository.kt`, `SettingsScreen.kt`)

`Version` 删掉 `id`, 构造处 (`SettingsRepository.getBuiltInDataVersion()`) 删掉 `R.string.about_version_summary`  
实参; 界面自己知道自己该用哪条文案:

```kotlin
// SettingsScreen → SettingsContent() 版本行的 supporting 文案
Text(
    stringResource(
        R.string.about_version_summary,
        v.versionName, v.versionCode, v.assetLldVersion,
        ...   // 其余字段实参不变
    )
)
```

另一处要跟着改的是预览里的 `SettingsContentPreview()` (`id = R.string.about_version_summary`).

## 不算欠账的两处

`MyModel` 里的 `MyModelTitle.Res` 属于 "界面模型携带资源 ID",  
与 [#01](../01-架构与分层/01-无领域模型.md) 的 mapper 方案一致 (mapper 就在 UI 层, 拿资源 ID 是合法的),  
不需要改.  
同一条里的 `color: @AttrRes` 那一半已经在 Compose 迁移里落地成 `StatusColor` 枚举 (`MyModel`, `ExtendedColors.kt`),  
也没有遗留的 `@AttrRes` 需要清.
