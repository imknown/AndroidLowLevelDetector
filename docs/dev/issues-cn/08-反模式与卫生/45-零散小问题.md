## 3. 属性读取的版本门控散落在调用方

原 `getStringProperty()` / `getBooleanProperty()` (`ui/common/PropertyExt.kt`) 与同形状的 `getShellResult()` (`ui/common/ShellExt.kt`) 都有 `condition: Boolean = true` 参数 — 它把 "该属性最低哪个 Android 版本才有" 的知识压给每个调用方. 两文件已分别随 `8b5dc266` / `c87137a2` 删除, 门控模式原样延续: `PropertyReader.getString()` / `getBoolean()` 仍带 `condition` 参数, shell 侧则散在 `HomeRepository` 的 GSI 调用点 (`if (isAtLeastAndroid9()) shell.execute(cmd) else ShellResult()`). `HomeRepository` 里现 14 处活跃调用传的是 `isAtLeastAndroid9()` 这类实参 (另有 7 处同样的调用被注释掉了, 没算进来). 版本门槛应与 key 定义放在一起, 而 key 今天就定义在各功能 DataSource 的伴生对象里 (`ui/home/datasource/AndroidDataSource.kt` 的 `PROP_*`):

```kotlin
// 与 key 同处定义 (AndroidDataSource 里), 门槛不再是调用方的记忆
data class PropKey(val key: String, val since: Int? = null)

val PROP_VENDOR_SECURITY_PATCH = PropKey("ro.vendor.build.security_patch", Build.VERSION_CODES.P)

// 调用方不再记得门槛
val mySecurityPatchVendor = propertyReader.getString(PROP_VENDOR_SECURITY_PATCH)
```

## 5. PropRepository.getBuildProp 的字符串套娃解析

`PropRepository.getBuildProp()` 对 `getprop` 输出做 `[key]: [value]` 字符串往返解析: 按行判断 `startsWith("[") && endsWith("]")` 拼出 `rawProp`, 再交给 `MyModelExt.toPropMyModel()` 用 `split(": ")` 拆开, 两边各做一次 `removeSquareBrackets()`. 属于 "把终端展示格式当数据格式" 的 stringly-typed (用字符串代替结构化数据) 味道. 低优先级: 等 [#01](../01-架构与分层/01-无领域模型.md) 做完, 可在 DataSource 层直接产出 `Pair<String, String>`. 解析本身已经暴露出的健壮性问题 (值里再出现 `": "` 就丢段, 未闭合的续块静默丢) 见 [#27](../05-稳定性与错误处理/27-比较解析杂项.md).

## 6. ShellDefault 零调用 — 有意保留, 不计入欠账

`base/src/main/java/.../base/shell/impl/ShellDefault.kt` 定义后全项目无引用 (实际使用的是 `ui/common/ShellLibSu.kt`). 它不是待删的死代码: AGENTS.md 把它记为**不依赖 libsu 的原生备选实现**, 留仓待用, "当前无人调用" 只是现状. 若将来启用, 先修它的读后死锁 — `execute()` 里 `process.waitFor()` 之后才读 `inputStream` / `errorStream`, 输出大时进程会先堵在管道上.

## 7. 文件存储路径属性名带动词后缀

`LldFileStore.savedLldJsonFileOrThrow` (原 `LldManager` 同名属性, 已随 `6e4e9ebf` 类化搬迁, 名字原样): 属性命名带 `OrThrow` (方法后缀习惯), 读起来像在调用函数. 顺手改为 `val savedJsonFile: File`.

## 8. 版本 / 日期字符串按字典序比较

四处用 `>=` / `<` 直接比较字符串, 正确性完全依赖格式恒定 (`HomeRepository.detectSecurityPatch()` 安全补丁, `detectMainline()` Mainline, `detectVndk()` VNDK, `LldFileStore.copyJsonIfNeededOrThrow()` lld 版本). 零填充的 ISO 日期目前碰巧正确, 但位数一变 (如 `9` 对 `10`) 即静默出错:

```kotlin
mySecurityPatch >= lldSecurityPatch      // "2026-08-05" 字典序比较, 目前靠零填充保平安
savedLldVersion < assetLldVersion        // "2026-09-28 08:25 +0800" 同上
```

`acb604ad` 之后, 在线那份 `version` 进门前已被格式校验 (`HomeViewModel.tryDetectOnline()` 用 `isLldDatetime()`, 格式钉在 `base/.../base/extension/DateTimeExt.kt` 的 `LLD_DATETIME_FORMATTER`, 解析不了的载荷直接降级到内置离线数据), 但 `LldFileStore` 里这条比较本身仍是裸字符串比. 其余同类比较点见 [#27](../05-稳定性与错误处理/27-比较解析杂项.md), Home 行整体比较语义见 [#43](43-比对语义逐行adhoc.md).

版本号统一走 `Version(...)` 比较, 安全补丁解析为 `LocalDate` / `YearMonth` 后比较.

## 9. 标题在组合期解析, 详情在检测期冻结

`MyModelCard` 的标题走 `stringResource(id)` 现解析 (`MyModelTitle.asText()` 那个 `@Composable` 解析 helper, `MyModelCard()` 里 `text = model.title.asText()`), `detail` 却是检测时冻结好的字符串 (`MyModelCard()` 里 `text = model.detail` 直接排版): 系统切换语言后, 同一行会显示 "新语言标题 + 旧语言详情", 直到手动刷新. 原 `MyAdapter.kt` (已随 `a92e163d` 删除) 在 `onBindViewHolder` 里就是每次绑定调 `MyApplication.getMyString(title.id)` 而详情直接 `tvDetail.text = model.detail`, 载体换成了 Composable, 缺陷原样搬了过来. [#01](../01-架构与分层/01-无领域模型.md) 的 mapper 落地之后, 标题与详情统一在数据到位时解析一次, 卡片只读现成字符串.

## 10. Easter egg 计数器放在 ViewModel

`SettingsViewModel.timesLeft` 是可变字段 (`private var timesLeft = 7`) + 返回资源 ID 的查询函数 (`@StringRes fun getVersionClickedMessage(): Int?`) — "连点 7 次版本号" 的交互细节属于界面层, 且查询函数里藏着 `timesLeft--` 副作用. 挪进 `SettingsScreen` (一个 `remember` 计数器即可), 或改为不可变状态流转.

## 11. CompositionLocal 的默认值是静默的常量流

`LocalScrollBarMode` (`MyModelListScreen.kt`) 与 `LocalThemeMode` (`Theme.kt`) 的默认值是**新建的常量 `MutableStateFlow`** (`ScrollBarMode.None` / `AppThemeMode.FollowSystem`), `LocalExtendedColors` 默认 `ExtendedLightColors`; 唯一 provide 点是 `MainActivity` 的 `CompositionLocalProvider`. 任何忘了 provide 的宿主 (新入口, 预览之外的测试宿主) 拿到的是静默默认值, 不报错 — 与 `LocalMetroViewModelFactory` 的 `error(...)` fail-fast 默认相反. 形状记录: 默认值该静默还是 fail-fast, 等出现第二个宿主时再定.

## 12. HomeViewModel 的两个未使用 import

`ui/home/HomeViewModel.kt` import 了 `MountDataSource` 与 `AppInfoDataSource` 但全文件未使用 — DI 重构的残留痕迹, IDE 会告警, 纯删.

## 13. 尺寸与排版体系两页并存

`SettingsScreen` 大量硬编码 dp (`1.5.dp`, `12.dp`, `88.dp` 等), 列表页用 `dimensionResource` 取 `R.dimen.*`; `Type.kt` 的 `AppTypography` 只覆盖 `titleLarge` / `bodyLarge` 两个 slot (为复刻旧 `includeFontPadding` 行为), 设置页用的 `bodyMedium` / `titleSmall` 落回 M3 默认 (无 font padding) — 两页的字体留白行为不一致. 收敛方向 (dimen 资源化, slot 补齐) 等排版整体重调时一并做, 见 [#59](../07-UI与无障碍/59-Expressive主题跟进.md).
