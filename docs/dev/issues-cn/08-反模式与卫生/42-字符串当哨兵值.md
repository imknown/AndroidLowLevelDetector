# 42 本地化字符串被当作"哨兵值", 数据状态藏在翻译文案里

> 返回 [README 索引](../README.md) · [8 · 反模式与卫生](../README.md#8--反模式与卫生).

**严重程度: P1(设计缺陷, 潜伏正确性风险) | 修复难度: 中 (随 #01 渐进)**  
**影响文件: `PropertyReader.kt`, `HomeRepository.kt`, `OthersRepository.kt`, `MyModelExt.kt`**

## 问题核心代码

数据访问函数把 "不支持 / 失败" 就地翻译成本地化**文案**返回 (`PropertyReader.getString()`, 原 `PropertyExt.kt` 顶层函数已随 `8b5dc266` 类化搬迁, 模式原样):

```kotlin
fun getString(key: String, condition: Boolean = true): String {
    val notSupport = application.getString(R.string.result_not_supported)
    return if (condition) {
        try {
            val default = application.getString(R.string.build_not_filled)
            property.getStringOrThrow(key, default)
        } catch (e: Exception) {
            Log.w("getStringProperty", "$key: ${e.fullMessage}")
            notSupport                            // ← 失败被翻译成 UI 文案
        }
    } else {
        notSupport                               // ← "不支持" 也是 UI 文案
    }
}
```

而判定层靠**比较这些文案的内容**来识别状态,  
全项目两处 (`HomeRepository.isPropertyValueNotEmpty()`, `OthersRepository.getPartitionFingerprints()`):

```kotlin
private fun isPropertyValueNotEmpty(result: String) =
    result.isNotEmpty()
        && result != MyApplication.getMyString(R.string.result_not_supported)
        && result != MyApplication.getMyString(R.string.build_not_filled)

// OthersRepository.getPartitionFingerprints, 同一模式第二处:
if (fingerprint != MyApplication.getMyString(R.string.build_not_filled)
    && fingerprint != MyApplication.getMyString(R.string.result_not_supported)
) { ... }
```

生产方不止 `PropertyReader.getString()` 一处: `MyModelExt.toTranslatedDetail()` 在详情为空时也填 `build_not_filled`.  
它只生产哨兵, 不做比较, 所以危害集中在上面那两处判定.

## 直接原因

`PropertyReader.getString` 的返回类型是 `String`, 无法表达 "有值 / 缺失 / 失败" 三种状态, 三种状态被编码进字符串**内容**; 下游只能用 `!=` 对着翻译资源反向猜状态.

## 根本原因

与 [#01](../01-架构与分层/01-无领域模型.md) 同根: 没有结果类型. 字符串内容一旦充当状态载体: 断言必须携带资源上下文 (不可单测); 语义对翻译资源形成依赖.

风险是潜伏的, 不是当前的缺陷: 正常运行中生产方与比较方在同进程同语言取同一资源, 比较成立; 四个语言档目前也把两条文案保持在不同值上:  
`result_not_supported` = "Not supported" / "Non supporté" / "不支持" / "不支援",  
`build_not_filled` = "**NOT FILLED**" / "**NON REMPLI**" / "**未填写**" / "**未填寫**". 一旦某语言把两条译成同一句, 或运行中切了语言,  
`!=` 会悄悄对不上, 把 "不支持" 误判成 "有值".

## 修复方案

数据层返回 "发生了什么", 翻译集中到唯一的展示映射:

```kotlin
// base/.../base/property/PropValue.kt: 状态用类型表达, 与 locale 彻底无关
sealed interface PropValue {
    data class Found(val value: String) : PropValue
    data object Missing : PropValue            // 属性不存在 / 系统版本不支持
    data class Failed(val error: Throwable) : PropValue
}

// 判定逻辑: 模式匹配, 翻译资源不参与
val hasVndk = when (val v = property.string(PROP_VNDK_VERSION)) {
    is PropValue.Found -> v.value.isNotEmpty()
    else -> false
}

// 展示翻译: 全项目唯一知道这些文案的地方
fun PropValue.toDisplayText(): String = when (this) {
    is PropValue.Found -> value
    is PropValue.Missing -> MyApplication.getMyString(R.string.result_not_supported)
    is PropValue.Failed -> MyApplication.getMyString(androidR.string.unknownName)
}
```

属性网关今天是 `:base` 模块的 `base/.../base/property/`  
(`IProperty.kt` 只有 `getStringOrThrow()` / `getBooleanOrThrow()` 两个方法,  
默认实现 `impl/PropertyDefault.kt` 经图的 `PropertyContainer` 绑定;  
原 `PropertyManager.kt` 委托壳已随 `8b5dc266`  
删除); `PropValue` 与返回它的方法加在那里, AGENTS.md 也把 `IProperty` / `IShell` 的抽象钉在 `:base`.

迁移路径: `PropValue` 先在属性网关内部做出来, `PropertyReader.getString()` 保留为薄包装 (内部调 `toDisplayText()`),  
各调用点随 [#01](../01-架构与分层/01-无领域模型.md) 的逐条迁移切换, 避免一口气全量切换. `toDisplayText()` 不能放进 `:base`, 因为  
`result_not_supported` 与 `build_not_filled` 是 `:app` 功能包里的资源 (`ui/home/res`, `ui/others/res`),  
展示映射留在 `:app` 侧.
