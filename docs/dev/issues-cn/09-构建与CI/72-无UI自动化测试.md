# 72 无 UI 自动化测试

> 返回 [README 索引](../README.md) · [9 · 构建与 CI](../README.md#9--构建与-ci).

**严重程度: P3 | 修复难度: 中**

**结论**: 不是缺陷, 是一条测试设施缺口的候选项: 仓库今天没有一行 UI 自动化测试,  
界面验证全部靠每次改动的人工手段. 本条登记 UI 自动化测试为未来要做的活;  
立项时另立 spec, 先定路线再动依赖, 立项前不预写代码.

**证据**:

- 依赖侧: `gradle/toml/android.toml` 的 `[bundles]` 一节里 `androidTest` 组只有 `test-core`,  
  `test-ext-junit`, `test-runner` 三件; 五份 toml 目录里没有 espresso,  
  没有 `androidx.compose.ui:test` 与 `ui-test-junit4`.
- 测试侧: `app/src/androidTest` 下 8 个文件全是仓库层检测测试  
  (`snapshot/ModelSnapshotTest` 加 7 个 `repository/Detect*`), 没有一个界面测试;  
  `app/src/test` 与 `base/src/test` 的 JVM 单测 (JUnit 4 加 Robolectric,  
  `gradle/toml/thirdParty.toml` 的 `robolectric` 条目) 覆盖检测引擎, mapper, repository 与 model,  
  不碰界面.
- CI 侧: [09-构建约定](../../../agents-cn/09-构建约定.md) 的 CI 一节写明 CI 不跑仪器测试, 也不连设备.
- 界面验证今天的三种人工手段: 按需真机目检 ([13-工作流](../../../agents-cn/13-工作流.md) 的 测试与验收 一节),  
  每次修改的黄金快照对照 ([05-项目架构](../../../agents-cn/05-项目架构.md)),  
  review 时的真机 adb 核对 ([15-review 检查表](../../../agents-cn/15-review检查表.md) 的 来源 一节).

**未来候选项**:

- Compose UI Test: compose-ui 1.13.0 起 `ComposeUiTest` 与 `TestFailurePolicy` 等转稳定  
  (核实程度: 调查, 未核; 出处为 Compose 升级 spec 目录  
  `docs/spec/2026-11-28-12-06-31-+0800-compose-bom-2026-11-01-upgrade-cn/2026-11-20-compose-survey-cn/`  
  里各份调查). 两条路线立项时选一条: 仪器化 (真机或模拟器; CI 不连设备, 进不了 CI),  
  或 Robolectric 跑 JVM (CI 可收, 现有 Robolectric 依赖可以直接搭).
- UI Automator: 跨应用与系统级自动化; 单应用内的界面测试 Compose UI Test 就能覆盖,  
  本应用要不要它, 立项时评估.

**处理**: 保持现状. 触发时机: 界面复杂度上来  
(例如 [59-Expressive 主题跟进](../07-UI与无障碍/59-Expressive主题跟进.md) 与  
[37-滚动条可拖动是stub](../07-UI与无障碍/37-滚动条可拖动是stub.md) 实施之后),  
或某次改动的真机目检开始漏东西.
