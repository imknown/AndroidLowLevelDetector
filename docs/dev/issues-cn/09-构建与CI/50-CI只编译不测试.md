# 50 CI 只编译, 不跑测试和 lint

> 返回 [README 索引](../README.md) · [9 · 构建与 CI](../README.md#9--构建与-ci).

**严重程度: P1 | 修复难度: 低 (立门禁)**

**影响文件**: `.github/workflows/android-ci.yml`, `app/src/test/`, `app/src/androidTest/`, `base/src/test/`

## 问题核心代码

CI 只有一个构建步骤 (`.github/workflows/android-ci.yml`):

```yaml
    # region [Gradle]
    - name: Build with Gradle
      run: ./gradlew assembleFossDebug        # ← 只编译, 不跑 test, 不跑 lint
    # endregion [Gradle]
```

测试源集的分布 (逐目录看, 不是 "一个测试都没有"):

| 位置 | 内容 |
|---|---|
| `base/src/test/.../base/extension/DateTimeExtTest.kt` | 4 个真实测试方法: lld 日期格式的正例, 四类偏离格式的反例, 同 offset 的格式化往返, US / ar locale 下解析一致 |
| `base/src/test/.../base/ExampleUnitTest.kt` | 模板 (`assertEquals(4, 2 + 2)`) |
| `app/src/test/.../ExampleUnitTest.kt` | 同上, 模板 |
| `app/src/androidTest/`, `base/src/androidTest/` | 各一个模板 `ExampleInstrumentedTest` |
| `binderDetector`, `build-logic` | 无测试源集 |

`DateTimeExtTest` 是 `b876b922` 为 `lld.json` 的 `version` 字段补的契约测试,  
锁的是 `base/.../extension/DateTimeExt.kt` 里固定 `Locale.US` 的 `LLD_DATETIME_FORMATTER` 与 `isLldDatetime()`,  
[README 的 "已经做对的地方"](../README.md#已经做对的地方) 一节把它记成了机器可查契约. 缺的不是测试本身, 而是 **没有任何东西会去跑它**: 该测试只在本地执行,  
把它写坏不会让 CI 变红.

收窄点可查: CI 的 Gradle 步骤起初写的是 `./gradlew build`,  
`a8d7909d` ("Update android.yml", 2025-05-29) 把它改成 `./gradlew assembleFossDebug`; 此后 CI 再没跑过别的任务,  
后续 "Chore: Update CI / Update dependencies" 只动 SDK/NDK 与动作版本 (`db802d3c`, `d0cd8101`, `a16a93c8`,  
`b62e1a49`).

## 直接原因

门禁链条断在第一环: CI 不执行 `test` / `lint` 任务, 即使有人写了测试也不会在合入前运行.

## 根本原因

"能编译 = 没问题" 的默认假设. [README 的修复路线](../README.md#修复路线) 上全是行为等价重构, 没有回归保护网时只能靠手工真机验证:  
[#01](../01-架构与分层/01-无领域模型.md) (领域模型化), [#09](../02-SSOT-唯一数据来源/09-myAndroid可变单例.md) (冻结全局状态),  
[#11](../03-UDF-单向数据流/11-HomeViewModel手工编排.md) (编排归位), [#30](../06-性能/30-Prop页逐key查询.md) (全表 query) 都在那条线上,  
改动意愿和信心会被消磨掉.

## 修复方案

约定变更已批: 负责人已确认 CI 扩跑 test + lint;  
[AGENTS.md](../../../../AGENTS.md) 的 "CI builds `assembleFossDebug` only" 条款随本条目落地同批改写.

门禁本身是一行:

```yaml
    - name: Build with Gradle
      run: ./gradlew assembleFossDebug testFossDebugUnitTest :base:testDebugUnitTest lintFossDebug
```

落地细节:

- flavor 只在 `app` 生成 (`AndroidApplicationFlavorsConventionPlugin` 是唯一的 `configureFlavors()` 调用点),  
  `base` 无 flavor, 它的单元测试任务是 `:base:testDebugUnitTest`, 得单列一条,  
  否则 `testFossDebugUnitTest` 不会跑到 `DateTimeExtTest`;
- 一条命令里前一个任务失败即停; 想测试挂了也把 lint 跑完, 加 `--continue`;
- 首跑之前先各跑一遍: 存量测试或 lint 只要有 error, CI 首跑就会变红, 需要先清掉, 或在动手前和负责人确认能不能带着红起步, 门禁一直推后的原因就记在这里;
- 静态分析工具 detekt / ktlint / spotless 在全仓零出现, `lintFossDebug` 先把 AGP 自带的官方检查跑起来, 要更严再引入 detekt.

值得续写的下一批测试 (不等 #01, 抽纯函数即可测): `toPropMyModel()` 的 getprop 行解析 (`ui/base/list/MyModelExt.kt`),  
`MountDataSource` 的 `/proc/mounts` 行解析, `Lld` 反序列化的 `ignoreUnknownKeys` 行为 (`ui/common/JsonExt.kt`),  
以及 `MyModel.key` 的同 key 判定 (崩溃链见 [#20](../archived/05-稳定性与错误处理/20-列表key重复崩溃.md)).  
[#01](../01-架构与分层/01-无领域模型.md) 做完之后, 领域判断才能整体纳入单测, 测试铺开不再靠抽纯函数.
