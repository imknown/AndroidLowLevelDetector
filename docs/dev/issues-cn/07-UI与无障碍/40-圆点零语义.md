# 40 · 状态圆点是纯颜色编码, 圆点自身零语义

> 返回 [README 索引](../README.md) · [7 · UI 与无障碍](../README.md#7--ui-与无障碍).

**严重程度: P3 | 修复难度: 低**

**现象**: 每张卡片右上角的状态圆点 (正常=绿 / 警告=黄 / 异常=红) 是判定结果的视觉信号, 但它只是一块带背景色的圆 — 没有 `contentDescription`, 没有 `stateDescription`, 没有任何语义节点. 焦点落在卡片上时, 圆点这一路传达不了信息.

不必夸大到 "整行读不到": 详情文案本身带着 支持 / 未识别 这类词 (如 `R.string.result_supported`, `R.string.result_compliant`, `androidR.string.unknownName`), 标题与详情照常读出. 缺的是 **判定色没有非视觉对应** — 颜色说了 "异常", 而读屏侧那一句话都不说. 具体念成什么要真机 + TalkBack 核对, 本条不下断言.

**直接原因**: 圆点是纯绘制的 `Box` — `clip(CircleShape).background(...)`, 不产生语义节点.

**根本原因**: 从旧 `my_view_holder.xml` 的 `ShapeableImageView` (`@+id/sivColor`) 1:1 搬来, 旧实现同样没有 `contentDescription` (原文件已随 `a92e163d` 删除) — 所以这是**继承至今的缺口, 不是迁移改出来的**. 它与 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md) 是同一个主题 "状态不能只靠颜色表达": #33 管普通用户把红色误读成失败, 这条管读屏用户从颜色这一路什么也拿不到. 迁移把行模型收成了 `StatusColor` 枚举 (`MyModel.color`), 补语义因此不需要新数据.

**问题代码**:

```kotlin
// MyModelCard.kt → MyModelCard() 的状态圆点
if (model.color != StatusColor.NONE) {
    Box(
        modifier = Modifier
            .align(Alignment.TopEnd)
            .size(with(LocalDensity.current) { MyModelColorDotSize.toDp() })
            .clip(CircleShape)
            .background(LocalExtendedColors.current.of(model.color)),   // ← 纯颜色, 零语义
    )
}
```

**影响面**: 圆点只在带状态色的行上出现, 而状态色只由 Home 的检测器给出 — `StatusColor` 在 `OthersRepository` 与 `PropRepository` 零出现, 那两个页面上唯一带色的行是 `toErrorMyModel()` 的失败行 (CRITICAL). `MyModelCard()` 的唯一调用点是 `MyModelListScreen()` 的 `LazyColumn` item (另有本文件的 `@Preview`). 所以范围是 Home 全部带色行 + 各页的错误行.

**修改方案**: 颜色不动, 给圆点补一条语义描述:

```kotlin
.semantics {
    contentDescription = when (model.color) {
        StatusColor.NO_PROBLEM -> dotNoProblem    // 新增状态词资源 (四语): "正常"
        StatusColor.WARNING -> dotWarning
        StatusColor.CRITICAL -> dotCritical
    }
}
```

三个分支就够 — `StatusColor.NONE` 走不到: `MyModelCard()` 在 `model.color == StatusColor.NONE` 时根本不组合这个 `Box` (conditional composition, 代码注释写明). 原来的四分支写法里那条 `NONE -> ""` 是死支.

成本: 新增 3 条 string 资源 (默认英文 + `zh-rCN` + `zh-rTW` + `fr-rFR` 三份翻译, 见 [AGENTS.md](../../../../AGENTS.md) 的 Localization 一节). 若与 [#33](../archived/07-UI与无障碍/33-Unknown渲染红色.md) 的三态映射同批落地, "未知" 一词顺带就有了, 状态词资源只加一次.

实现时注意与 [#34](34-Card空点击.md) 的相互影响: 圆点自己不是焦点目标, 它的描述要经 `mergeDescendants` 归并进卡片节点; 而 #34 记录的出路之一 `clearAndSetSemantics {}` 按该 API 的语义会把子节点的语义一并清掉. 两条同批处理时要先定顺序, 别一边补一边清.

顺带同类的零成本补齐: `SettingsCategoryHeader()` 现在只是一个 `Text`, 可以加 `semantics { heading() }`.
