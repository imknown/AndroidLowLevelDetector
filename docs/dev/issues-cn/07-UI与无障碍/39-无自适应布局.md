# 39 无 NavigationRail / 自适应布局

> 返回 [README 索引](../README.md) · [7 · UI 与无障碍](../README.md#7--ui-与无障碍).

**严重程度: P2(🟡) | 修复难度: 中~难**

代码事实, 逐项核实 (源码, 依赖与资源目录均为零命中):

- 没有 `NavigationRail`, 没有 `WindowSizeClass`, 没有 `NavigationSuiteScaffold`, 全仓源码 grep 零命中.
- 依赖侧没有 material3-adaptive 与 window-* 条目: `gradle/toml/android.toml` 的 compose bundle 只列 `compose-ui`,  
  `compose-ui-graphics`, `compose-ui-tooling-preview`, `compose-material3`, `activity-compose`,  
  两个 lifecycle 条目与三个 navigation3 条目.
- 没有限定布局资源: `app/src` 下 `res` 的子目录只有 `drawable`, `values`, `values-zh-rCN`, `values-zh-rTW`, `values-fr-rFR`,  
  没有 `layout-*`, 没有 `values-land`, 没有 `sw600dp`.
- `AppRootShell()` 是单一手机布局: 一个 `Scaffold`, `topBar` 是 `TopAppBar`, `bottomBar` 是固定 `NavigationBar` (四个标签),  
  内容区由 `innerPadding` 避让. 平板与折叠屏拿到的仍是竖屏手机壳.

**这条怎么定性**: 它是一件从未构建的功能, 不是回归. 已裁要做; 与 [#38](38-工具栏不随滚动隐藏.md) 是同一批栏位行为, 一起做省一次接线.

**方向 (已采纳)**: 用 `WindowSizeClass` 分档, 中等与展开宽度把底栏换成 `NavigationRail`, 紧凑宽度维持现状.  
这意味着 `AppRootShell()` 从 "一个 Scaffold" 变成 "按宽度档选外壳", 而 `AppRoot()` 的每条标签各自一条 `NavBackStack` 的结构不用动.
