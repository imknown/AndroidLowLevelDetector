# AGP 10.0 的存在性核查与官方 roadmap

> **状态**: **frozen**. 写下的结论不改; 后来的更正留在原处.
> 9.1 到 9.6 在 [01](01-agp-9-1-to-9-6.md) 与 [02](02-agp-compatibility-kgp.md),  
> 仓库对照判定在 [04](04-repo-check.md).

本篇的事实一律是转述未核, 出处列在文末. 数据基准日: 2026-11-04.

## 存在性: 截至 2026-11-04 没有任何 10.0 构建产物

| 核查点 | 结果 |
|---|---|
| Google Maven `com.android.tools.build:gradle` 的 maven-metadata.xml | `<latest>` 与 `<release>` 都是 9.6.0-alpha02, `lastUpdated` 2026-10-28; 全量版本从 3.0.0-alpha1 排到 9.6.0-alpha02, 没有 10.x |
| 官方 10.0 release notes 页 | https://developer.android.com/build/releases/agp-10-0-0-release-notes 返回 404 |
| android/skills 仓库的升级 skill | 只有 `agp-9-upgrade`, 没有 agp-10-upgrade |
| 当前 canary 归属 | Studio Rabbit 3 Canary 1/2 的官方博客帖子写捆绑 AGP 9.6.0-alpha01 / alpha02 |

结论: AGP 10.0 目前只存在于官方计划文档, 连 alpha01 都没上 Maven.

## roadmap: 官方对 10.0 的定位

唯一权威来源是官方 "Android Gradle Plugin DSL/API migration timeline"  
(页尾 Last updated 2026-07-22), AGP 10.0 章节:

- 定位 "AGP 10.0 (late 2026)", 完成向 fully lazy, 兼容 configuration cache  
  的构建模型转型, 让 AGP 能完整支持 Gradle Configuration Cache 与 Project Isolation.  
  官方措辞是 "fully support", 没有说强制开启 configuration cache.
- 官方声明时间表是估算, 可能变动. AGP 9.0 release notes 更早写的是  
  "removed in AGP 10.0 (mid-2026)", 两个官方页面的口径从 mid-2026 滑到了 late 2026.

## 移除清单 (roadmap 表格的归纳)

| 移除项 | 替代 |
|---|---|
| 旧 Variant API 全套 (`applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants`) | `androidComponents.onVariants()` |
| `variantFilter` 块 | `androidComponents.beforeVariants()` 加 variant selector |
| 直接任务访问 (`getJavaCompile()`, `getMergeResourcesProvider()`, `getAssembleProvider()`) | Artifacts API (`variant.artifacts`) |
| 急切源集注册 (`registerJavaGeneratingTask()`, `registerResGeneratingTask()`) | Sources API (`variant.sources.java.addGeneratedSourceDirectory(...)`) |
| classpath 访问 (`getCompileConfiguration()`, `getCompileClasspath()`) | Instrumentation API (`variant.instrumentation.transformClassesWith(...)` 加 `AsmClassVisitorFactory`) |
| 急切属性写入 (`buildConfigField()`, `resValue()`) | 惰性 `MapProperty`: `variant.buildConfigFields.put(...)` 与 `variant.manifestPlaceholders.put(...)` |
| 退路旗标 `android.newDsl` 与 `android.builtInKotlin` (含 `android.newDsl.optOut`) | 无直接替代; 现代 DSL 与内置 Kotlin 变为强制 |
| SDK 组件访问 (`sdkDirectory`, `ndkDirectory`, `bootClasspath`, `adbExecutable`) | `androidComponents.sdkComponents` |
| 自定义测试环境 (`deviceProvider`, `testServer`) | Gradle-managed devices |
| Transform API (`com.android.build.api.transform` 整包) | Artifacts API 加 `AsmClassVisitorFactory`; 该整包早在 AGP 8.0 已移除, 10.0 是对旧引用面的收尾表述 |
| 一组无替代的过时注册 API (如 `registerArtifactType`) | 直接删除 |

## (Tentative) 私有内部类访问移除

roadmap 里有一条标注 "Tentative": `com.android.tools.build:gradle` 构件将隐藏全部内部类,  
编译期只暴露 `gradle-api` 里的接口, 且无法通过手动加依赖绕过.  
官方 tracking issue: https://issuetracker.google.com/219002669

## Gradle, JDK, Studio 最低要求: 官方未公布

roadmap 的 10.0 章节完全没提 10.0 要求的 Gradle, JDK 或 Studio 版本, 因为还没有实际构建产物.  
可参考的锚点:

- AGP 版本政策: 一年一个大版本, 每个 AGP major 要求升级一个 Gradle major.
- AGP 9.0 (上一个 major) 最低 Gradle 9.1.0, JDK 17.
- Gradle 官方文档说 configuration cache 将在 Gradle 10 默认开启.

按既定模式推断 (非官方声明): AGP 10.0 大概率要求 Gradle 10.x.  
JDK 最低要求再抬升没有官方信号. 按发布节奏推断 (非官方声明):  
参照 AGP 9.0 stable 于 2026 年 1 月发布, 10.0 stable 大概率滑向 2027 年初.

## 官方迁移步骤 (roadmap 内嵌的五条)

1. 先跑 AGP Upgrade Assistant.
1. 用 Android Studio 的 Agent Mode 升级 skill (android/skills 仓库; 目前只有 agp-9-upgrade).
1. 先在 AGP 9.x 上清完所有 deprecation 警告, 做到不依赖 `android.newDsl=false` 与  
   `android.builtInKotlin=false`, 即可平滑迁 10.0.
1. 审计第三方 Gradle 插件; 仍依赖旧 extension 类型的插件会报  
   `ClassCastException: ... cannot be cast to class BaseExtension`.
1. 参考 https://github.com/android/gradle-recipes 官方迁移配方.

不用等 10.0 就能在 9.x 上预演 10.0 行为: 在 `gradle.properties` 显式设  
`android.newDsl=true` 与 `android.builtInKotlin=true`.  
迁移堵点先查 AGP 10.0 Variant API 总 tracking issue:  
https://issuetracker.google.com/532056644
