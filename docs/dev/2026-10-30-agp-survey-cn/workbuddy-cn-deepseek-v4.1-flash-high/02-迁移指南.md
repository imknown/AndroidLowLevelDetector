# 02-迁移指南

> **状态**: **frozen**. 抄的是官方发布说明和迁移时间表, 2026-10-30 查到的状态.

## 9.0 改了什么

- `android` 块只实现新的 DSL 接口. 旧的 `BaseExtension` 这类类型藏起来, 旧变体 API 也一起没了. 要拿回旧接口, 得在 `gradle.properties` 里显式退让.
- 内置 Kotlin 默认打开. 不再应用 `org.jetbrains.kotlin.android`; `kotlinOptions {}` 换成 `compilerOptions {}`; `kotlin.sourceSets {}` 换成 `android.sourceSets` 里的 `kotlin` 目录. 用 kapt 的换 `com.android.legacy-kapt`, 或者改用 KSP.
- AGP 在运行时依赖 KGP, 我们不再声明 KGP 版本. 要抬高, 在顶层构建文件的 `buildscript` 里加 `classpath("org.jetbrains.kotlin:kotlin-gradle-plugin:<版本>")`. 要降低, 只能在关掉内置 Kotlin 之后用 `strictly`.
- 第三方插件跟不跟得上, 看它有没有还在用旧类型. 撞上的报错长这样: `ClassCastException: ... cannot be cast to class com.android.build.gradle.internal.dsl.BaseExtension`.
- 几处默认值翻了: `targetSdk` 没写时取 `compileSdk`, 不再取 `minSdk`; `resValues` 和 `shaders` 两个构建特性默认关; 资源缩减固定跟着 R8 跑, 旧的实现被删掉.

## 9.x 里能用的过渡手段

| 手段 | 写在哪 | 从哪一版起 | 作用 |
|---|---|---|---|
| `android.newDsl=false` | `gradle.properties` | 9.0 | 恢复旧 DSL 和旧变体 API |
| `android.builtInKotlin=false` | `gradle.properties` | 9.0 | 关掉内置 Kotlin. 必须同时关 `newDsl`, 因为 `kotlin-android` 插件跟新 DSL 不兼容 |
| `android.newDsl.optOut=:模块` | `gradle.properties` | 9.4.0-alpha04 | 只让点名的模块退让 |
| `android { enableKotlin = false }` | 模块构建文件 | 9.0 | 对没有 Kotlin 源码的模块关掉编译器任务, 顺带去掉对 Kotlin 标准库的依赖 |

三个开关都是 9.x 里的东西, 10.0 会连 `android.newDsl` 和 `android.builtInKotlin` 一起删掉.

## 想提前按 10.0 的规矩跑

在 `gradle.properties` 显式写这两行, 9.x 上就会按 10.0 的严格要求执行:

```
android.newDsl=true
android.builtInKotlin=true
```

两步都做到之后, 构建没有弃用警告, 也没靠过任何退让开关, 升 10.0 就只剩第三方插件的问题.

## 10.0 删什么, 换成什么

| 10.0 删掉的 | 替代 |
|---|---|
| `getJavaCompile()`, `getMergeResourcesProvider()`, `getAssembleProvider()` | Artifacts API, 用 `variant.artifacts` 改传过去的文件 |
| `registerJavaGeneratingTask()`, `registerResGeneratingTask()` | `variant.sources.java.addGeneratedSourceDirectory(...)` |
| `getCompileConfiguration()`, `getCompileClasspath()` | `variant.instrumentation.transformClassesWith(...)` 配 `AsmClassVisitorFactory` |
| `buildConfigField()`, `resValue()` | `variant.buildConfigFields.put(...)`, `variant.manifestPlaceholders.put(...)` |
| `applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants` | `androidComponents.onVariants()` |
| `variantFilter` 块 | `androidComponents.beforeVariants()` 配选择器 |
| `sdkDirectory`, `ndkDirectory`, `bootClasspath`, `adbExecutable` | `androidComponents.sdkComponents` |
| `deviceProvider`, `testServer` | Gradle 管理的设备 |
| `registerArtifactType`, `registerBuildTypeSourceProvider`, `registerProductFlavorSourceProvider`, `registerJavaArtifact`, `registerMultiFlavorSourceProvider`, `wrapJavaSourceSet` | 没有直接替代 |
| Transform API | Artifacts API 配 `AsmClassVisitorFactory` |
| `android.newDsl`, `android.builtInKotlin` | 两个开关删掉, 没有替代 |

还有一条在时间表的另一节里, 标着暂定: 10.0 计划把 `gradle` 工件里的内部类藏起来, 编译期只给 `gradle-api` 里的接口和类.
自己写插件时依赖 `com.android.tools.build:gradle-api`, 别依赖 `com.android.tools.build:gradle`.

官方的升级顺序是: 先升到最新的 9.x, 把弃用警告清干净, 确认没靠两个退让开关, 再上 10.0.
