# 03-仓库核对

> **状态**: **frozen**. 核的是 2026-10-30 当天仓库的写法, 证据是文件加行号.

## 三条 AGP 版本 key 的分工

`gradle/toml/android.toml` 里存着三个 AGP 版本:

- `androidGradlePlugin` 是生产用的稳定线.
- `androidGradlePlugin-beta` 和 `androidGradlePlugin-canary` 跟 Android Studio 测试版自带的 AGP 走, 用来临时试, 不参与常规构建. 前者的值现在和稳定线相同, 后者指向 9.6 的 alpha.
- `build.toml` 里的 `isPreview` 只切 Android SDK 那几个值 (`compileSdkPreview`, `targetSdkPreview`, `buildToolsPreview`), 不切 AGP.

## 逐条核对

| 要求 | 仓库现状 | 判定 |
|---|---|---|
| AGP 落在 9.1 到 9.5 区间 | `gradle/toml/android.toml` 的 `androidGradlePlugin` 钉在 9.5 这条线上, 正好是区间右端 | 满足 |
| Gradle 门槛 9.6.0, 9.6 线要 9.7.1 | `gradle/wrapper/gradle-wrapper.properties` 的版本高于这两个门槛 | 满足 |
| JDK 门槛 17 | `gradle/toml/build.toml` 的 `javaToolchain` 高于 17 | 满足 |
| Build Tools 门槛 36.0.0 | `build.toml` 的 `buildTools` 高于 36.0.0 | 满足 |
| 最高 API 37 | `build.toml` 的 `compileSdk` 配了 minor 版本, 实测构建不报不支持 | 满足 |
| NDK 无门槛 | `build.toml` 的 `ndk` 自己钉了版本, 不取 AGP 默认值 | 满足 |
| KGP 不低于 2.2.10 | `gradle/toml/kotlin.toml` 的 `kotlin` 经顶层 `build.gradle.kts` 的 `buildscript` 抬上去, 正是官方写的升级写法 | 满足 |
| 用新 DSL | `KotlinAndroid.kt:31` 起用 `compileSdk { release(...) { minorApiLevel } }`, `KotlinAndroid.kt:18` 的 `CommonExtension` 不带类型参数 | 满足 |
| 内置 Kotlin | 没有任何模块应用 `org.jetbrains.kotlin.android`, `gradle.properties` 也没有关掉内置 Kotlin 的开关 | 满足 |
| 不用旧变体 API | 全仓没有 `applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants`, `variantFilter`, `registerTransform` | 满足 |
| 不用旧 Kotlin DSL | 全仓没有 `kotlinOptions`, 没有 `kotlin.sourceSets` | 满足 |
| R8 保留规则能扛住 9.0 与 9.2 的收紧 | `app/build.gradle.kts:93` 起只用 `proguard-android-optimize.txt`; 三个 `.pro` 都在 (app 的两个, base 的 `consumer-rules.pro`); 内容是模板, 没有 `-keepattributes` 通配符, 也没有 `-dontoptimize` | 满足 |
| 库模块包名唯一 | `app/build.gradle.kts:22`, `base/build.gradle.kts:6`, `binderDetector/build.gradle.kts:9` 三个 `namespace` 各不相同 | 满足 |
| 插件只依赖 `gradle-api` | `build-logic/convention/build.gradle.kts:16` 用 `compileOnly` 依赖 `gradle-api`, build-logic 里所有 AGP import 都是 `com.android.build.api.dsl.*` | 满足 |
| 10.0 的移除清单 | `AndroidApplicationConventionPlugin.kt:44` 用了 `buildConfigField` | 会坏, 只有这一处 |

## 实测

两条命令, 都在仓库根跑:

1. `./gradlew assembleFossDebug --dry-run --no-configuration-cache` 成功, 三个模块全部配置通过.
   输出里只有一条告警: `android.enableBuildConfigAsBytecode=true` 是实验开关, 当前默认是关.
   没有弃用告警, 也没有陈旧 API 告警, 尽管 `gradle.properties` 开着 `android.debug.obsoleteApi`.
1. `./gradlew :build-logic:convention:compileKotlin --rerun-tasks` 成功, 零警告.
   也就是说 build-logic 里那套 DSL 在 9.5 的 `gradle-api` 上没有踩到一条弃用标记.

## 两条不会坏, 但值得知道的

- 9.1 起 R8 默认重打包到无名包. release 构建的类名形状会变, `mapping.txt` 照旧能还原堆栈.
- 9.0 起 `android.dependency.useConstraints` 默认是 false, 依赖约束只加在 androidTest 里. 仓库没用依赖约束, 不受影响.

## 到 10.0 之前

1. 在 `gradle.properties` 显式写 `android.newDsl=true` 和 `android.builtInKotlin=true`. 现在靠默认值, 写上等于提前按 10.0 的规矩跑.
1. 把 `buildConfigField` 换成 `variant.buildConfigFields.put(...)`. 位置要跟着从 `defaultConfig` 挪到 `androidComponents.onVariants` 里.
1. 第三方插件 (Crashlytics, Google Services, Metro) 得等它们出兼容 10.0 的版本, 这一步仓库这边做不了.

## 可选, 不采用也不算违规

- 9.3 的 `optimization {}` 块替掉 `isMinifyEnabled` 加 `isShrinkResources`; `src/<variant>/keepRules/` 源集替掉 `proguardFiles`.
- 9.3 的 `:app:analyzeReleaseR8Config`, 用来审 libsu, Metro, Firebase 带进来的保留规则, 不用等整个 release 跑完.
- 9.5 的备份恢复测试, 9.6 的设备上覆盖率. 两个都还要开实验开关.
