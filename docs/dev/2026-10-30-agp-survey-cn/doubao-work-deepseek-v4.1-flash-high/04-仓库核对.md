## 构建实测: 先撞上 PATH, 补上后通过

头两次 `./gradlew help` 都失败在 configuration cache 存盘阶段, 报一条 problem:

```
Failed to compute value with custom source 'org.gradle.api.internal.provider.sources.process.ProcessOutputValueSource' (output of the external process 'git')
```

底层是 `CreateProcess error=2, 系统找不到指定的文件`. 原因是 agent 这个 shell 进程的环境变量 PATH 里没有 Git 的目录,  
在这个 shell 里 `Get-Command git` 取不到位置; 换成用户自己的 PowerShell 窗口, 同一个命令返回 `D:\App\Git\cmd\git.exe`,  
说明 Git 装着, 只是这个 shell 没继承到那条 PATH.

## 修正之后的结果

把 Git 的 `cmd` 目录临时补进这次进程的 PATH 后 (只影响这一次子进程, 没改系统环境变量), 重跑都通过:

| 命令 | 结果 |
|---|---|
| `git --version` | git version 2.56.1.windows.1 |
| `./gradlew help` | BUILD SUCCESSFUL in 6s, 写到 `Configuration cache entry stored`, 无 problem |
| `./gradlew :app:compileFossDebugKotlin` | BUILD SUCCESSFUL in 12s, 48 个任务, 四个 ABI 的 CMake 都构建, 配置缓存写入 |

两次成功构建的日志里只有三类噪音: parallel configuration cache 与 configuration on demand 的 incubating 提示,  
type-safe accessors 的 incubating 提示, 以及 `android.enableBuildConfigAsBytecode` 的 experimental 警告. 没有弃用条目.

顺手记一条小坑: `:app:compileDebugKotlin` 这个任务名在 app 里不唯一, 有 Foss 与 Firebase 两套变体,  
直接跑会报 `Ambiguous task name`, 得写全 `:app:compileFossDebugKotlin`.

## 判定总结

- AGP 侧: 在 9.5 线最新 patch 上, 这个 patch 真实存在, 官方没有公开它的已知问题.  
  两条修复里, 工程依赖那条正好是仓库在用的写法, 它在 9.5 线出现过问题, patch 之后才干净.
- Gradle 侧: 在 9.9 线最新 patch 上, 这一版修了四个高危安全问题, 还把 9.9.0 公布的两条已知问题一起清掉.  
  这一版没有查到已知问题.
- 组合侧: AGP 9.5.2, Gradle 9.9.2, KGP 2.5.0-RC, JDK 25, compileSdk 37.2 这一套, 配置与 Foss debug 的 Kotlin 编译都跑通了,  
  配置缓存写得进, 日志里没有弃用提示. 功能上没问题, 但官方测试范围不覆盖这几个组合, 以后出问题只能自己扛.
- 那两次失败与版本无关: agent 的 shell 没继承到 Git 的 PATH. 用户自己的终端, 以及 Android Studio, 都不受影响.
