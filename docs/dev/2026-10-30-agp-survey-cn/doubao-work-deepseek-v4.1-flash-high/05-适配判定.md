# 9.x 与 10.0 的适配判定

> **状态**: **frozen**. 写下的结论不改; 后来的更正留在原处.  
> 上游版本与兼容要求在 [01](01-agp-9-5-2.md), [02](02-gradle-版本线.md), [03](03-gradle-兼容要求.md); 仓库取值在 [04](04-仓库核对.md).

判定日: 2026-11-25. 本篇的证据只有两类, 官方文档与本仓库当场跑的构建或 grep.

## 判定表

| 范围 | 要不要改 | 依据 |
|---|---|---|
| AGP 9.1 到 9.5 (已发布线, 仓库正在用) | 不要 | 全量 debug 构建通过, 零弃用警告; 9.5 线的两处回归已由 9.5.2 修掉 |
| Gradle 9.0 到 9.9 (已发布线, 仓库正在用) | 不要 | 同上; 配置缓存写入成功; `warning.mode=all` 下没有弃用条目 |
| AGP 10.0 (未发布) | 一处必改 | 移除清单里的急切属性写入: `buildConfigField()` 换惰性 `MapProperty`, 仓库命中一处 |
| AGP 10.0 | 一处待观察 | `configureondemand` 与并行配置缓存同时开着; 不在移除清单, 但 Project Isolation 要完整支持, 这个开关留不留没有官方结论 |
| AGP 10.0 | 一处靠外部 | 第三方插件审计: 仍碰旧扩展类型的插件会以 `ClassCastException` 挂掉, 仓库这边做不了 |
| Gradle 10.0 (未发布) | 不要 | 四条计划变化 (配置缓存默认开, 软件模型移除, 父工程隐式查找移除, 未声明输入的 Transform 转错误) 仓库都不涉及 |

一句话: **9.x 线内没有要适配的; 10.0 到来前有一处必改, 两处要盯着.**

## 9.x 线为什么不用动

1. 门槛全部满足: AGP 9.5 要 Gradle 9.6.0, JDK 17, Build Tools 36.0.0; 仓库三项都高过门槛, 明细见 [04](04-仓库核对.md).
1. 新写法已经就位: 全仓库没有 `applicationVariants`, `libraryVariants`, `variantFilter`, `BaseExtension`,  
   没有 `kotlinOptions`, 没有 `org.jetbrains.kotlin.android`; `gradle.properties` 里也没有 `android.newDsl`  
   与 `android.builtInKotlin` 这两个退路开关, 等于一直跑在 9.x 的默认严格模式上.
1. 实测干净: `./gradlew :app:assembleFossDebug` BUILD SUCCESSFUL, 93 个任务, 配置缓存写入,  
   日志里只有 incubating 提示和一条 `android.enableBuildConfigAsBytecode` 的 experimental 警告, 零弃用.  
   仓库开着 `org.gradle.warning.mode=all` 与 `android.debug.obsoleteApi=true`, 这两个开关下都没有弃用条目,  
   说明没有踩到 9.x 的陈旧 API.
1. 9.x 那几条会伤到人的变更都不命中, 这一条在本仓库当场核过:  
   `Class.forName` 全仓三处, 目标分别是 `android.os.SystemProperties` 与 `android.webkit.WebViewUpdateService`,  
   `android.webkit.WebViewProviderInfo`, 没有一处指向本仓库的类;  
   `app/proguard-firebase-rules.pro` 第 4 行写的是显式属性名 `SourceFile,LineNumberTable`;  
   全仓没有 `ServiceLoader`, 没有 `dynamicFeatures`, 也没有 `-dontrepackage`.

## 10.0 前唯一必改的一处

位置: `build-logic` 的 `AndroidApplicationConventionPlugin.kt` 第 44 行, 在 `defaultConfig` 块里急切写 `GIT_BRANCH`.

要改成什么样:

- 从 `defaultConfig` 挪进 `androidComponents.onVariants { }`, 用 `variant.buildConfigFields.put(...)` 惰性写入.
- 同一个分支名还被第 41 行拿去做 `archivesName`, 一处算两处用; 迁移时要把这段取值一起挪, 别留下两份来源.
- 官方 roadmap 的 10.0 章节把 `buildConfigField()` 与 `resValue()` 列在移除表, 替代写法写明是  
  `variant.buildConfigFields.put(...)` 与 `variant.manifestPlaceholders.put(...)`;  
  同一页要求先在 9.x 上把弃用警告清干净. 核实程度: **已验证** (页面原文).
- 这一项还没进 `gradle-api` 参考页的弃用标记, 所以在 9.5.2 上跑构建不会报警; 以 10.0 preview 出来后的实际警告为准.

## 两处要盯着, 现在不用动

- **第三方插件**. Metro, Firebase Crashlytics, Google Services, 两处 compose lint checks, Develocity, foojay resolver,  
  都得等它们出兼容 10.0 的版本. 官方给的失败长相是 `ClassCastException: ... cannot be cast to class ... BaseExtension`.
- **`configureondemand`**. 仓库同时开着 `org.gradle.configureondemand=true` 与 `org.gradle.configuration-cache.parallel=true`,  
  构建能过, 但两条都标 incubating. AGP 10.0 的定位是完整支持 Configuration Cache 与 Project Isolation,  
  这个开关要不要拿掉, 官方没说. 核实程度: **不确定**.

## 想提前预演 10.0 的话

官方给的办法是在 `gradle.properties` 显式写 `android.newDsl=true` 与 `android.builtInKotlin=true` 再跑一遍.  
仓库现在靠默认值, 已经等于在这个模式里, 写上只是把默认值钉死, 好处是将来默认值变了也不会悄悄退回.  
这属于改构建配置, 要动之前先报负责人.

## 顺带记下的两条现状

- `android.enableBuildConfigAsBytecode=true` 每次配置都会打一条 experimental 警告. 它是实验开关, 不影响结果,  
  但 10.0 前后值得回头看一眼这个开关还在不在.
- `:app:compileDebugKotlin` 这个任务名在 app 里不唯一, 有 Foss 与 Firebase 两套变体, 命令行要写全 `:app:compileFossDebugKotlin`.
