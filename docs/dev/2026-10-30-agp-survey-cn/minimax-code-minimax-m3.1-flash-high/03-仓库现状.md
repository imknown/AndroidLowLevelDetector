`gradle/toml/android.toml` 里有三个 AGP 版本 key:

- `androidGradlePlugin` 是生产用的稳定线.
- `androidGradlePlugin-beta` 和 `androidGradlePlugin-canary` 跟着 Android Studio 测试版自带的 AGP 走, 用来临时试, 不参与常规构建. canary 那个 key 指的版本就是 Google Maven 上 9.6 线当前最新的 alpha.
- `build.toml` 里的 `isPreview` 只切 Android SDK 那几个值 (`compileSdkPreview`, `targetSdkPreview`, `buildToolsPreview`), 不切 AGP.

## 新 DSL 与内置 Kotlin

- `KotlinAndroid.kt:31` 起写 `compileSdk { release(...) }`, `KotlinAndroid.kt:52` 起写 `targetSdk { release(...) }`. 9.0 之前那套 `targetSdkVersion` 写法没有出现.
- `KotlinAndroid.kt` 里的 `CommonExtension` 不带类型参数, `ApplicationExtension` 和 `LibraryExtension` 都从 `com.android.build.api.dsl` 包里 import.
- 全仓没有 apply `org.jetbrains.kotlin.android`, `gradle.properties` 里也没有关掉内置 Kotlin 的开关.
- 全仓没有 `applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants`, `variantFilter`, `dexOptions`. AGP 那个 `BaseExtension` 也没有. `KotlinAndroid.kt:16` 里的 `KotlinBaseExtension` 是 Kotlin 插件的接口, 名字相近, 不是一回事.
- `build-logic/convention/build.gradle.kts:16` 用 `compileOnly` 依赖 `gradle-api`, build-logic 里的 AGP import 全在 `com.android.build.api.dsl` 包下, 没有碰内部类.
- `gradle.properties` 没写 `android.newDsl` 和 `android.builtInKotlin`, 两个开关的默认值都是开着. 10.0 要的严格模式, 仓库现在就在这个模式里.

## R8 那几条变更的影响

- 9.1 起 R8 默认把类重打包到无名包. `app/build.gradle.kts:88` 起 release 变体开了压缩和资源缩减, 没有写 `-dontrepackage`, 等于接受默认行为. 仓库没有按包名反射找自身类的写法: 原生代码 `binderDetector/src/main/cpp` 下没有 `FindClass` 硬编码类名, Kotlin 侧的 `Class.forName` 只指向框架类, 见 `HomeRepository.kt:1037` 和 `HomeRepository.kt:1046`.
- 9.2 起 `-keepattributes` 的通配符不再保住运行时不可见注解. 仓库自己的规则写的是显式属性名, 见 `app/proguard-firebase-rules.pro:4` 的 `-keepattributes SourceFile,LineNumberTable`. `app/proguard-rules.pro` 是模板内容, `base/consumer-rules.pro` 是空文件, 两处都没有通配符写法.
- 9.5.0-alpha10 修了 l8DexDesugarLib 破坏混淆映射的问题. 仓库同时开了核心库脱糖 (`KotlinAndroid.kt:88`) 和 release 压缩, 这条修复正对得上.

## 9.6 那条线的影响

- 设备端覆盖率要求被测变体上设 `enableAndroidTestCoverage`. 仓库没有设过这个属性. 插桩测试用的 runner 是 `KotlinAndroid.kt:75` 设的 `androidx.test.runner.AndroidJUnitRunner`, 满足代理的要求.
- 9.6.0-alpha01 修的 lint 缓存不确定问题, 对仓库有影响: `gradle.properties:25` 开着 build cache, `app/build.gradle.kts:117` 指着 lint baseline.
- 9.6.0-alpha01 修的库 APK 资源缩减失效, 对仓库影响小: 只有 app 的 release 变体开了资源缩减, 两个库模块都没开.

## 10.0 移除清单的命中点

- `AndroidApplicationConventionPlugin.kt:44` 用了 `buildConfigField`. 这是全仓唯一命中点.
- `gradle-api` 的参考页里, `buildConfigField` 这一项还没打弃用标记, 同一页的 `targetSdkVersion` 已经标了会在 10.0 移除. 官方路线图把 `buildConfigField()` 和 `resValue()` 列在 10.0 的移除表里. 这一条以升级时的实际警告为准.
- `gradle.properties:26` 开着 `org.gradle.configureondemand=true`. Gradle 文档写明并行配置不支持按需配置, AGP 10 要完整支持 Project Isolation 时这个开关大概得拿掉.

## 没验到的部分

这台机器上 gradle 起不来. wrapper 要在 `~/.gradle/wrapper/dists` 写锁文件, 沙箱不让写.  
换已经解压好的 Gradle, 它加载 native 库时也要写 `~/.gradle/native`, 一样被拦.  
所以上面全是读文件得出的结果, 一次构建都没跑.

CI 脚本 `.github/workflows/android-ci.yml:36` 只跑 `assembleFossDebug`.  
debug 变体不开压缩, release 上的 R8 行为一次都没被验证过.
