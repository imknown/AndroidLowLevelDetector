# 02-对本仓库的要求

> **状态**: **frozen**. 记的是 2026-10-30 查到的上游规矩. 仓库该怎么写, 看 [09-构建约定](../../../agents-cn/09-构建约定.md).

## 门槛

每条发布线有四道门槛: Gradle 版本, JDK 版本, Build Tools 版本, 最高 API 级别.  
KGP 另有一道, AGP 9.0 起在运行时依赖它, 版本低于 2.2.10 时 AGP 会把项目里的版本抬上去.

仓库这四道门槛的现状记在 [03-仓库现状](03-仓库现状.md).

## 必须做的

### 把 KGP 抬到 AGP 要的版本之上

AGP 9.0 起在运行时依赖 KGP. 要放更高的版本, 做法是在顶层构建脚本的 `buildscript` 里把 KGP 压在 classpath 上.  
官方同时警告, 把这个版本降回 2.0.0 以下会碰上不兼容问题.

### 迁移 `buildConfigField()`

AGP 10.0 的移除清单里有 `buildConfigField()` 和 `resValue()`, 换成 `variant.buildConfigFields.put(...)` 和 `variant.manifestPlaceholders.put(...)`.  
仓库踩中的是前者.

### 拿掉两个过渡开关

`android.newDsl` 和 `android.builtInKotlin` 在 AGP 10.0 里被删掉, 没有替代.  
`android.newDsl.optOut` 作为按模块豁免的手段, 10.0 一起删掉.

### 第三方插件要有 10.0 兼容版本

还依赖旧扩展类型的插件会以 `ClassCastException: ... cannot be cast to class BaseExtension` 挂掉.

## 10.0 的移除清单

10.0 完成向全 lazy 构建模型的切换, 好让 AGP 完整支持 Gradle 配置缓存和 Project Isolation.

| 删掉的东西 | 换成什么 |
|---|---|
| `applicationVariants`, `libraryVariants`, `testVariants`, `unitTestVariants` | `androidComponents.onVariants()` |
| `variantFilter` 块 | `androidComponents.beforeVariants()` 加选择器 |
| `getJavaCompile()`, `getMergeResourcesProvider()`, `getAssembleProvider()` | Artifacts API, 用 `variant.artifacts` |
| `registerJavaGeneratingTask()`, `registerResGeneratingTask()` | Sources API, 用 `variant.sources.java.addGeneratedSourceDirectory(...)` |
| `getCompileConfiguration()`, `getCompileClasspath()` | Instrumentation API, 用 `variant.instrumentation.transformClassesWith(...)` 配 `AsmClassVisitorFactory` |
| `buildConfigField()`, `resValue()` | `variant.buildConfigFields.put(...)`, `variant.manifestPlaceholders.put(...)` |
| `sdkDirectory`, `ndkDirectory`, `bootClasspath`, `adbExecutable` | `androidComponents.sdkComponents` |
| `deviceProvider`, `testServer` | Gradle 托管设备 |
| `registerArtifactType`, `registerBuildTypeSourceProvider`, `registerProductFlavorSourceProvider`, `registerJavaArtifact`, `registerMultiFlavorSourceProvider`, `wrapJavaSourceSet` | 无 |
| Transform API | Artifacts API 和 `AsmClassVisitorFactory` |
| `android.newDsl`, `android.builtInKotlin` | 无 |
| 私有内部 AGP 类 (官方标了 tentative) | 只用 `gradle-api` 制品里的接口 |

写自定义插件或 build logic 时, `com.android.tools.build:gradle-api` 制品提供上面这些新接口.  
`gradle` 制品会把内部类藏起来, 编译时只给接口和 `gradle-api` 里有的类.

## 9.x 里的过渡开关

| 开关 | 作用 |
|---|---|
| `android.newDsl` | 关掉就回到旧 DSL. 默认开着. 10.0 删掉这个开关 |
| `android.builtInKotlin` | 关掉就回到手写 Kotlin 插件. 默认开着. 10.0 删掉这个开关 |
| `android.newDsl.optOut` | 按模块豁免新 DSL, 值是项目路径. 9.4.0-alpha04 起可用. 10.0 一起删掉 |
| `android.enforceDynamicFeatureVariantMatching` | 把动态功能的变体维度校验从警告变成错误. 10.0 起默认就是错误 |

模块级还有 `android { enableKotlin = false }`, 用来关掉单个模块的内置 Kotlin.  
它能把 Kotlin 编译任务从没有 Kotlin 代码的模块里拿掉, 也让那些模块不再依赖 Kotlin 标准库.

在 9.x 上验证 10.0 的行为, 做法是在 `gradle.properties` 写 `android.newDsl=true` 和 `android.builtInKotlin=true`.

## 官方的迁移顺序

1. 先在 9.x 上把所有弃用警告处理掉.
1. 在 `gradle.properties` 写 `android.newDsl=true` 和 `android.builtInKotlin=true`, 记下所有报错.
1. 还没迁完的模块用 `android.newDsl.optOut` 顶着.
1. 查第三方插件的兼容版本.
1. 用 Android Studio 的 AGP Upgrade Assistant, 以及 Android skills 仓库里的升级 skill.
1. 复杂场景照官方 gradle-recipes 仓库里的迁移例子改.

旧 Variant API 和新 Variant API 的差别, 官方给的对照是这样:

```
// 旧写法, 10.0 移除
android {
    applicationVariants.all {
        variant -> if (variant.buildType.name == "release") { }
    }
}

// 新写法
androidComponents {
    onVariants(selector().withBuildType("release")) {
        variant -> }
}
```

## 可以不做的

这些是新能力, 不用也不影响构建:

- 9.2 的统一测试报告, 和 9.6 的设备端覆盖率. 两个都要开实验开关.
- 9.3 的 `optimization {}` 块, 和 `src/<variant>/keepRules/` 源集. 旧写法仍然受支持.
- 9.3 的 `:app:analyzeReleaseR8Config` 任务.
- 9.5 的自动备份与恢复测试.
