# 01-上游发布线

> **状态**: **frozen**. 上游版本线和门槛是 2026-10-30 从官方发布说明查到的事实, 不是本仓库的规定.

## 门槛

门槛是这条发布线要求的最低版本. 官方表格里最低版本和默认版本在每一行都相同, 这里只写一个.

| 发布线 | 发布 | Gradle | Build Tools | JDK | 最高 API |
|---|---|---|---|---|---|
| 9.1 | 2026 年 3 月 | 9.3.1 | 36.0.0 | 17 | 36.1, 9.1.1 起是 37.0 |
| 9.2 | 2026 年 4 月 | 9.4.1 | 36.0.0 | 17 | 37.0 |
| 9.3 | 2026 年 7 月 | 9.5.0 | 36.0.0 | 17 | 37 |
| 9.4 | 2026 年 9 月 | 9.6.0 | 36.0.0 | 17 | 37 |
| 9.5 | 2026 年 10 月 | 9.6.0 | 36.0.0 | 17 | 37 |
| 9.6 | 预览, 只到 alpha | 9.7.1 | 36.0.0 | 17 | 37 |
| 10.0 | 未发布 | 未公布 | 未公布 | 未公布 | 未公布 |

9.1 那条线有两件事要说清:

- 发布说明页的标题写的是 9.1.1, 日期是 2026 年 4 月. 9.1.0 是 2026 年 3 月发的, 这个日期来自 Gradle 2026 年 3 月那期 newsletter 和一篇第三方文章, 官方页面本身没写.
- 最高 API 有两个数. 官方"关于 AGP"那张表里写着 API 37.0 的最低 AGP 版本是 9.1.1, 所以 9.1.0 支持到 36.1. Gradle 那期 newsletter 也写着 9.1.0 支持 API 36.1. 9.1 的发布说明页正文写 37.0, 那个页面是 9.1.1 的.

9.6 那条线的 Gradle 下限比 9.5 高, 是这几条线里最严的一条.

Kotlin Gradle 插件 (KGP): AGP 9.0 起在运行时依赖它, 页面写的版本是 2.2.10.  
项目里放的版本低于它时 AGP 会把它抬上去. 要放更高的版本, 做法见 [02](02-对本仓库的要求.md).

## 每一版加了什么

### 9.1

- R8 在编译到 DEX 时默认把类重打包到无名包, 等于给没写 `-repackageclasses` 或 `-flattenpackagehierarchy` 的构建补上 `-repackageclasses`. 要退出用 `-dontrepackage`.
- `-maximumremovedandroidloglevel` 可以写级别名字 (`ASSERT`, `ERROR`, `WARN`, `INFO`, `DEBUG`, `VERBOSE`, `NONE`), 不用写数字, 名字必须全大写.

### 9.2

- 统一的覆盖率与测试报告, 实验性. 开 `android.experimental.reportAggregationSupport`, 任务名是 `testAllSuites` 和 `testAllSuitesWithDependencies`, 报告是一个 HTML 面板.
- `-keepattributes` 的通配符不再保住 `RuntimeInvisibleAnnotations`, `RuntimeInvisibleParameterAnnotations`, `RuntimeInvisibleTypeAnnotations`. 要保就逐个点名.
- 成员规则可以写否定名, 例如 `*** !*ForTesting(...)`. 否定名也能用在 `-if` 的前置条件里.

### 9.3

- 独立任务 `:app:analyzeReleaseR8Config`, 不跑完整的打包流程就能出 R8 配置分析报告.
- 新的 `optimization {}` 块, 写在应用模块的 buildType 里, 库模块和测试也支持. 打开它等于同时打开代码优化和优化后的资源缩减, 也不用手写默认的保留规则文件. 旧写法仍然受支持.
- 保留规则可以放在 `src/<variant>/keepRules/`, 后缀 `.keep`. 新旧两套 DSL 都认这个源集.

### 9.4

- `android.newDsl.optOut` 可以按模块退让, 从 9.4.0-alpha04 起可用, 值是项目路径, 例如 `:lib`.
- 应用模块和动态功能模块之间的变体维度做 1:1 校验. 默认只出警告, 开 `android.enforceDynamicFeatureVariantMatching=true` 变成构建错误. 10.0 起默认强制.

### 9.5

- 自动备份与恢复测试, 实验性. 开 `android.experimental.testSuiteSupport` 和 `android.experimental.enableBackupTest`, 测试套件写在 `testOptions.backupTests`. AGP 构建并运行 JUnit 5 测试, 在已连接的设备上加数据, 备份, 恢复, 再核对数据是否完好. 结果出 HTML 报告.
- 9.5.0-alpha10 修了 l8DexDesugarLib 破坏混淆映射的问题, 表现是读完整份 mapping.txt 之后把它换成几十字节的存根.

### 9.6

- 插桩测试的覆盖率改到设备上算, 实验性. 开 `android.experimental.androidTest.coverage.useOnDeviceAgent` 和 `android.experimental.reportAggregationSupport`, 被测变体上还要设 `enableAndroidTestCoverage`. 构建期不再用 JaCoCo 织入应用类, 覆盖率代码不进应用 APK. 报告任务名和输出位置不变, 仍是 `create{Variant}AndroidTestCoverageReport`. 要求被测应用可调试, 设备是 API 28 以上.
- 官方给的收益是构建时间少 10% 到 20%, debug APK 小 20% 到 25%.
- 修复里有三条会影响别人的仓库:
  - 9.6.0-alpha01 修了 aapt2 变更导致库 APK 的 `shrinkResources` 失效.
  - 9.6.0-alpha01 修了 lint 的 ThreadConstraint 部分结果在不同 JVM 上不确定, 会把 lintAnalyze 的 build cache 打坏.
  - 9.6.0-alpha02 修了 R8 任务不安全地读系统属性.

## 发到哪一步

Google Maven 上 `com.android.tools.build:gradle` 的 `release` 标记指向 9.6 线当前最新的 alpha.  
10.0 没有任何构件发出来, 唯一的正式依据是 DSL/API 迁移时间表, 那里写的是 2026 年末.
