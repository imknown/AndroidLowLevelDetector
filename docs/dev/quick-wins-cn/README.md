# 快赢清单 · 小改动、好 review 的架构问题修复

> 基于[架构评审](../architecture-review-cn/README.md)选出的「改动少、可独立提交、编译即可验证」修复清单。每条含:问题代码、引入提交(时间与原因)、修改后的代码、直接原因、根本原因。问题诊断的完整分析不再重复,链接到对应评审条目。

## 选法说明

- 只从评审已确认的问题里挑:修复难度标注为「低」、或可拆成 ≤4 文件小提交的才入选。
- 负责人已裁定「不动 / 推迟」的条目一律不再列(见[已裁定事项](../architecture-review-cn/05-已裁定事项.md))。
- 每条各自独立成一个提交,互不依赖(QW-8a / QW-8b 是两个独立提交);`./gradlew assembleFossDebug` 编译通过 + 真机四个页面过一眼即可验收。个别条目附带了小单测(QW-2 / QW-5),跑法见对应条目。

**读表须知**:

- 「引入提交」表里,日期与提交信息原文是 git 记录的事实;「当时目的」栏凡标注(推断)的是结合 diff 与上下文做出的推测,未经当事人证实。按需只写日期与提交信息,不写提交 hash(用 `git log --oneline --date=short` 可自行对应)。
- 「修改后」代码为节选:省略处以 `...` 标注;除标注的新增/删除 import 外,其余函数体与调用点一律不动。
- 提交「Feat: Improve exception handling via UDF」(2025-12-03)一次性重写了首页异常处理与检测编排,是多个问题当前形态的共同来源,因此在多条目里重复出现。
