## 4.1 扩展色板：自定义主题色的官方做法

**背景**：`?attr/colorNoProblem`（绿）、`?attr/colorWarning`（黄）、`?attr/colorCritical`（红）是本项目在 M3 色板**之外**自定义的三个主题属性。Compose 的 `MaterialTheme.colorScheme` 里没有它们，硬编码散落各处是反模式——官方推荐"扩展 MaterialTheme"：建一个 `@Immutable` 数据类 + `CompositionLocal`，随 `AppTheme` 一起切换深浅色。

before（现状，散在 XML 里）：

```xml
<!-- ui/home/res/values/attrs.xml + colors.xml + values-night/colors.xml -->
<attr name="colorNoProblem" format="color" />
<color name="colorNoProblem">#D0ACDDB7</color>   <!-- 浅色：淡绿 -->
<color name="colorWarning">#D0FDD18F</color>     <!-- 浅色：淡黄 -->
<color name="colorCritical">#D0FFB1AC</color>    <!-- 浅色：淡红 -->
<!-- values-night 里另有一套深色值 -->
```

after —— `ui/theme/ExtendedColors.kt`（新增）：

```kotlin
package net.imknown.android.forefrontinfo.ui.theme

import androidx.annotation.AttrRes
import androidx.compose.runtime.Immutable
import androidx.compose.runtime.staticCompositionLocalOf
import androidx.compose.ui.graphics.Color
import net.imknown.android.forefrontinfo.R

/** M3 色板之外的项目自有主题色。值 = XML 里那六份 <color>，ARGB 十六进制原样照搬。 */
@Immutable
data class ExtendedColors(
    val noProblem: Color,
    val warning: Color,
    val critical: Color,
)

private val ExtendedLightColors = ExtendedColors(
    noProblem = Color(0xD0ACDDB7),
    warning = Color(0xD0FDD18F),
    critical = Color(0xD0FFB1AC),
)

private val ExtendedDarkColors = ExtendedColors(
    noProblem = Color(0xD02B5128),
    warning = Color(0xD07E581F),
    critical = Color(0xD0812F2F),
)

val LocalExtendedColors = staticCompositionLocalOf { ExtendedLightColors }

/** 把旧代码里的 ?attr 引用映射到新色板；RES_ID_NONE 由调用方先行过滤。 */
@Composable
fun ExtendedColors.of(@AttrRes attr: Int): Color = when (attr) {
    R.attr.colorNoProblem -> noProblem
    R.attr.colorWarning -> warning
    R.attr.colorCritical -> critical
    else -> Color.Unspecified
}
```

`Theme.kt` 的 `AppTheme(...)` 末尾把本地值"挂"上去（改动 4 行）：

```diff
     MaterialTheme(
         colorScheme = colorScheme,
         typography = AppTypography,
-        content = content
-    )
+    ) {
+        CompositionLocalProvider(
+            LocalExtendedColors provides if (darkTheme) ExtendedDarkColors else ExtendedLightColors
+        ) {
+            content()
+        }
+    }
```

**API 讲解**：

- `staticCompositionLocalOf`：造一个 CompositionLocal（02 章第 7 节）。`static` 版本意味着"值很少变"——切换深浅色时整棵树重组一次，可接受；频繁变化的值要用 `compositionLocalOf`（细粒度重组）。
- `CompositionLocalProvider(...) { content() }`：在子树里注入值，子树内 `LocalExtendedColors.current` 取用——等价于 View 时代的"读主题属性"。
- `@Immutable`：向编译器承诺不可变（02 章第 2 节），让用它的组件可跳过。
- `Color(0xD0ACDDB7)`：ARGB 十六进制与 XML 完全同构（前两位 D0 是透明度 82%），照搬零换算。

## 4.2 字号：先校准 Typography

> **⚠️ 2026-09-19 实现期更正（用户拍板，两次迭代）**：观感要与旧 my_view_holder.xml 逐像素一致。最终方案：`titleLarge`/`bodyLarge` 两个槽位显式 `platformStyle = PlatformTextStyle(includeFontPadding = true)`——**根因是新版 Compose 已把 includeFontPadding 默认翻成 false**（ui-text 的 PlatformParagraphStyle 私有构造反编译实证 =0），而旧 TextView 默认 true，丢掉的字体留白就是"变矮"的来源；行高**不设**（字体度量 + 字体留白 = 旧 TextView 不设行高的同款行为；中间试过显式行高 24sp/20sp，不如补字体留白正确）。另注意 material3 Typography 构造参数默认值来自 TypographyTokens 基线，传入部分 TextStyle 是**整体替换**而非合并，须显式写出全部要保留的字段。将来 Material 3 Expressive 可用时再重新调制。

现状标题是 `20sp + bold`，而 M3 默认 `titleLarge` 是 `22sp + 常规`、`titleMedium` 是 `16sp + 中黑体`——都不精确匹配。**不逐个 Text 写死字号**，而是校准全局 `AppTypography`（这也是官方"用语义样式而非硬编码"的推荐做法）：

`ui/theme/Type.kt`（修改）：

```diff
+import androidx.compose.material3.Typography

+import androidx.compose.ui.text.font.FontWeight
+import androidx.compose.ui.unit.sp

-val AppTypography = Typography()
+val AppTypography = Typography(
+    // 对齐现状 my_view_holder.xml 的 20sp + bold
```

之后所有标题统一写 `MaterialTheme.typography.titleLarge`，详情用 `bodyLarge`（默认 16sp，与现状一致）。将来想全局调字号只改这一处。

```kotlin
import androidx.annotation.AttrRes                        // @AttrRes 只是注解（标记"这是 attr 资源 id"）
import androidx.compose.foundation.background            // Box 的背景修饰符
import androidx.compose.foundation.layout.Box            // 叠放容器（色点要叠在标题右上角）
import androidx.compose.foundation.layout.Column         // 纵向容器（标题在上、详情在下）
import androidx.compose.foundation.layout.fillMaxWidth   // = layout_width="match_parent"
import androidx.compose.foundation.layout.padding        // = XML 的 padding
import androidx.compose.foundation.layout.size           // 固定尺寸（给色点用）
import androidx.compose.foundation.shape.CircleShape     // 圆形（= XML 的 Circle 样式）
import androidx.compose.material3.Card                   // M3 填充式卡片
import androidx.compose.material3.CardDefaults           // Card 的默认值定制入口（配色/阴影）
import androidx.compose.material3.MaterialTheme          // 主题读取入口（颜色/文字样式）
import androidx.compose.material3.Text                   // 文本组件
import androidx.compose.runtime.Composable               // @Composable 注解本体
import androidx.compose.ui.Alignment                     // Box 内对齐（TopEnd = 右上角）
import androidx.compose.ui.Modifier                      // 修饰符（本章主角之一）
import androidx.compose.ui.draw.clip                     // 按形状裁剪（圆形色点）
import androidx.compose.ui.platform.LocalDensity         // 密度（sp → dp 换算要用）
import androidx.compose.ui.res.dimensionResource         // 读 dimens 资源（与 XML 单一数据源）
import androidx.compose.ui.res.stringResource            // 读字符串资源（可翻译、有缓存）
import androidx.compose.ui.unit.sp                       // sp 字号单位

/** 状态色圆点尺寸。原 XML 写的是 16sp（随系统字号缩放），Compose 尺寸只认 dp，故运行时换算。 */
private val MyModelColorDotSize = 16.sp

@Composable
fun MyModelCard(
    model: MyModel,                // 数据进：卡片长什么样完全由它决定（单向数据流的"数据进"）
    modifier: Modifier = Modifier, // 惯例参数：调用方传来的"尺寸/位置"约束，先接住、稍后合并
) {
    Card(
        modifier = modifier
            .fillMaxWidth(),      // 在调用方约束基础上补"横向占满"（= match_parent）
        // 原 XML: Widget.Material3.CardView.Filled + cardBackgroundColor="?attr/colorSurfaceBright"
        // Compose 的 Card 默认带 1dp 阴影，XML 的 Filled 样式是 0 阴影——显式归零保持视觉一致
        elevation = CardDefaults.cardElevation(defaultElevation = 0.dp),
        colors = CardDefaults.cardColors(                     // "默认值对象"模式：改配色不换组件
            containerColor = MaterialTheme.colorScheme.surfaceBright,  // = ?attr/colorSurfaceBright
        ),
    ) {
        Column(                   // 纵向排：标题块在上、详情在下
            modifier = Modifier.padding(
                dimensionResource(R.dimen.item_card_padding)  // = XML 的 item_card_padding
            )
        ) {
            Box {                 // 叠放：标题铺满 + 色点叠右上（替代原两条约束）
                Text(
                    text = model.title.asText(),                  // 资源 id→翻译文案；原文直接用
                    style = MaterialTheme.typography.titleLarge,  // 语义样式（4.2 已校准为 20sp 粗体）
                    color = MaterialTheme.colorScheme.onSurface,  // = ?attr/colorOnSurface
                    modifier = Modifier.fillMaxWidth(),           // 占满宽，色点的"右上角"才有意义
                )

                if (model.color != RES_ID_NONE) {   // 条件即显隐：不满足就"根本不组合"（非"藏起来"）
                    Box(
                        modifier = Modifier
                            .align(Alignment.TopEnd)   // 叠放容器内对齐到右上角
                            .size(                     // 固定大小：16"号字"那么大
                                with(LocalDensity.current) {   // 借当前密度做单位换算
                                    MyModelColorDotSize.toDp() // sp→dp：系统字号放大圆点跟着大
                                }
                            )
                            .clip(CircleShape)         // 先定形状……
                            .background(               // ……再上色（顺序反了色会溢出圆外）
                                LocalExtendedColors.current.of(model.color)  // ?attr → 扩展色板
                            ),
                    )
                }
            }

            Text(
                text = model.detail,
                style = MaterialTheme.typography.bodyLarge,         // 默认 16sp，与旧 XML 一致
                color = MaterialTheme.colorScheme.onSurfaceVariant, // = ?attr/colorOnSurfaceVariant
            )
        }
    }
}
```

**逐段讲为什么**：

- **`Card { ... }`**：M3 的"填充式"卡片（同家族还有 `ElevatedCard`、`OutlinedCard`；没有单独叫 `FilledCard` 的组件）。注意它**默认带 1dp 阴影**，与 XML `Widget.Material3.CardView.Filled`（0 阴影）不同，故上面显式 `elevation = CardDefaults.cardElevation(defaultElevation = 0.dp)` 归零。另外 `Card(onClick = ...)` 是另一个带点击涟漪的重载——原 XML 的 `clickable="true"` 没绑任何监听器，故这里选无点击版本，**行为等价**。
- **`colors = CardDefaults.cardColors(containerColor = ...)`**：M3 组件的配色统一走"组件默认值对象"（`CardDefaults`），支持从 `MaterialTheme.colorScheme` 取值。凡是 XML 里见过的 `?attr/colorXxx`，在 Compose 里就是 `MaterialTheme.colorScheme.xxx`。
- **`Column` + `Box` 替代 ConstraintLayout**：标题在上、详情在下（Column）；色点叠在右上角（Box + `align(Alignment.TopEnd)`，等价于 `layout_constraintEnd_toEndOf="parent"`）。约束简单到不值得用约束布局。
- **`dimensionResource(R.dimen.item_card_padding)`**：Compose 里仍能读 dimens 资源，保证与 XML 单一数据源。等第 7 步删 XML 后可换成 `10.dp` 常量。
- **`if (model.color != RES_ID_NONE)`**：替代 `isGone = true` 的命令式隐藏——条件为假时这个 `Box` 根本不进组合树（XML 是"造好了再藏"，Compose 是"不造"）。
- **色点尺寸的 `sp` → `dp`**：Compose 的 `size()` 只接受 dp；原 XML 用 `16sp` 是想让圆点跟随系统字号。`with(LocalDensity.current) { 16.sp.toDp() }` 在每次组合时按当前字体缩放换算，保留这一行为。
- **`stringResource(id)` vs `MyApplication.getMyString(id)`**：前者是 Compose 的资源读取（跟随组合、有缓存、语言切换自动刷新），后者要在 Application 上持 Context——新代码一律用前者。
- **`model.title.asText()`**：密封接口的解析写成一个 `@Composable` 扩展函数，把 `when` 从卡片里抽走，后面别处（如"复制结果"功能）可复用。

## 4.4 试水 Style API（Compose 最新样式范式，实验性）

> **⚠️ 2026-09-19 实现期更正**：官方 Styles 文档（含本节的 `Style { }` lambda 构建器、`MutableStyleState(null)`、`Modifier.styleable { }` lambda 重载）对应的是 foundation **alpha 线**（文档自己写明 "latest alpha release"，示例 `1.12.0-alpha03`）。反编译 + 编译实证：BOM 2026.09.00 映射的 **1.12.1 stable 里这些签名均不存在**（只有旧形态：`Style` 接口 + `then`/`Style(...)` 合并 + `styleable(state, style)` + 非空构造 `MutableStyleState(InteractionSource)`）。与 material3 Expressive 主题同剧本：alpha 引入 → stable 撤出 → 只活在 alpha。**经用户拍板，本步试水撤掉**（卡片用 4.3 的 `Modifier.padding`），试水推迟到 BOM 升 1.13（新 DSL 落地）后在第 7 步收尾时立项。本节以下内容保留作 alpha 线参考。

> 调研来源：官方指南 [Styles in Compose](https://developer.android.com/develop/ui/compose/styles)（用户指定）+ [foundation 发布说明](https://developer.android.com/jetpack/androidx/releases/compose-foundation) + [API reference](https://developer.android.com/reference/kotlin/androidx/compose/foundation/style/package-summary)。

**它是什么**：Compose 的下一代"样式"机制，与 Modifier 并存、分工不同——**只管"长相"**（内外边距、背景、边框、形状、阴影、文字排版、颜色），不管"行为"（点击、手势、语义）。官方三个核心概念：

| 概念 | 官方定义（意译） |
| --- | --- |
| `Style` | 定义元素外观的对象，属性集合类似 CSS 样式；**同名属性"后写覆盖"**（与 Modifier 的叠加相反） |
| `StyleScope` | `Style { }` 内部的作用域，提供 `contentPadding` / `background` / `border` / `shape` 等属性函数 |
| `StyleState` | 只读状态（`isPressed` / `isHovered` / `isEnabled` / 自定义状态），供样式做条件分支与内置动画 |

**版本现状与采用决策**（按你的成熟度评估习惯给出）：

- foundation **1.11.0-alpha06 引入**，本 BOM 的 **1.12.1 里可用**，标注 `@ExperimentalFoundationStyleApi`；
- foundation 1.13.0-alpha03 发布说明已宣布把它**重构为"DSL + 修饰符"两件套，旧 `Style` 实现将废弃移除**；
- material3 组件的 `style` 参数**官方预告在未来版本**——即当前 M3 组件还吃不到 Style。

结论：**只在本文件小范围试水**（学新范式 + 把样式集中成可合并的对象），不铺满全项目；将来无论迁向 1.13 新 DSL 还是 M3 的 style 参数，改动面都锁定在这一个文件里。

### 改造：卡片内层容器的样式从 Modifier 挪进 Style

before（4.3 节的 Column）：

```kotlin
Column(modifier = Modifier.padding(dimensionResource(R.dimen.item_card_padding))) {
```

after：

```kotlin
// 文件顶部：卡片内容区的视觉样式，集中一处定义
@OptIn(ExperimentalFoundationStyleApi::class)
private val MyModelCardContentStyle = Style {
    contentPadding(10.dp)   // 即原 dimens 的 item_card_padding
}

// "过期应用"条目在此基础上再叠一层（演示 then 合并与后写覆盖）
@OptIn(ExperimentalFoundationStyleApi::class)
private val OutdatedApkCardStyle = Style {
    contentPaddingBottom(16.dp)   // 只覆盖 bottom，其余沿用 MyModelCardContentStyle
}

@OptIn(ExperimentalFoundationStyleApi::class)
@Composable
fun MyModelCard(model: MyModel, modifier: Modifier = Modifier) {
    // ... Card 与前文相同 ...

    val styleState = remember { MutableStyleState(null) }
    val contentStyle = if (model.type == MyModelType.OutdatedTargetSdkApk) {
        MyModelCardContentStyle then OutdatedApkCardStyle
    } else {
        MyModelCardContentStyle
    }

    Card(
        modifier = modifier.fillMaxWidth(),
        // 与 4.3 相同：XML 的 Filled 样式是 0 阴影，Compose 默认 Card 带 1dp，显式归零
        elevation = CardDefaults.cardElevation(defaultElevation = 0.dp),
        colors = CardDefaults.cardColors(
            containerColor = MaterialTheme.colorScheme.surfaceBright,
        ),
    ) {
        Column(modifier = Modifier.styleable(styleState, contentStyle)) {
            // ... Box/Text 与前文相同 ...
        }
    }
}
```

（导入来自 `androidx.compose.foundation.style` 包：`Style` / `styleable` / `MutableStyleState` / `ExperimentalFoundationStyleApi`。）

### 讲解

- **`Style { }` 与 `then`**：`styleA then styleB` 把两个样式按"后写覆盖"合并。对比 Modifier 的叠加语义——`Modifier.padding(10.dp).padding(16.dp)` 两层都生效；`Style` 里 `contentPadding(10.dp)` 之后又写 `contentPaddingBottom(16.dp)`，结果是 bottom 为 16、其余仍为 10。**这是两套系统最本质的差异**，官方特别标注为 Important。
- **`Modifier.styleable(styleState, style)`**：把样式挂到任意容器上；`MutableStyleState(null)` 暂不接交互源（传 `null`），将来要做按压效果时把 `InteractionSource` 传进去，就能在 `Style` 里写 `pressed { animate { borderColor(...) } }`——样式切换自带动画且**只在布局/绘制阶段求值，跳过组合阶段**（性能卖点的根源）。
- **诚实结论**：对这个无交互的卡片而言，Style 与 `Modifier.padding` 效果等价、当前收益为零；真正的赢面在"状态驱动样式 + 内置动画 + 主题级统一样式"（可参考官方指南的登录按钮示例）。此处试水的目的是在低风险位置建立对新范式的手感。
- 细节：样式属性还支持排版类（`textStyle` / `fontSize`）与 `contentColor`，这类属性**可被子组件继承**（实验开关 `ComposeFoundationFlags.isInheritedTextStyleEnabled`）；样式内可读 `CompositionLocal`。

## 验证

1. `./gradlew :app:compileFossDebugKotlin` 编译通过；
2. Android Studio 里打开 `MyModelCard.kt`，右侧出现三张卡片的实时预览（浅色 + 深色两个变体），深色变体里圆点是深色版颜色——验证 `ExtendedColors` 接线正确；
3. 运行 app，**行为零变化**（新组件尚未被任何界面引用）。

## 本步小结（学到了什么）

- CompositionLocal 的"自建主题扩展"完整套路：`@Immutable` 数据类 → `staticCompositionLocalOf` → `CompositionLocalProvider` 挂进 `AppTheme`；
- M3 组件三件套通用模式：组件（`Card`）+ 默认值对象（`CardDefaults`）+ 语义样式（`MaterialTheme.typography`）；
- 声明式的"条件即显隐"，以及资源（string/dimension）在 Compose 里的标准读法；
- **Style API 初体验**：`Style { }` 构建样式、`then` 后写覆盖合并、`Modifier.styleable` 挂载——以及它与 Modifier 的语义差异和版本现状。
