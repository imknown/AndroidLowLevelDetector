## 9.2 依赖与构建瘦身

`app/build.gradle.kts`：

```diff
-    implementation(libsAndroid.bundles.arch.core)
-    implementation(libsAndroid.cardView)
-    implementation(libsAndroid.constraintLayout)
-    implementation(libsAndroid.coordinatorLayout)
-    implementation(libsAndroid.fragment)
-    implementation(libsAndroid.preference)
-    implementation(libsAndroid.recyclerView)
-    implementation(libsAndroid.swipeRefreshLayout)
```

- `buildFeatures { viewBinding = true }` 删除（`ViewBindingExt` 已死）；
- **`preference` 删除的前置条件**：`MyApplication` 里 `PreferenceManager.getDefaultSharedPreferences(instance)` 是 androidx.preference 的最后一处引用，先换成等价写法 `instance.getSharedPreferences("${instance.packageName}_preferences", Context.MODE_PRIVATE)`——**读写的是同一个文件**，用户设置原样继承；
- **`appcompat` 与 `material`（MDC）都暂留**，原因彼此相关：`MainActivity` 还是 `AppCompatActivity`、主题模式靠 `AppCompatDelegate.setDefaultNightMode`；`resTheme/` 的 XML 主题父级是 MDC 的 `Theme.Material3Expressive.*`，`MyApplication` 的 `DynamicColors.applyToActivitiesIfAvailable` 也是 MDC 类。两者随 9.4 遗留优化第 2 条（去 AppCompat 化 + XML 主题改平台主题）一起退场；
- `androidx.fragment` **已删除**：代码无直接 `import androidx.fragment`，运行时由 `androidx.activity` / `lifecycle-*` 传递依赖提供；`arch-core`（bundle: core-common + core-runtime）同理——`lifecycle` 内部已传递引入，无需显式声明；
- `gradle/toml/android.toml` 里对应条目与 bundle 随之清理（arch-core / cardView / constraintLayout / coordinatorLayout / fragment / preference / recyclerView / swipeRefreshLayout 的 version + library + bundle 全部移除）；
- `resTheme/` 的 XML 主题**继续保留**：窗口背景、启动外观、状态栏初始样式仍由它提供（官方立场：全 Compose 后也保留 XML 主题作为窗口级底座，删除的只是"控件样式"职责）。`values-night` 的深色窗口配色同理保留。

3. **滚动条**：设置项 UI 存在且 SharedPreferences 读写正常，但当前为 inert（滚动条实现推迟至 material3 1.5 `nonInteractiveScrollbar` 转正）；验证切选项不崩溃、值持久化即可；
4. **设置项继承**：从旧版本升级，主题/滚动条/两开关的值全部保留（SharedPreferences 键未动）；
5. **主题**：四档主题模式 × 深浅色 × 动态取色（Android 12+）× 高对比度（系统辅助功能）抽查；

## 9.4 遗留优化（本计划刻意不做，供后续立项）

按收益排序，每条都是独立小项目：

1. **滚动条换代**：material3 1.5 转正后，自绘 `verticalScrollbar` 一行替换为官方 `Modifier.nonInteractiveScrollbar`（自带淡出动画）。
2. **主题模式去 AppCompat 化**：`MainActivity` 换 `ComponentActivity`，`AppTheme(darkTheme = ...)` 由"偏好状态 + `isSystemInDarkTheme()` + 省电模式"直接驱动（省一次 Activity 重建，切换更顺滑）；XML 主题同步改为平台主题（父级脱离 MDC）、`MyApplication` 移除 `DynamicColors`。完成后 `appcompat` 与 `material`（MDC）依赖即可删除。
3. **Expressive 主题**：material3 1.5 线的 `expressiveLightColorScheme()` / `MaterialExpressiveTheme` / `MaterialTheme.motionScheme` 可让整体观感升级为 M3 Expressive（弹出手势、组件动效全套）。评估稳定后切换。
4. **Style API 跟进**：foundation 1.13 把 Style API 重构为"DSL + 修饰符"后，按官方迁移把 3.4 节的试水代码迁到新 DSL；material3 组件开放 `style` 参数后进一步收纳。
5. **设置存储现代化**：SharedPreferences → DataStore（官方推荐组合），偏好状态改 Flow，`MyApplication.sharedPreferences` 单例退场。
6. **自适应导航**：引入 `material3-adaptive-navigation-suite`（1.5.0-alpha，不在 BOM），手机/折叠/平板自动切换底栏与侧栏。
7. **底栏随滚动隐藏**：如需复刻旧行为，用 `Modifier.nestedScroll` + 自定义 `NestedScrollConnection` 包住 `Scaffold`。
8. **测试基建**：Compose UI 测试（`createComposeRule`）、Robolectric、Macrobenchmark——对应此前已记录的"CI 门禁待测试基建补齐后再上"的决定。
