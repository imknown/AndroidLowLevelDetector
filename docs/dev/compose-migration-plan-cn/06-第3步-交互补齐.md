## 6.1 下拉刷新：SwipeRefreshLayout → PullToRefreshBox

### before（BaseListFragment，节选）

```kotlin
val color = MaterialColors.getColor(binding.root, materialR.attr.colorOnPrimaryContainer)
binding.swipeRefreshLayout.setColorSchemeColors(color)

binding.swipeRefreshLayout.setProgressBackgroundColorSchemeColor(backgroundColor)

binding.swipeRefreshLayout.setOnRefreshListener { listViewModel.refresh() }

State.Loading -> binding.swipeRefreshLayout.isRefreshing = true
```

### after

`MyModelListScreen` 订阅处增加两个派生值，内容外包一层 `PullToRefreshBox`：

```kotlin
MyModelListContent(
    models = models,
    isRefreshing = state is State.Loading,   // 状态向下：Loading 即转圈（含首次加载，与旧行为一致）
    onRefresh = viewModel::refresh,          // 事件向上：手势触发 → VM 刷新（方法引用就是 lambda）
    scrollBarEnabled = rememberScrollBarEnabled(),  // 偏好 → 状态（6.2 的成果）
    modifier = modifier,
)
```

```kotlin
@Composable
private fun MyModelListContent(
    models: PersistentList<MyModel>,   // 纯数据
    isRefreshing: Boolean,             // 转圈与否（外部状态，本组件不自作主张）
    onRefresh: () -> Unit,             // 刷新回调（事件向上抛）
    scrollBarEnabled: Boolean,         // 滚动条开关
    modifier: Modifier = Modifier,
) {
    val listState = rememberLazyListState()   // 列表的"仪表盘"：滚动位置、可见条目、指示器状态都在这
    // 自定义 indicator 时必须自备状态，并同时传给 PullToRefreshBox 与 Indicator（见下方讲解）
    val pullToRefreshState = rememberPullToRefreshState()   // 下拉手势的"仪表盘"：拉动距离进度等

    PullToRefreshBox(
        isRefreshing = isRefreshing,   // 状态进：转不转圈我说了不算，参数说了算
        onRefresh = onRefresh,         // 事件出：用户拉够阈值 → 通知上层
        state = pullToRefreshState,    // 手势状态（自备指示器时必须显式传）
        modifier = modifier.fillMaxSize(),
        indicator = {                  // 指示器槽：默认给一个 M3 圆形，这里按旧配色定制
            // 对应旧代码的两行配色（primaryContainer 底 + onPrimaryContainer 圈）。
            // 删掉整个 indicator 参数则用 M3 默认配色（surfaceContainerHigh 底）
            PullToRefreshDefaults.Indicator(
                modifier = Modifier.align(Alignment.TopCenter),   // 在 PullToRefreshBox 内居顶
                isRefreshing = isRefreshing,
                state = pullToRefreshState,
                containerColor = MaterialTheme.colorScheme.primaryContainer,
                color = MaterialTheme.colorScheme.onPrimaryContainer,
            )
        },
    ) {
        LazyColumn(
            state = listState,         // 接上仪表盘（滚动条要从里面读数）
            modifier = Modifier
                .fillMaxSize()
                .background(MaterialTheme.colorScheme.surfaceContainer)
                .then(                 // 条件修饰符：开关开着才"贴上"滚动条
                    if (scrollBarEnabled && listState.scrollIndicatorState != null) {
                        Modifier.verticalScrollbar(
                            state = listState.scrollIndicatorState!!,   // !! 前面已判空，安全
                            color = MaterialTheme.colorScheme.outline.copy(alpha = 0.7f),
                        )
                    } else {
                        Modifier                       // 空 Modifier = 什么都不加
                    }
                ),
            contentPadding = /* 与第 2 步相同 */,
            verticalArrangement = /* 与第 2 步相同 */,
        ) {
            /* items(...) 与第 2 步相同 */
        }
    }
}
```

**白话**：`PullToRefreshBox` 干的是"翻译 + 绘制"两件事——把手势**翻译**成事件（下拉到位 → `onRefresh`）、把状态**绘制**成转圈（`isRefreshing` → 指示器）。它**不自作主张去刷新**：转不转、何时停，全部听外部状态的——这就是它和旧 `SwipeRefreshLayout`（自己管 `isRefreshing`）的本质区别。

**API 讲解**：

- **`PullToRefreshBox(isRefreshing, onRefresh) { content }`**：把"手势识别 + 指示器动画"包进一个 Box。与旧 `SwipeRefreshLayout` 的关键差别：它**不做任何事**除非你把状态喂回去——`isRefreshing` 由外部状态驱动（本例 = `state is State.Loading`），这正是单向数据流（02 章第 3 节）的教科书案例：手势事件向上（`onRefresh` → `viewModel.refresh()`），加载状态向下（`Loading → isRefreshing`）。
- **`indicator` 槽**：默认给一个 M3 风格圆形指示器；本项目旧版指定了"主容器色"配色，故按官方签名 `PullToRefreshDefaults.Indicator(containerColor = ..., color = ...)` 照搬，视觉零变化。
- material3 1.4.0 的 `PullToRefreshBox` 尚无 `enabled` / `threshold` 参数（1.5.0 新增），本计划不使用它们。

## 6.2 滚动条：设置项 → 共享状态 → 自绘修饰符

### 状态侧：`ui/common/ScrollBarMode.kt`（新增）

旧代码里"读一次偏好 + 收设置页事件"这套逻辑同时存在于列表页和设置页，抽成一个可组合函数：

```kotlin
/** 滚动条模式偏好 → 布尔状态。设置页改动后经 scrollBarModeChangedSharedFlow 即时生效。 */
@Composable
fun rememberScrollBarEnabled(): Boolean {
    val key = MyApplication.getMyString(R.string.interface_scroll_bar_key)
    val normalValue = MyApplication.getMyString(R.string.interface_normal_scroll_bar_value)

    var mode by remember {
        mutableStateOf(MyApplication.sharedPreferences.getString(key, null))
    }

    LaunchedEffect(Unit) {
        SettingsViewModel.scrollBarModeChangedSharedFlow.collect { mode = it }
    }

    return mode == normalValue
}
```

（这里用 `MyApplication.getMyString(...)` 而不是 `stringResource(...)`：键与"普通模式"值都是 `translatable="false"` 的常量，不随语言变，在 `remember`/普通函数里取用更直接。）

### 绘制侧：`ui/base/list/VerticalScrollbar.kt`（新增）

```kotlin
/**
 * 自绘垂直滚动条（纯视觉，不可拖动）。
 * 用的是 foundation 1.12 的稳定状态 API ScrollIndicatorState；
 * material3 1.5.0 转正后可用官方 Modifier.nonInteractiveScrollbar 一行替换。
 */
fun Modifier.verticalScrollbar(
    state: ScrollIndicatorState,   // 列表的滚动数据源（scrollOffset/contentSize/viewportSize）
    color: Color,                  // 主题色由调用方传：修饰符本身不依赖 MaterialTheme，纯函数
    width: Dp = 4.dp,              // 滚动条粗细
): Modifier = drawWithContent {    // 绘制阶段：不参与布局、不触发重组（本步的性能关键）
    drawContent()   // 先画原本的列表内容——drawWithContent 的约定：不调它原内容就消失了

    val contentSize = state.contentSize      // 内容总长（px）
    val viewportSize = state.viewportSize    // 视口长（px）——两者同单位，比例运算不受单位影响
    if (contentSize <= viewportSize) return@drawWithContent   // 内容不满一屏：不画

    val trackLength = size.height            // 轨道长 = 本组件绘制区的高（size 是绘制阶段的可用信息）
    val thumbLength = trackLength * viewportSize / contentSize          // 拇指长 = 可见占比 × 轨道
    val scrollRange = (contentSize - viewportSize).toFloat()            // 最多还能滚多远
    val thumbTop = (trackLength - thumbLength) * state.scrollOffset / scrollRange  // 按进度定位

    drawRoundRect(   // 画一个圆角矩形当拇指条
        color = color,
        topLeft = Offset(size.width - width.toPx(), thumbTop),   // 贴最右侧
        size = Size(width.toPx(), thumbLength),
        cornerRadius = CornerRadius(width.toPx() / 2),           // 两端圆头
    )
}
```

`color` 参数由调用侧传入（6.1 主代码里的 `MaterialTheme.colorScheme.outline.copy(alpha = 0.7f)`——这也是 material3 官方滚动条的默认取色），修饰符本身保持无主题依赖。

**API 讲解（本步最有含金量的部分）**：

- **`ScrollIndicatorState`**：官方在 foundation 1.10 引入的稳定接口，`LazyListState` / `ScrollState` / `PagerState` 都实现了 `scrollIndicatorState` 属性，提供 `scrollOffset`（滚过多少）、`contentSize`（内容总长）、`viewportSize`（视口长）三个数——自绘滚动条要的原料齐了。官方注释里 `scrollOffset` 标了 `@get:FrequentlyChangingValue`：**它是为绘制阶段读取设计的**。
- **`Modifier.drawWithContent { }`**：进入**绘制阶段**（不做布局、不触发重组）。在它的 lambda 里读 `state.scrollOffset`，滚动时只重画这一层，**零重组、零重新布局**——这是 Compose 性能三层模型（组合 → 布局 → 绘制）里"把读取推迟到最后一层"的标准优化。对比方案：如果用 `LazyColumn` 的 `firstVisibleItemIndex` 之类在组合里读，滚动一下整列重组一次。
- **拇指条几何**：`thumbLength / trackLength = viewport / content`（可见占比），`thumbTop / (trackLength - thumbLength) = scrollOffset / (content - viewport)`（滚动进度）。两行中学几何，这也是官方指示器的算法。
- 与旧行为的已知差异：View 滚动条滚停后约 0.5 秒淡出；本实现**常显**（4dp、70% 透明度，观感克制）。要做淡出需引入滚动监听 + 动画，收益低，留给官方 1.5.0 的 `nonInteractiveScrollbar`（自带 fade）转正后一行替换。

**白话**：Compose 刷新分三层流水线——**组合（决定有啥）→ 布局（决定多大）→ 绘制（决定长啥样）**。读状态读得越靠后，动的层越少：滚动条这种"每帧都在变"的读数，放到**绘制阶段**读，就只重画一小块，前面的层全免——这是 `@get:FrequentlyChangingValue` 注解存在的意义（官方在告诉你：这个值就该这么用）。

✅ 正例 / ❌ 反例（同一个滚动条，两种天差地别的写法）：

```kotlin
// ❌ 反例：在组合阶段读滚动状态——firstVisibleItemIndex 按"条"变，
//   每滚过一条边界，整个 LazyColumn 就重组一次（换成 scrollOffset 则按像素变，更凶）
val firstVisible = listState.firstVisibleItemIndex   // 组合里一读，就把"滚动"和"重组"绑死了
Text("当前第 $firstVisible 条")                       // 仅为显示个数字，拖累整个列表

// ✅ 正例：drawWithContent 里读——滚动只触发这一层的重画，零重组、零重排
Modifier.drawWithContent {
    drawContent()
    val p = state.scrollOffset / state.contentSize.toFloat()   // 绘制阶段读，只重画
    drawRoundRect(...)
}
```

**记忆锚点**：**变的越勤的值，读的越晚**——静止数据组合里读，动画数据绘制里读。

## 6.3 验证清单

1. Prop 页下拉 → 转圈（primaryContainer 配色）→ 松手加载数据 → 转圈停；
2. 转圈期间列表不清空（`produceState` 保留旧值，第 2 步已做）；
3. 设置页把滚动条切到"普通" → 回 Prop 页**不重新进入**（Fragment 还在后台）→ 滚动条立即出现；切回"无" → 立即消失；
4. 内容不满一屏时无滚动条；
5. 快速滚动大列表（Prop 页几百条）无卡顿（绘制阶段读取的效果，可用布局检查器的重组计数对比验证）。
