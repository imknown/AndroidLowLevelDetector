# 文档排版细则

> **状态**: **living**, 是 [AGENTS-cn.md](../../AGENTS-cn.md) 的文档规则一节的一部分.  
> 写或重做受这里收录的规则管辖的东西 (一份文档, 一条代码注释, 一笔提交信息, 或给负责人的一条聊天回复) 之前先读它,  
> 转换或重排已有的文本时也是.  
> 禁令由 AGENTS-cn.md 提出; 本文件收禁用词表, 改名对照表, CJK 到 ASCII 的映射, 间距例外, 豁免情形,  
> 以及语言与文件命名的机械部分.

## 用词要平实

规定不该写什么, 以及该改写成什么. 它管辖一份文档, 一条代码注释, 一笔提交信息, 也给负责人的一条聊天回复.  
它适用于你写作的任何一种语言: 下面的词表是本仓库写出过的写法和负责人点名的写法, 起作用的是判断标准, 词表不是规则的边界.

三类用词出局:

1. **填充词和缓和语**: 不带任何事实的说法. 删掉这个短语, 再看句子有没有少说一件事: `值得注意的是`,  
   `综上所述`, `不难看出`, `众所周知`, `毋庸置疑`, `至关重要`, `重中之重`, `让我们开始吧`,  
   `在当今快速发展的时代`. 英语: `It is worth noting that`, `In summary`, `As we can see`, `Obviously`,  
   `Needless to say`, `crucial`, `paramount`, `Let us begin`, `In today's fast-moving world`.
2. **营销式形容词**: 一句没人能核对的宣称. 要么说出事实, 要么删掉: `无缝` 该说成 "不需要人工步骤",  
   `强大` 该说这个功能做什么, `健壮` 该说它扛得住哪些失败. 同样出局: `极致`, `颠覆`, `革命性`, `全方位`,  
   `高水平`, `高质量`, `生态`, `赋能`, `抓手`, 以及英语的 `seamless`, `powerful`, `ultimate`, `disruptive`,  
   `revolutionary`, `comprehensive`, `world-class`, `cutting-edge`, `ecosystem`.
3. **拿跨领域的比喻当作一个工作项, 一次检查, 或一个决定的名字.**  
   起作用的是判断标准, 不是清单: 一个没打开过本仓库文档的人能不能读懂这句. 按证据分三组列:
   - 确实写进过本仓库自己的文档: `桶`, `闸门`, `台账`/`账本`, `收口`, `收尾`, `落地`, `尾巴`, `漂移`, `债`,  
     `接缝`, `护栏`, `兜底`, `兜住`, `裁定`, `定夺`, `拍板`, `点头`, `落点`, `门禁`, `地基`, `伸手点`, `保护网`,  
     `沉淀`, `复盘`, `闭环`, `对齐` (表"一致"时), `粒度`, 以及英语的 `bucket`, `gate`, `ledger`, `close-out`, `land`/`landing`,  
     `tail`, `drift`, `debt`, `seam`, `in-flight`, `tempo`.
   - 出现在负责人对 AI 回复的抱怨里, 在本仓库的文件中从没找到过: `顶牛`, `揪出`, `放宽`, `颗粒度`.
   - 同一类失败的英语近亲, 这里还没人写过就先禁掉: `guardrail`, `harness`, `circle back`, `touch base`.

代码本来就命名的那个东西, 它的名字留下: 布局里的 `Alignment`, Gradle 的构建产物,  
`gradle/toml/thirdParty.toml` 里 Metro 的 artifacts, `PropertyReader` 里那个 placeholder fallback.  
禁的是给代码已经有名字的东西再起一个编出来的第二名.

## 本仓库改过名的术语

living 文档一律用右列. 旧写法还留在归档的 record 里 (`docs/spec/archived/`, `docs/dev/issues-cn/archived/`),  
这些不该就地重写; 另外 living 文档引用某条 record 时, 用的是它归档时的文件名, 条目标题或小节标题.  
引用 record 就用它归档时的名字: 那名字里被禁的词要保留, 因为那是它的名字, 不是今天的写法.  
中列说的是含义, 不是必须照抄的替换词: 能用一句白话说清含义, 就写那一句.

| 已改掉的写法 | 现在生效的写法 | 说的是什么 |
|---|---|---|
| 闸门 (计划闸门, 提交闸门), gate | 确认点, approval point | AI 停下来提问, 负责人给答复的那一处 |
| 台账, 账本, 偏差台账, ledger, deviation ledger | 进度记录, 偏差记录, progress record | `progress.md`, 以及每跳过一步记的那一行 |
| 收敛护栏, convergence guard | review 循环何时停, when the review loop stops | 轮次不再带来新发现时就别再循环 |
| 收尾 (当作阶段名时), close-out | 任务结束, finishing the task | 清空待学习清单, 开那一次横向回顾总结 |
| 裁定, 定夺, adjudicate, rule (动词: 负责人裁的) | 判定哪边错, decide which side is wrong | 由负责人决定, 不由 AI 决定 |
| 点头, nod, say-so | 负责人的明确同意, the owner's approval | 负责人用话说同意 |
| 尾巴, tail | 没做完的部分, leftover part | 本单元里还没做完的工作 |
| 落地, land | 记录, 实现, 完成, 实施, record, implement | 写下来, 或者做出来 |
| 兜底 (当作文档术语), fallback | 失败时怎么做, what to do when it fails | 代码自己有名字时就用那个名字 |
| 漂移, drift | 过期, 不一致, out of date, inconsistent | 代码已经对不上的那句话 |
| 债, debt | 已有的问题, existing problem | 代码已经欠下的工作 |
| 接缝, seam | 天然的边界, natural boundary | 一份长笔记从哪里切开 |
| 落点 | 归到哪一条, 记在哪一条 | 一个决定或一处修改由哪一条, 哪一步承担 |
| 门禁 | CI 上必须通过的检查 | 会把合入拦下来的那个 CI 检查 |
| 地基, 保护网 | 基础, 防回归的测试与检查 | 主线开工前本来就得先有的东西 |
| 伸手点 | 全局取用点 | 没传参数却任何调用点都能取到的值 |
| 沉淀 (当动词用) | 写成文档, 汇总成文档 | 把知识写下来让它留得住 |
| in-flight, tempo | 进行中的, 还没做完的, 多久要一次同意 | 正在执行的步骤, 以及要同意的频率 |
| 对齐 (表"一致"时) | 一致 | 两处说法讲的是同一件事 |
| 粒度 | 精确到 | 一个取值或一次切分有多细 |

## 任何语言都用 ASCII 标点

中文 (或日文) 文档用英语标点符号, 绝不用 CJK 的: `,` `.` `;` `:` `!` `?` `(...)` `"..."`  
而不是 `，。；：！（）「」《》`.

一一对应的映射:

| CJK | ASCII |
|---|---|
| `，` `、` | `,` |
| `。` | `.` |
| `；` | `;` |
| `：` | `:` |
| `（）` | `()` |
| `「」` `『』` `《》` | `"` (嵌套时用 `'`) |
| `……` `…` | `...` |

不是标点的字形保持原样: `·` `→` `←`, 示意图里的制表线, 以及状态 emoji.  
破折号不做映射; 它们是被禁用的, 见下一节.

间距按英语来, 不管两侧是什么文字: 一个标记后面还有正文时它后面留一个空格 (`每个条目, 每次检测`),  
`,` `.;:!?)` 之前不留空格,  
`(` 和 `"` 内部也不留. 另有两种情形:

- 紧跟在标识符之后的 `(` 是一次调用, 所以那里不留空格 (`collectModels()`).
- 数字之间的 `:` 保持紧挨 (`16:9`, `12:30`).

这对每一份文档都成立, **frozen**, **record**, **scratch** 的也包括在内:  
那里的标点属于排版, 不是那几种状态要保住的实质.  
写新文本或重做一段时, 把这次编辑碰到的内容一并转换, 在两种语言之间翻译时也要检查标点.

标题的标点和间距决定目录所指向的那个 GitHub 锚点, 所以重排一个标题的间距时,  
要在同一次修改里改写所有解析到它的 `](#...)`.  
显式的 `<a id="...">` 锚点是稳定文本, 永不移动.

## 破折号

任何文档, 代码注释或聊天回复里都绝不把破折号当标点用: 不许有 em dash `—`, 不许有 CJK 破折号 `——`,  
不许有 ASCII 替代品 `--`, 也不许有注释开头或收尾的 `----` 装饰线.

每一处都按它承载的关系改写成等价的词:

| 关系 | 英语 | 中文 |
|---|---|---|
| 一个释义 | `, i.e. ` | `, 即 ` |
| 换个说法再说一遍 | `, that is, ` | `, 也就是 ` |
| 原因, 解释, 列举 | `:` | `:` |
| 两个独立分句 | `;` | `;` |
| 真正的旁白 | `(...)` | `(...)` |
| 平铺直叙地接下去 | `,` | `,` |

在 inline code 里点名这个符号 (本规则自己就这么做) 是这条禁令唯一的例外.

不当作标点的 `--` 承载结构, 保持原样:

- GitHub 锚点里的双连字符 (`../README.md#1--架构与分层`).
- markdown 表格分隔符 (`|---|`).
- XML 注释边界符 (`<!-- -->`).
- 命令行 flag (`--project=...`).
- 后置自减 (`i--`).
- `git ... -- ` 这个选项结束标记.

## 长行按语义硬换行

一行源码太长时, 在句子或分句的边界断行 (以逗号收尾的分句是合法的断点, 但一个很短的分句可以和后面的内容留在同一行;  
短的列举保持在一起). 要点是没有任何一行整体过长, 不是固定宽度.

下面这些绝不断行; 每一项都占一行源码:

- 标题, 链接目标, URL, 代码块, inline code.
- 表格行绝不拆成两行源码, 但一个过长的单元格可以在单元格内部用 `<br>` 换行 (裸换行会破坏表格).

段落, 列表项或引用块内部的每一个换出来的行都以两个尾随空格收尾 (或用 `<br>`), 这样断行在渲染后依然成立;  
该块的最后一行不带.  
这些空格是承重的: 绝不剥掉, 也绝不合并.

代码注释遵循同一条规则; 与代码共享同一行的注释保持一行, 而一次换行处理绝不可碰任何不是注释的东西.

换行属于排版, 所以对 **frozen**, **record**, **scratch** 文档同样成立.

## 语言与文件命名

文档默认用英语, 文件名默认也是英语. 非英语的文档, 整个目录都用这门语言写时把语言标识加在目录上,  
目录里的文件保持平名, `docs/dev/issues-cn/` 和 `docs/agents-cn/` 就是这样. 只有文档落在混语言目录或仓库根时,  
标识才加在文件上, `docs/dev/module-structure-cn.md`, `AGENTS-cn.md` 和 `README-cn.md` 就是这样.  
译本的根 `README` 仍然是根文件: GitHub 只渲染仓库根的 `README.md`, 它搬不进语言目录. 一个目录已经有了  
命名模式时, 照它来.

镜像集合是根目录的 `AGENTS.md` 和 `README.md` 加上 `docs/agents/` 下的每一份英文正本.  
仓库里今天存在的副本是中文那一份组: `AGENTS-cn.md`, `README-cn.md`, 以及装着平名文件的 `docs/agents-cn/`.  
集合里的文档会被镜像进仓库持有译本的每一种语言, 而同一份文档的各份镜像承载同样的陈述, 顺序也相同.  
集合之外没有镜像, 只有一种语言的文档也不是某一对的一半: `docs/dev/JOTTINGS.md` 只有英语,  
`docs/dev/module-structure-cn.md` 和 `docs/dev/issues-cn/` 是中文原创, 没有对应版本.  
集合外的文档不欠任何语言的任何镜像.

一份文档被镜像时, 它的英语文件是生效的那一份, 并保住不带后缀的规范文件名.  
译本带着它自己语言的标识, 不自称译本, 也不放指向自身另一种语言副本的链接: 标识已经说明了这层关系.

改一份镜像文档的任何那个文件, 在这份文档的其余文件都带上同一改动之前都不算改完, 所以整组要在一次修改里改到底:  
一条生效的规定在每种语言里读起来都一样. 两份副本说法不一致时, 以英语文件为准, 该被修的是译本.  
采用一门新语言就是给集合里的每个文件添一份副本: `docs/agents/` 里的文件的副本进那个带语言标识的目录,  
而根文件的副本仍是带文件标识的根文件; 从那时起它们全部加入这同一项同步义务.

链接跟随承载它们的那份文档的语言: 任何一份文档, 不论在不在镜像集合里, 在自己这门语言有副本时就指向那份副本,  
没有时指向英语文件; 英语文档指向英语文件. 这项义务同样管写在正文里的引用, 不只是链接: 中文文档引用时写  
`AGENTS-cn.md`, 只有自己这门语言没有对应版本时才点默认的英文文件. 只有一类句子照旧用英文名: 讲哪一侧生效的  
那句话, 指向的是生效的那一份.

归档材料不受这条义务管辖: record 保留它归档时的链接与引用, 所以一份中文归档仍然指向英文文件是正确的现状,  
不是要就地修复的不一致.

有理由时, 文档内部仍然可以使用任何语言.
