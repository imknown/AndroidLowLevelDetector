# 07-文档规则

> **状态**: **living**. 这套规则文件的入口在根 [AGENTS.md](../../AGENTS.md), 编号和阅读时机见那份索引.

这份文件是在这里写东西的规矩. 它是 **living** (活的): 它讲代码的每一句说的都是当下,  
哪一句过期了, 哪一句就是要就地改掉的 bug. 约定是另一回事: 约定规定代码*应该*怎么做,  
代码暂时没做到, 约定也不过期; 照着当前代码去改约定, 反而是改错了 (见 [01-判据](01-判据.md)).  
[docs/dev/JOTTINGS.md](../dev/JOTTINGS.md) 是 **scratch** (草稿): 没整理的材料, 不能拿来当规则.  
一份笔记可以把自己标成 **frozen** 或 **record**: 这份笔记保住写下时说过的事, 里面的更正和后来的发现一起留着.  
引用它是看历史, 别把今天的代码回填进去. 这个状态保住的是内容: 发现, 逻辑, 决定, 结论, ID, 日期.  
不改动这些东西才可以重写措辞, 而且动手之前要先问负责人. 公文腔, 翻译腔, 空话套话这类不说人话的问题也算措辞,  
record 里同样可以就地修, 同样先问. record 里的死链可以就地修: 链接只是找路的标记, 不是要保住的内容.  
默认没有东西是 frozen; 新写的一切都是 living, 除非它自己另有声明.  
一份新笔记要写清自己是哪一种: **living**, **frozen / record**, 或 **scratch**.  
有一种状态不看文件, 看位置. 一份笔记挪进任何 `archived/` 目录, 它就是 **record**:  
`docs/spec/archived/` 里的 spec 目录, `docs/dev/issues-cn/archived/` 里的 issue 条目, 以后仓库新长的归档都一样.  
挪进去这个动作就把状态声明了, 文件不用只为了写清状态而被编辑. 里面标题还写着 living 的算被作废.

- 这些规则管本仓库里的一切文字, 也管你为这个仓库产出的文字: 文档, 提交信息, 还有各种代码注释 (文档注释,  
  行尾注释, 块注释). 你发给负责人的聊天回复一样受管辖.
- 文档记录什么, 什么就有一个 ID. ID 跨文档共用, 所以按 ID 引用.
- 文档**就地**改: 一句陈述查出来是错的, 就重写它, 连下游靠它的每一处一起重写,  
  让这份文档单独读起来就是当下的真话. 别把顶掉的那句留在原地, 后面接一个括号或一段引用块当更正;  
  也别在改好的句子上标它是哪次检查改出来的. 事实写在句子里, 不写在 "谁在什么时候检查过它" 那句备注里.
- **不带敏感信息**: 任何文档都不许带敏感信息, memory 文档也算.  
  隐私数据, 密码, 密钥, 证书, 签名材料, 一律不许.
- 判谁错之前先问. 两份文档对不上, 或者一份文档和代码对不上而且证据判不了谁错时,  
  把两边摆出来让负责人定, 然后只重写被判定该改的那一句. 更正不许乱扩散:  
  另一句看着像同一个问题, 放进要问的清单, 别并进同一次编辑.
- 文档只写负责人说过的或代码显示的. 不能为了让某一行或某一句看着完整就加术语, 加检测条目, 加限定语.  
  词汇表的每一行只管这份文档自己用到的词. 一行的最后一处引用没了, 那是拿来问的,  
  不能因为这个词谁都认识就留着.
- **大白话**: 每个短语都要一遍读懂.  
  不许自造简称; 不许给会反复用到的东西起比喻性的外号 (比如把一批工作项叫成 "桶");  
  不许用文档里没介绍过的缩写. 沿用这套规则文件或本文档已经定义过的词;  
  真是新词, 就在它第一次出现的地方定义. 代码注释和给负责人的聊天回复也按这个标准来.  
  拆句的标准见 [08-文档排版](08-文档排版.md) 的 `一句一个意思` 一节.
- **禁止的句式**: 词都对, 句式照样可能是错的. 全表和每一种的改法在 [08-文档排版](08-文档排版.md) 的 `禁止的句式` 一节.
- **译本要像用那门语言原写的**: 别照搬原语言的句式和语序, 也别写成公文腔. 中文就该主语和动词先出,  
  把定语从句拆成单独一句, 主语要再写一遍就再写一遍, 别连着用 `它`/`该`/`其`,  
  说法按中文自己的习惯写 (`住在` 对应 lives in, `欠` 对应 owes, 这两个就是照搬出来的).  
  `由 ... 决定`, `予以记录`, `上述`, `此类` 这类空话不写. 仓库以后加别的语言的副本, 同样按那门语言的习惯写.  
  词要日常, 但 `必须` 和 `绝不` 的力度不许松.  
  句子规则和对照表见 [08-文档排版](08-文档排版.md) 的 `中文怎么写` 一节.
- **给负责人的聊天回复**: 写给一个没打开过这套规则的人看. 这条标准对你写作的任何一种语言都一样.  
  [08-文档排版](08-文档排版.md) 里的词表是两种来源:  
  本仓库写出过的写法, 和负责人点名的写法. 词表不是规则的边界.  
  只有在等负责人答复时, 才加一句话说下一步做什么.  
  只说会改变负责人决定的内容: 不复述问题, 不把规则原文背回给负责人, 结尾不加没人要的总结.  
  不叙述内部工作: 你在守哪条规则, 你打算查什么, 你自己的判断怎么推出来的.  
  本仓库要你交上去的报告有两种: 编辑前那份, 和 reviewer 的发现. 它们是负责人在等的实质内容, 不是内部叙述.  
  给出内容, 去掉那些一步步交代自己过程的文字.  
  指称一样东西时用代码符号, 文件路径或原文字符串, 这套规则自起的外号不算名字.  
  这套规则定义的术语确实是最清楚的说法时, 先用大白话说它, 再把术语放进括号, 而且只放第一次.  
  禁用词表在 [08-文档排版](08-文档排版.md) 的 `用词要平实` 一节,  
  改过名的术语清单在同文件的 `本仓库改过名的术语` 一节.  
  聊天回复的口吻 (自称, 人设, 语气词) 在根 `AGENTS.md`, 每次回复都适用.
- 正文里留的是实质和找路的标记: 句子划的范围和例外, 按 ID 的交叉引用, 代码符号.  
  **谁在什么时候决定了什么, 不进正文**: 带日期的决定去查 `git log`.  
  别给每句挂 "负责人决定, <日期>" 这样的标签. 一份带版本行的文档点名版本并指向 `git log`;  
  它不攒修订记录.
- 语言与文件命名: 文档和文件名的语言, 标识加在哪, 链接和引用指向哪里, 一对副本要同步什么,  
  仓库现状如何, 全部见 [08-文档排版](08-文档排版.md) 的语言与文件命名一节.
- **列表和句子**: 一句话只装一个意思; 长句拆开. 并列项什么时候排成列表, 有序列表怎么写,  
  见 [08-文档排版](08-文档排版.md) 的 `什么时候排成列表` 一节.  
  **frozen** 或 **record** 文档的措辞, 标点和换行照同样的规矩办.
- **重写不许改实质**: 重写已有的文本时, 代码块, 命令, 路径, 标识符, 版本, URL, 文件名,  
  还有从界面引来的原文, 一律逐字保留. 不加事实, 不减事实, 每条规定的力度和每条例外的范围都保持原样.  
  判断不出原来那句话有多强时, 问负责人, 别自己挑一种读法.  
  完整步骤在另一节里: [08-文档排版](08-文档排版.md) 的 `重写已有文本时不改实质` 一节.
- **任何语言都用 ASCII 标点**, **不把破折号当标点**, **长行按语义硬换行**:  
  这三条每一份文档, 每一条代码注释, 每一次聊天回复都要守, **frozen**, **record**, **scratch** 的也一样.  
  聊天里的 emoji 和颜文字不算标点, 不在这三条之内.  
  标点和换行是排版, 不是那几种状态要保住的东西.  
  写文档, 代码注释, 提交信息或给负责人的回复之前要读它, 转换或重排已有文本时也要读:  
  [08-文档排版](08-文档排版.md).  
  它是机械部分: 禁用词表, 禁止的句式, 中文句子规则, 标点映射, 换行和重写步骤都在里面.
- **不许长篇大论**: 一段只说一件事; 一段里有第二件事, 就拆成两段. 一条规定只在管它的那份文件里写一遍,  
  别处给指向它的链接. 这份文件留禁令, 长度的细则留一个指针:  
  [08-文档排版](08-文档排版.md) 的 `长度: 不许长篇大论` 一节.
- 笔记别写长; 一份长到过头时, 照它天然的边界拆开, 前面留一页当索引.

## 调查报告与分析报告

新设立的调查报告与分析报告放在 `docs/dev/` 目录下, 结构参考 `docs/dev/2026-10-30-agp-survey-cn/`.  
既有的分析材料 (例如 `../dev/2026-10-16-project-analysis-cn`) 保持原状, 不按本套结构重写.

### 外层目录

- 目录名叫 `docs/dev/<yyyy-MM-dd>-<topic>[-cn]/`.  
  日期写在外层, 只表示目录创建时间, 主题用简短英文, 中文内容结尾带 `-cn`.
- 外层目录带一份 `README.md`, 状态固定为 **living**.  
  标题写明主题与创建日期 (例如 `# AGP 调查 (创建于 2026-10-30)`),  
  收录关于这个主题的全部调查或分析.
- 外层 `README.md` 用一张表汇总每一次调查记录, 每增加一次调查就在表末尾加一行:  
  `| 调查者 | 模型 | effort | 调查日期 | 内容 |`.  
  调查者和模型两列填写显示名称 (例如 `WorkBuddy CN` 和 `DeepSeek-V4.1-Flash`),  
  调查日期写实际调查那一天, 内容列给出指向对应子目录 `README.md` 的链接.
- 后续日期由新的 agent 或模型继续调查同一主题时, 依然复用既有的外层目录并在表里追加,  
  不按日期另起新目录.

### 内层子目录

- 里面一次调查建一个子目录, 目录名按 `<agent-slug>-<model-slug>-<effort>` 组织,  
  全部用小写字母, 数字, 短横线和点 (例如 `workbuddy-cn-deepseek-v4.1-flash-high`).
- 换一个 agent, 换一个模型, 或者换一个 effort 档位再查一遍, 都另起一个子目录, 绝不覆盖上一份.
- 各个 agent 与模型之间独立调查:  
  绝不读取其他 agent 或模型的调查子目录的结构与文件内容来参考, 不管它在哪个外层目录, 防止先入为主.
- 每个子目录的 `README.md` 和每个分篇文件都在开头声明状态为 **frozen**.  
  写下的结论不改, 后来的更正留在原处.  
  子目录里的内容记下写下时查到的现状和结论, 附上出处的证据.  
  这些笔记不规定代码该怎么做; 要变成规矩, 另外写进对应的规则文件.
- 子目录 `README.md` 开头写清调查者, 模型, effort 与调查日期, 正文列出各分篇的索引和核心结论.
- 正文照它天然的边界拆成带两位数字编号的文件 (`01-...md`, `02-...md`),  
  每一篇单说一件事, 并且附上能够核对的文件行号证据或命令输出.
