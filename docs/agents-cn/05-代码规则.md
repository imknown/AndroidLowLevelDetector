# 05-代码规则

> **状态**: **living**. 这套规则文件的入口在根 [AGENTS.md](../../AGENTS.md), 编号和阅读时机见那份索引.

## 代码规则

下面这些只管新代码. 这些规则记的是已经定下来的决定, 所以别让已有的问题变得更糟:

- `ViewModel` 一律拼全. 标识符, 注释, 提交信息, 文档里都不许缩写成 `VM`. `VM` 已经是 *virtual machine* 的缩写,  
  而这个应用本来就有一项是关于虚拟机的 (进程/VM 架构, `getArchitecture`),  
  所以哪怕上下文一眼能看懂, 这个短写也有歧义.  
  `UseCase` 和 `DataSource` 同样拼全: 不写 `UC` / `DS`.
- 不用静态事件总线. `SharedFlow`/`StateFlow` 绝不放进 ViewModel 的伴生对象. 跨功能的数据走 repository.
- UI 层 (Compose / ViewModel) 绝不用 try 去接业务异常. Repository 和 DataSource 要么自己把失败处理掉,  
  要么返回 wrapper 类型; 名字不带 `OrThrow` 后缀的函数, 约定就是不抛.  
  异常能跑到 UI 层, 就是要从源头修的 bug, 不该让 UI 咽下去.
- 全局的 `myAndroid` 已删除. 设备版本事实只有一个来源:  
  `AndroidVersionDataSource.currentAndroidInfo` (`ui/home/datasource`, 进程内推导一次并记住, 读运行时 `Build.VERSION`).  
  `lld` 里 `known` 那一行的修正只作用于 Android 版本那一行的显示, 修正值不再落到任何全局.
- minSdk 从 `gradle/toml/build.toml` 来.  
  新一点的 API 要用 `Build.VERSION.SDK_INT >= Build.VERSION_CODES.X` 或 `@RequiresApi` 挡住.  
  SDK API 的版本判断只看运行时的 `Build.VERSION.SDK_INT`;  
  preview 和已知值推断 (`AndroidVersionDataSource`, `ui/home/datasource`) 只留给显示和检测逻辑.
- 新代码用钉住的版本允许的最新语法和 API. 绝不写比工具链允许的更老的写法. 要紧的是这三样:
  - 现在的 Kotlin 版本支持的最新 Kotlin 语法和 std-lib API
  - 现在的 compileSdk 给得出的最新平台 API
  - 现在的依赖版本给得出的最新 API
- 最新能用的语法或 API 自己还在 Beta 或 experimental 时, 不许自己决定采用: 摆出来问负责人怎么处理.  
  `build-logic` 里已经开的那组实验性编译器 flag 是定下来的; 这条管的是新加的那些.
- 会阻塞的活 (shell, 系统属性, 文件, 网络) 跑在 `Dispatchers.IO`, 不跑在 `Dispatchers.Default`.
- `ShellDefault` 现在没有调用方, 这是故意的. 它是留着备用的原生 shell 实现, 好处是不依赖 libsu;  
  在用的是 `ShellLibSu`. 别把它当死代码删掉. 将来真要启用它, 先修那个死锁: 它在 `waitFor()` 之后读管道会卡住.
- **默认英语**: 你生成的代码注释和提交信息一律用英语, 用户另有说明时除外. 文档用什么语言, 负责人定.  
  只有一条例外: 一条**新增**的代码注释在实施期间用负责人的聊天语言写, 这样负责人看没完工的东西时读的是自己的语言.  
  入库的代码库还是英语, 所以每条这样的注释在提交前都要翻成英语.  
  这笔翻译归当下这次改动的确认点做, 不是只有任务工作流的第 1 步才做: 一次没开 spec 目录的改动,  
  永远走不到那一步.  
  一条注释已经存在, 这次没重写它, 就保持那个文件的语言.  
  一个文件里的注释全是英语, 也不会让一条新增注释免掉这个例外.  
  文档不管用什么语言写, 标点都是 ASCII, 空格按英语来 (不用 `，。、：（）「」`): 见 [07-文档规则](07-文档规则.md).

## 本地化

- 字符串按功能包拆开. 支持的 locale 有:  
  默认 (英语), `zh-rCN`, `zh-rTW`, `fr-rFR` (`localeFilters` + `generateLocaleConfig`).  
  要加一门新语言时, 把它的 locale 加进 `localeFilters`.
- 新的面向用户字符串一律要有默认英语条目; 做得到的时候, 把三个翻译文件一起更新.
- 各语言自己的排版标点 (中文用全角冒号, 法语冒号前面要留空格, ...) 只管面向用户的本地化文案.  
  [07-文档规则](07-文档规则.md) 里那条 ASCII 标点规则照样管文档, 代码注释, 还有非文案的字符串资源 (存储 key, URI,  
  技术取值).
