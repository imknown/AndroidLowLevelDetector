# 03-非功能需求, 发布与路线图

> **状态**: **living**, [需求文档](README.md) 的一篇.

## 1. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-1 | 兼容性 | 应用能跑在 `gradle/toml/build.toml` 里 `minSdk` 那一档及以上 (今天是 Android 7.0), 与 AndroidX 的下限一致. 老旧或厂商改过的系统上, 特性检测要平稳降级, 显示未知, 绝不崩溃. |
| NFR-2 | 隐私 | 两个变体的检测都在手机上跑, 检测结果从不上传. 参考数据同步 (FR-7) 用不用网络, 用户定 (FR-8, 只管同步). 缓存下来的参考数据只放在应用的私有存储里. 遥测跟变体走 (FR-10): `firebase` 变体通过 Firebase 收集崩溃报告与使用数据, 默认开启, 目前没有运行时开关; `foss` 变体什么都不收集. |
| NFR-3 | 性能 | 检测异步跑; 结果界面很快出现, 检测工作从不阻塞主线程. |
| NFR-4 | 可靠性 | 状态能扛过界面重建, 系统杀掉进程后界面能恢复, 这些都按 FR-13 的懒加载与缓存规则来; 刷新既不卡死也不叠加 (FR-5); 失败只隔离在一个条目内 (FR-6). |
| NFR-5 | 可维护性 | 代码要让人和 AI 助手都好找: 状态只有一处权威 (SSOT), 单向数据流 (UDF), 代码按功能聚在一起, 一个功能的逻辑就在一处, 不会散落到相隔很远的目录里. |
| NFR-6 | 合法与安全 | 只用合法且只读的手段 (FR-9), 不用任何规避技巧 (NG6). |
| NFR-7 | 可读性 | 三态模型要让不懂行的用户, 也就是 Explorer 那类人, 也看得懂. 结论圆点 (仅 Home) 是三态的可视化呈现, 同一个指示: 绿色是最好的状态, 黄色是中间, 红色是最差的, 未知或探测不到通常也显示成红. 某个情形取哪个颜色, 看那个条目自己的语义定, 不强加跨条目统一映射. |
| NFR-8 | 自适应 | 界面用自适应布局: 手机, 平板, 折叠屏, 窗口缩放与多窗口都要能用. 这一条写的是目标; 今天做到哪一步记在下面的发布范围与路线图表里. |

## 3. 成功标准 (产品层面)

1. 刷机爱好者不用查任何外部资料, 就能对清单里每个条目回答 "我的设备支持 X 吗?".
1. 当前版本没有 "一直转圈加载" 和 "旋转后结果没了" 的报告.
1. 成功同步过一次之后, 飞行模式下应用完全可用.
1. 新来的贡献者, 人或 AI, 只看仓库的目录树, 几分钟内就能把某个检测功能的逻辑找齐在一处.
